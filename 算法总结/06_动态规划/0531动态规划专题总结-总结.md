# 动态规划专题总结（总纲回顾）

> 来源笔记：`0531动态规划专题总结.md`｜性质：DP 总纲（必读）｜分类：06 动态规划

## 一、什么是动态规划

一些递归**有重复计算**，可以用空间记录返回值来避免重复计算；动态规划是related的一整套原理和技巧的总和。

## 二、什么样的递归可以变成动态规划

- 设计的**可变参数类型简单**（不比 int 更复杂）的递归，可以改成动态规划；
- 如果递归过程中的**路径信息比较复杂（回溯）**，那么不能或没有必要改成动态规划；
- 虽然有路径信息，但**路径信息比较简单**时，也能改 → 这就是**状压 DP**。

## 三、三个经典名词

| 名词 | 含义 |
| --- | --- |
| **重叠子结构** | 除了数据量不同，剩下所有过程得到的逻辑大体相同 → **任何 DP 都一定来自某个递归** |
| **最优子问题** | **局部最优推导全局最优**：大问题的最优解一定来自若干子问题；子问题的最优解要么是决策出来的、要么是加工组合出来的 |
| **无后效性** | 之前做的决策对后续过程不产生影响 → **必须把参数带全** |

## 四、动态规划的大致过程（五步）

1. **想出设计优良的递归尝试**（一般用「**选或不选**」和「**枚举选哪个**」两种思路启发）；
2. **记忆化搜索**（从顶到底的 DP）；
3. **严格位置依赖的动态规划**（从底到顶的 DP）；
4. **进一步优化空间**（空间压缩）；
5. **进一步优化枚举行为**。

## 五、几条务实建议

- **推荐从尝试入手**，最符合自然智慧；
- 分析位置依赖时**多画图建立空间感**（这正是要写迭代版的重要原因）；
- 复杂度公式：`O(状态数量 × 每个状态的枚举代价)`；
- 尝试方法的优劣由**题目具体的数据量**决定：先确定靠谱的尝试，再做后续实现；
- DP 与其他专题、数据结构、算法技巧都有融合，**未完待续**。

## 八、把“尝试”写完整的检查表

一个合格的 DP 递归必须在纸面上回答六个问题：

1. **参数集是否完整**：同一组参数是否可能对应不同后续答案？
2. **边界是否唯一**：空串、空树、只剩一个元素分别返回什么？
3. **每个决策是否枚举完**：不选、选哪个、最后操作是谁，是否覆盖所有可能？
4. **重复调用是否真实存在**：若没有，递归或搜索更合适；
5. **依赖是否无环**：状态图是否可能绕回自己？
6. **答案从哪里取**：入口状态、某个必选结尾，还是一整行/整列的最值？

任何一项含糊，都不应急着写代码。

## 九、DP 选型决策树

```text
问题是否能在原问题上递推出子问题？
  否 -> 搜索/构造/数学
  是 -> 状态里需要记录什么可变参数？
       一维位置/剩余量      -> 线性 DP
       两个序列/二维网格    -> 二维 DP
       区间端点             -> 区间 DP
       树上子树             -> 树形 DP
       选过哪些样本          -> 状压 DP
       数位前缀约束          -> 数位 DP
       容量 + 物品选择       -> 背包 DP
之后：先写暴力递归，再加记忆化，最后按依赖压缩和优化。
```

## 十、不同 DP 的状态设计对比

| 类型 | 典型状态 | 核心技巧 | 常见错误 |
| --- | --- | --- | --- |
| 一维线性 | `dp[i]` | 从 `i-1/i-2` 转移 | 把不连续问题误当连续 |
| 二维 | `dp[i][j]` | 双串/网格 | 初始化边界漏掉 |
| 背包 | `dp[cap]` | 容量遍历方向 | 01 与完全背包混用 |
| 区间 | `dp[l][r]` | 按长度填表 | 划分点漏解 |
| 树形 | 子树返回结构体 | 后序合并 | 返回信息不足 |
| 状压 | `dp[mask]` | 集合位表示 | 遗漏关键状态 |
| 数位 | `dp[pos][state]` | 上界与前导零 | 缓存了路径特有状态 |
