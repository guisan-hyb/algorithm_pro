# 动态规划中根据数据量猜解法的技巧

> 来源笔记：`0530动态规划中根据数据量猜解法的技巧.cpp`｜核心程度：必背（DP 选型）｜分类：06 动态规划

## 一句话

DP 的可行性由 **`状态数量 × 每个状态的枚举代价 ≤ 10^7 ~ 10^8`** 决定；同一道题，**参数范围不同，应该选的 DP 维度就不同**——先估数据量，再决定"按哪个量做容量、按哪个量做答案"。

## 题目一：贿赂怪兽（牛客）——同一题的两种 DP

题意：初始能力 0，依次经过 n 只怪兽；能力 < 怪兽能力时必须花钱贿赂（钱数 `b[i]`），贿赂后能力 `+a[i]`；也可以选择不贿赂（能力保持不变）；求通过所有怪兽的最小花费。

**问题一：`a[i]` 很大但 `b[i]` 不大** → 按**钱**做容量：

`dp[i][j]` = 前 i 只怪兽、花费 ≤ j 时能获得的最大能力（`INT_MIN` 表示不可达）：

```
不贿赂：若 dp[i-1][j] >= a[i] -> dp[i][j] = dp[i-1][j]
贿赂  ：若 dp[i-1][j-b[i]] != INT_MIN -> dp[i][j] = dp[i-1][j-b[i]] + a[i]
```

最后从小到大找第一个可达的 j。

**问题二：`a[i]` 不大但 `b[i]` 很大** → 按**能力**做容量：

`dp[i][j]` = 通过前 i 只怪兽、能力**恰好**为 j 时的最小花费（`INT_MAX` 表示不可达）：

```
不贿赂：若 j >= a[i] 且 dp[i-1][j] 可达 -> dp[i][j] = dp[i-1][j]
贿赂  ：若 dp[i-1][j-a[i]] 可达 -> dp[i][j] = dp[i-1][j-a[i]] + b[i]
```

最后取最后一行最小值；还能空间压缩成一维（注意倒序）。

> **同一道题、两种解法**，正是"根据数据量猜解法"的教科书示例。

## 题目二：选 k 个数字使两集合和相差不超过 1（大厂笔试）

`n ≤ 10^6`：**01 背包完全不可行**（状态数和值域都太大）。

**正解：利用数据本身的特殊性直接构造**——从 1~n 中选 k 个数，和的范围是连续的 `[k(k+1)/2, k(k+1)/2 + k(n-k)]`，任意目标和都能构造出来：

- `need = 目标 - kSum`，`d = n - k`；
- 取前若干个"小数字" + 从后面取 `need / d` 个大数字，余数用中间一个数字补齐（`midIndex = k - rightSize + need % d`）。

复杂度 O(n) 甚至 O(k)。

## 题目三：两个排列的最长公共子序列（洛谷 P1439，n ≤ 10^5）

**经典 LCS 不可行**（O(n²)）。但两个序列都是**排列**，于是：

1. 记录 `where[x]` = x 在第一个排列中的下标；
2. 把第二个排列映射成 `arr[i] = where[b[i]]`；
3. **求 arr 的 LIS**（严格递增）即为答案——O(n log n)。

> 笔记点评："非常巧妙！"

## 题目四：使数组严格递增的最小操作数（LeetCode 1187）

`arr1[i]`、`arr2[i]` 的值域到 10^9，**不能用"值"做 DP 维度**：

- 法一（枚举选哪个）：`f(i)` = `arr1[i..]` 需要的最小替换数，且假设 `arr1[i-1]` 没被替换；在 `arr2` 上二分找"比 pre 大的最小数"，枚举第一个不替换的位置 j；
- 法二（选或不选）：`f(pre, i)`，因为 pre 可能很大 → 用 `map<pair<int,int>,int>` 或**把两个 int 压成一个 long long 当哈希键**（`((long long)pre << 32) | i`）。

## 适用特征（看到这些信号就选它）

- 同一道题给出多个数据范围版本（如"a 大 b 小"与"a 小 b 大"）；
- 想用 DP 但发现"某个参数的值域太大做不了状态" → 换另一个参数做状态；
- 数据是**排列 / 有特殊结构** → 往往有比通用 DP 更快的转化（转 LIS、构造）；
- 值域太大但状态少 → 用哈希表当 DP 表。

## 易错点

1. 先估 `状态数 × 枚举代价`，再动手写；
2. "用哪个量做容量"要和"另一个量的范围"匹配（本题一对解法就是镜像）；
3. `INT_MIN/INT_MAX` 当"不可达"时，转移前要判可达性，防溢出；
4. 空间压缩时要保证依赖方向正确（01 背包倒序）；
5. 特殊结构的题（排列、区间和连续）要敢用构造，而不是硬上背包；
6. 哈希表做 DP 时 key 的设计（两个 int 压缩成一个 long long）。

## 模板（可直接编译运行）

```cpp
// 数据量猜解法模板：同一题的两种 DP / 排列转 LIS / 值域太大用哈希表
#define _CRT_SECURE_NO_WARNINGS
#include <algorithm>
#include <climits>
#include <iostream>
#include <unordered_map>
#include <vector>
using namespace std;

// ================= 1. 贿赂怪兽：a 大 b 小 -> 按"钱"做容量 =================
// dp[j] = 花不超过 j 的钱能获得的最大能力（NEG 表示不可达）
int bribeByMoney(int n, const vector<int>& a, const vector<int>& b) {
    int sumB = 0;
    for (int i = 1; i <= n; i++) sumB += b[i];
    const int NEG = INT_MIN / 2;
    vector<int> dp(sumB + 1, NEG);
    dp[0] = 0;
    for (int i = 1; i <= n; i++) {
        vector<int> ndp = dp;
        for (int j = 0; j <= sumB; j++) {
            if (j >= b[i] && dp[j - b[i]] != NEG)
                ndp[j] = max(ndp[j], dp[j - b[i]] + a[i]);      // 贿赂
        }
        // "不贿赂"要求当前能力 >= a[i]，所以在能力维度上不可直接用一维滚动，
        // 这里给出明确的二维写法便于理解（实际按数据量可二选一）
        dp.swap(ndp);
        for (int j = 0; j <= sumB; j++) if (dp[j] < a[i] && dp[j] != NEG) dp[j] = NEG;
    }
    for (int j = 0; j <= sumB; j++) if (dp[j] != NEG) return j;
    return -1;
}

// ================= 2. 贿赂怪兽：a 小 b 大 -> 按"能力"做容量 =================
// dp[j] = 能力恰好为 j 时花的最少钱（INF 表示不可达）
long long bribeByAbility(int n, const vector<int>& a, const vector<int>& b) {
    int total = 0;
    for (int i = 1; i <= n; i++) total += a[i];
    const long long INF = LLONG_MAX / 4;
    vector<long long> dp(total + 1, INF);
    dp[0] = 0;
    for (int i = 1; i <= n; i++) {
        for (int j = total; j >= 0; j--) {
            long long cur = INF;
            if (j >= a[i] && dp[j] != INF) cur = dp[j];          // 不贿赂
            if (j >= a[i] && dp[j - a[i]] != INF)
                cur = min(cur, dp[j - a[i]] + b[i]);             // 贿赂
            dp[j] = cur;
        }
    }
    long long ans = INF;
    for (int j = 0; j <= total; j++) ans = min(ans, dp[j]);
    return ans == INF ? -1 : ans;
}

// ================= 3. 两个排列的 LCS -> LIS（n <= 1e5） =================
int lcsOfPermutations(const vector<int>& A, const vector<int>& B) {
    int n = (int)A.size();
    vector<int> where(n + 1, 0);
    for (int i = 0; i < n; i++) where[A[i]] = i;
    vector<int> ends(n);
    int len = 0;
    for (int i = 0; i < n; i++) {
        int x = where[B[i]];
        int l = 0, r = len - 1, pos = -1;
        while (l <= r) {
            int m = l + (r - l) / 2;
            if (ends[m] >= x) { pos = m; r = m - 1; }
            else l = m + 1;
        }
        if (pos == -1) ends[len++] = x;
        else ends[pos] = x;
    }
    return len;
}

// ================= 4. 值域太大：用哈希表当 DP 表 =================
// f(pre, i) 中 pre 可达 1e9，用 long long 把 (pre, i) 压成 key
unordered_map<long long,int> memo;
int makeArrayIncreasing(const vector<int>& arr1, vector<int> arr2, int i, int pre) {
    if (i == (int)arr1.size()) return 0;
    long long key = ((long long)pre << 32) | (unsigned)i;        // pre 为负时也能用（哈希键）
    auto it = memo.find(key);
    if (it != memo.end()) return it->second;
    const int INF = INT_MAX / 2;
    int ans = INF;
    if (arr1[i] > pre) ans = min(ans, makeArrayIncreasing(arr1, arr2, i + 1, arr1[i]));
    auto pos = upper_bound(arr2.begin(), arr2.end(), pre);
    if (pos != arr2.end()) ans = min(ans, 1 + makeArrayIncreasing(arr1, arr2, i + 1, *pos));
    return memo[key] = ans;
}

int main() {
    vector<int> a = {0, 8, 2, 5}, b = {0, 1, 4, 2};     // 1-based 使用
    std::cout << "按钱做容量 = " << bribeByMoney(3, a, b) << "\n";
    std::cout << "按能力做容量 = " << bribeByAbility(3, a, b) << "\n";

    vector<int> A = {3, 2, 1, 4, 5}, B = {1, 2, 3, 4, 5};
    std::cout << "排列的 LCS = " << lcsOfPermutations(A, B) << "\n";   // 3

    vector<int> arr1 = {1, 5, 3, 6, 7};
    vector<int> arr2 = {1, 3, 2, 4};
    sort(arr2.begin(), arr2.end());
    arr2.erase(unique(arr2.begin(), arr2.end()), arr2.end());
    memo.clear();
    std::cout << "最小替换次数 = " << makeArrayIncreasing(arr1, arr2, 0, INT_MIN / 2) << "\n";
    return 0;
}
```

## 如何根据数据量选状态

先写出候选递归参数，再计算每个参数的可能取值数。令 `S = 状态数`、`T = 单状态转移枚举数`，要求 `S×T` 落在评测机可承受范围内。经验预算：

| 规模 | 常见复杂度 |
| --- | --- |
| n≤10 | O(n!), O(2^n n²) |
| n≤20 | O(2^n n) |
| n≤100 | O(n³) |
| n≤500 | O(n²) |
| n≤5000 | O(n√n) 或较小常数 O(n²) |
| n≤10^5 | O(n log n), O(n√n) |
| n≤10^6 | O(n) |

表只是起点，必须乘上常数、内存和值域。例如 O(nW) 的工作量可能远大于 O(n²)，因为 W 不是输入长度。

## 手算演练：按钱与按能力

怪兽 `(能力, 花费)` 为 `(8,1),(2,4),(5,2)`：

- 按花费做状态：总花费 7，表仅 8 列；
- 按能力做状态：总能力 15，表 16 列；
- 若花费升到 `10^9`，按钱不可行；若能力升到 `10^9`，按能力不可行。

同一逻辑只是在交换“状态维度”和“答案维度”。这种镜像转换是遇到大值域时最值得先尝试的手段。

## 四种降维路线

1. **交换参数**：让值域较小的量进入 DP 状态；
2. **压缩坐标**：把值域映射成排名，只保留相对大小；
3. **哈希稀疏状态**：只保存真正可达的 `(capacity, value)`；
4. **利用结构**：排列转 LIS、区间和连续、正数用堆枚举。

## 反例：为什么 10^9 的值域不能硬开数组

若每个状态用 `int`，`10^9` 个状态至少需要 4 GB，且每次扫描都远超时限。即便把 `long long` 换成 `char`，复杂度仍与值域线性相关。应首先问：这个维度是否真的必须作为状态？能否换成另一个参数或只保存可达点？
