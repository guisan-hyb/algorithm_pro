# 从递归入手一维动态规划

> 来源笔记：`0225从递归入手一维动态规划.cpp`｜核心程度：必背（整个 DP 专题的总纲）｜分类：06 动态规划

## 一句话

**任何动态规划都一定对应一个"有重复调用行为"的递归**。所以正确的顺序是：先写尝试（递归），再记忆化，再改成严格位置依赖的迭代，最后做空间压缩和枚举优化——这条路线稳、通用，而且"尝试想错了"的返工代价最低。

## 解决什么问题

动态规划处理的题通常同时满足：

- 问题能拆成**规模更小的同类子问题**；
- 子问题会被**重复求解**（同一个参数组合被多次调用）；
- 当前决策只依赖子问题的结果，不依赖"到这里的路径怎么走"（无后效性）。

典型形态：求最小值 / 最大值 / 方案数 / 可行性。

## 核心心法（笔记原文）

- **DP = 用空间换重复计算**：算过的答案存下来，下次直接取。
- 「知道怎么算的算法」vs「知道怎么试的算法」——DP 真正练的是**怎么试**。
- **尝试策略就是转移方程**，两者是同一件事。推荐从尝试入手：代码好写、好验证，想错了重新想的代价也轻。
- **DP 表就是装递归返回值的容器**；表有几维，取决于递归函数有几个"关键可变参数"。
- 演进路线：

```
暴力递归
  -> 记忆化搜索（自顶向下的 DP）
  -> 严格位置依赖的迭代 DP（自底向上）
  -> 空间压缩
  -> 优化枚举（前缀和 / 滑动窗口 / 单调队列 / 查询结构）
```

- **什么时候没必要改 DP**：每次展开都是不同的解，或重复调用现象很少。此时递归本身就是最合适的写法。
- **记忆化是自顶向下**（从大问题往小问题走）；**迭代 DP 是自底向上**（按依赖顺序填表）。

## 为什么这样做（正确性从哪来）

一维 DP 成立靠三件事：

1. **重叠子问题**：同一个 `f(i)` 会被不同路径反复调用。暴力复杂度 = 递归树节点数；记忆化之后 = 不同状态数。
2. **最优子结构**：`f(i)` 的最优解能由 `f(i-1)`、`f(i-2)` 等子问题的最优解组合出来，转移方程就是组合规则。
3. **无后效性**：只要把"当前在下标几 / 还剩多少"这些参数带全，之前怎么走到这个状态不影响后续答案。参数带不全，就会出现"同一个状态对应不同答案"，DP 直接失效。

以斐波那契为例：暴力递归有 O(2^n) 个调用节点，但**不同的 `f(i)` 只有 n+1 个**；记忆化让每个只算一次，于是 O(n)；迭代按 `i = 2..n` 填表，天然保证依赖已算；滚动变量只留 `dp[i-1]`、`dp[i-2]`，空间 O(1)。

## 手算演练

### 演练 1：斐波那契的递归树

`f(0)=0, f(1)=1, f(n)=f(n-1)+f(n-2)`，求 `f(5)`：

```
f(5)
├── f(4)
│   ├── f(3)
│   │   ├── f(2) -> f(1)+f(0)
│   │   └── f(1)
│   └── f(2)          <- 与上面重复
└── f(3)              <- 与上面重复
    ├── f(2)          <- 重复
    └── f(1)
```

`f(3)` 被算了 2 次、`f(2)` 被算了 3 次，n 越大重复越夸张。这就是"重叠子问题"；记忆化后每个 `i` 只真正计算一次。

### 演练 2：解码方法 `s = "226"`

定义 `f(i)` = 从第 i 位开始有多少种解码方式，`f(3) = 1`（空串算一种）：

| i | s[i] | 单独解码 | 两位解码 | f(i) |
| --- | --- | --- | --- | --- |
| 2 | '6' | f(3)=1 | 越界 | 1 |
| 1 | '2' | f(2)=1 | "26" ≤ 26 → f(3)=1 | 2 |
| 0 | '2' | f(1)=2 | "22" ≤ 26 → f(2)=1 | 3 |

答案是 3：`2,2,6`、`22,6`、`2,26`。

注意表格是**从右往左**填的——因为 `f(i)` 依赖 `f(i+1)`、`f(i+2)`，迭代方向必须与依赖方向一致。

## 四道题

### 题一：斐波那契数（LeetCode 509）

暴力 O(2^n) → 记忆化 O(n) → 迭代 O(n) → **滚动变量 O(1) 空间**。

> 最优解是**矩阵快速幂 O(log n)**，见 `0625快速幂、矩阵快速幂与两类问题`。

### 题二：最低票价（LeetCode 983）

- `f(i)` = 从第 i 个出行日往后，最少花多少钱；
- 三种票（1 / 7 / 30 天）各算一次能覆盖到哪个下标 `j`，再取 `costs[k] + f(j)` 的最小值；
- 记忆化 → 迭代（`dp[n] = 0`，从后往前）。

这里的关键是"**用一张票覆盖掉一段出行日**"，而不是"每天买什么票"——状态定义决定了转移是否干净。

### 题三：解码方法（LeetCode 91）

- `f(i)`：从 i 开始有多少种解码；
- `s[i] == '0'` → 返回 0（0 不能单独解码）；
- 单个数字 → `f(i+1)`；两位数字 ≤ 26 → `+ f(i+2)`；
- 空间压缩：`last` 表示 `dp[i+1]`、`lastLast` 表示 `dp[i+2]`，从后往前滚。

### 题四：解码方法 II（LeetCode 639，带 `*`）

- 单个：`'*'` 时 ×9；
- 两位：`s[i]` 是数字且 `s[i+1]=='*'` 时，`s[i]=='1'` 加 9 种、`'2'` 加 6 种；
- `s[i]=='*'` 且 `s[i+1]` 是数字时，`≤6` 加 2 种、否则 1 种；
- 两个 `*` 加 **15** 种（11~19、21~26）；
- 全程对 `1e9+7` 取模。

## 适用特征（看到这些信号就选它）

- 递归展开时**反复求解同一个子问题**；
- 只有**一个可变参数**能决定返回值 → 一维 DP；
- 求"最少 / 最多 / 方案数"，且当前决策只依赖相邻的几个状态；
- 数据量提示：n 在 10^5 ~ 10^7，转移 O(1)。

## 复杂度

统一公式：**时间 = 状态数量 × 每个状态的枚举代价**，**空间 = 状态数量**（可压缩时更小）。

| 实现 | 时间 | 空间 | 说明 |
| --- | --- | --- | --- |
| 暴力递归 | 指数级 | O(n) 栈 | 递归树节点数 |
| 记忆化搜索 | O(状态数 × 转移代价) | O(状态数) | 自顶向下 |
| 迭代 DP | 同左 | O(状态数) | 自底向上 |
| 空间压缩 | 同左 | O(1) / O(k) | 只留依赖的几层 |

## 与相似算法对比

| 算法 | 核心 | 什么时候用 | 与 DP 的关系 |
| --- | --- | --- | --- |
| 分治 | 子问题**不重叠**，合并结果 | 归并排序、快排 | DP 是"子问题重叠"的分治 |
| 贪心 | 每步取局部最优，不回头 | 能证明局部最优 → 全局最优 | DP 更稳，贪心更快 |
| 搜索 / 回溯 | 枚举所有路径 | 状态无法压缩、需要具体方案 | 记忆化搜索 = 搜索 + DP 缓存 |
| 矩阵快速幂 | 固定线性递推 | 递推阶数固定、n 极大 | DP 的加速版 |

**选型原则**：能贪心就贪心（快）；不能贪心但子问题重叠就 DP；状态无法用简单参数描述就搜索。

## 易错点（含反例）

1. `dp` 初始化成 `-1` 表示"没算过"；若答案本身可能是 -1，要换哨兵（如 `INT_MIN`）。
2. base case 必须先想清楚。反例：解码方法 `f(n)` 应返回 1（空串算一种），写成 0 就全错。
3. 空间压缩时滚动变量的顺序不能反：

```cpp
int current = lastLast + last;
lastLast = last;      // 先更新 lastLast
last = current;       // 再更新 last
```

4. 迭代方向必须与依赖方向一致：依赖 `f(i+1)` 就从后往前，依赖 `f(i-1)` 就从前往后。
5. 取模题要**每一步**取模，只在最后取会溢出。
6. 用**长度**定义递归（`len` 从 0 开始）往往能省掉下标越界讨论。
7. 不要把"状态"与"决策"混在一起：状态是"现在在哪"，决策是"下一步选什么"。

## 模板（可直接编译运行）

```cpp
// 一维动态规划模板：递归 -> 记忆化 -> 迭代 -> 空间压缩
#define _CRT_SECURE_NO_WARNINGS
#include <algorithm>
#include <climits>
#include <iostream>
#include <string>
#include <vector>
using namespace std;

// ================= 1. 记忆化搜索骨架 =================
vector<int> memo;
int dfs(int i) {
    if (/* base case 1 */ false) return 0;
    if (memo[i] != -1) return memo[i];          // 算过就直接返回
    int ans = 0;
    // ans = min(ans, ... + dfs(...));
    return memo[i] = ans;
}
int solveMemo(int n) {
    memo.assign(n + 1, -1);
    return dfs(n);
}

// ================= 2. 记忆化搜索：最低票价（LeetCode 983） =================
class MinCostTickets {
    vector<int> duration{1, 7, 30};
    vector<int> days, costs;
    vector<int> dp;
    int f(int i) {
        if (i == (int)days.size()) return 0;
        if (dp[i] != -1) return dp[i];
        int ans = INT_MAX;
        for (int k = 0; k < 3; k++) {
            int j = i;
            while (j < (int)days.size() && days[i] + duration[k] - 1 >= days[j]) j++;
            ans = min(ans, costs[k] + f(j));
        }
        return dp[i] = ans;
    }
public:
    int mincostTickets(vector<int>& d, vector<int>& c) {
        days = d; costs = c;
        dp.assign(days.size(), -1);
        return f(0);
    }
};

// ================= 3. 迭代 + 空间压缩：解码方法（LeetCode 91） =================
int numDecodings(const string& s) {
    int n = (int)s.size();
    int last = 1;               // dp[n]
    int lastlast = 0;           // dp[n+1]
    for (int i = n - 1; i >= 0; i--) {
        int cur = 0;
        if (s[i] != '0') {
            cur = last;
            if (i + 1 < n && ((s[i] - '0') * 10 + (s[i + 1] - '0')) <= 26)
                cur += lastlast;
        }
        lastlast = last;
        last = cur;
    }
    return last;
}

// ================= 4. 解码方法 II（带 '*'，取模） =================
int numDecodingsII(const string& s) {
    const long long MOD = 1000000007;
    int n = (int)s.size();
    long long last = 1, lastlast = 0;            // dp[n] = 1, dp[n+1] = 0
    for (int i = n - 1; i >= 0; i--) {
        long long cur = 0;
        if (s[i] != '0') {
            cur = last * (s[i] == '*' ? 9 : 1);  // 一位
            if (i + 1 < n) {                     // 两位
                if (s[i] != '*') {
                    if (s[i + 1] != '*' && ((s[i] - '0') * 10 + (s[i + 1] - '0')) <= 26)
                        cur += lastlast;
                    else if (s[i + 1] == '*') {
                        if (s[i] == '1') cur += 9 * lastlast;
                        else if (s[i] == '2') cur += 6 * lastlast;
                    }
                } else {
                    if (s[i + 1] != '*') cur += ((s[i + 1] - '0') <= 6 ? 2 : 1) * lastlast;
                    else                 cur += 15 * lastlast;
                }
            }
            cur %= MOD;
        }
        lastlast = last;
        last = cur;
    }
    return (int)last;
}

int main() {
    std::cout << "斐波那契 f(10) = " << solveMemo(10) << "\n";            // 0 初始化后未用，示例占位
    vector<int> days = {1, 4, 6, 7, 8, 20}, costs = {2, 7, 15};
    MinCostTickets m;
    std::cout << "最低票价 = " << m.mincostTickets(days, costs) << "\n";   // 11
    std::cout << "解码方法(226) = " << numDecodings("226") << "\n";        // 3
    std::cout << "解码方法II(1*) = " << numDecodingsII("1*") << "\n";      // 18
    return 0;
}
```

## 进阶拓展

1. **状态压缩**：`dp[i]` 只依赖前 k 个状态时，用长度 k 的滚动数组，空间 O(k)。
2. **矩阵快速幂**：递推是固定线性关系时写成矩阵乘法，O(log n) 求第 n 项。
3. **记忆化 + 哈希表**：状态参数不是小整数（字符串、大坐标）时，用 `unordered_map` 当缓存。
4. **计数 DP 取模**：方案数题每步取模，乘法用 `long long` 中间量。
5. **输出方案**：开 `parent` 数组记录"从哪个状态转移来"，从终点反推；见 `0525动态规划中得到具体决策方案的技巧`。
6. **DP 优化枚举**：转移里有区间 `max/min/sum` 时，考虑前缀和、滑动窗口、单调队列；见 `0512`。

## 面试追问

1. **DP 和递归什么关系？** 任何 DP 都对应一个递归；DP 是对"子问题重叠"的递归做缓存或改写。
2. **记忆化和迭代哪个好？** 记忆化好写、只算用到的状态；迭代便于空间压缩和枚举优化，但要求能确定填表顺序。
3. **什么时候空间能压到 O(1)？** `dp[i]` 只依赖常数个前驱时。
4. **为什么取模要每步做？** 中间结果可能远超 `long long`，只在最后取模会溢出。
5. **怎么判断能不能 DP？** 看子问题是否重叠、是否有最优子结构、参数能否无后效地描述状态。
