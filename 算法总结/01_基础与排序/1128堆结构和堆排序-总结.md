# 堆结构 & 堆排序（heapInsert / heapify / 两种建堆）

> 来源笔记：`1128堆结构和堆排序.cpp`｜核心程度：必背（堆结构比堆排序有用得多）｜分类：01 基础与排序

## 一句话

堆 = 用数组前缀表示的完全二叉树；两个核心动作是"新元素往上浮（heapInsert）"和"变小的元素往下沉（heapify）"，各自 O(log n)。

## 解决什么问题

1. 维护动态极值：随时插入一个数、随时弹出最大值（大根堆）/ 最小值（小根堆）；
2. 堆排序；
3. 一切"动态第 K 大 / 动态中位数 / 合并 K 个有序序列"的地基（见 `1130堆结构常见题目`）。

## 核心思想

### 下标关系（完全二叉树 ↔ 数组）

对下标 `i`（0 开始）：

| 关系 | 公式 |
| --- | --- |
| 父结点 | `(i - 1) / 2` |
| 左孩子 | `2 * i + 1` |
| 右孩子 | `2 * i + 2` |

孩子下标 `>= size` 视为不存在（所以堆的有效范围由**单独的变量 size** 控制，而不是数组长度）。

### 两个基本动作

- **heapInsert（向上调整）**：`arr[i]` 是新来的，与父结点比较，比父大就交换并继续往上，直到不比父大或到达根。O(log n)。
- **heapify（向下调整）**：`arr[i]` 变小了（或被换成了小值），找出左右孩子中较大的那个，若比自己大就交换并继续往下，直到两个孩子都不比自己大或到达叶子。O(log n)。

### 建堆的两种方式（差别就在这一步）

| 方法 | 过程 | 建堆复杂度 |
| --- | --- | --- |
| 从顶到底（法一） | 依次 `heapInsert(arr, i)` | O(n log n)（log1+log2+...+log n） |
| 从底到顶（法二） | 从最后一个非叶结点往上 `heapify` | **O(n)** |

堆排序的第二步（依次弹出堆顶）过程相同：`swap(arr[0], arr[--size])` 把最大值换到未排序区末尾并断开，再对根 `heapify`，重复到 `size == 1`。整体仍是 O(n log n)。

## 为什么 heapify 建堆从最后一个非叶节点 `n/2 - 1` 开始

这是堆排序最容易“会背但不理解”的细节。

### 第一步：找出哪些下标是叶子

在从 0 开始的完全二叉树中：

```text
parent(i) = (i - 1) / 2
left(i)   = 2 * i + 1
right(i)  = 2 * i + 2
```

若节点 `i` 是叶子，它没有孩子，所以 `2*i+1 >= n`。解这个不等式：

```text
2*i + 1 >= n
i >= (n - 1) / 2
```

整数除法下，所有叶子下标恰好是：

```text
floor(n/2), floor(n/2)+1, ..., n-1
```

因此倒数第一个**非叶子节点**是 `floor(n/2) - 1`。代码里的 `n / 2 - 1` 不是经验值，而是完全二叉树编号关系直接推出来的。

### 第二步：叶子为什么不需要 heapify

`heapify(i)` 只做一件事：在当前节点和两个孩子之间选较大者，然后必要时下沉。叶子没有孩子，候选最大值就是自己，交换不会发生。因此对所有叶子调用 `heapify` 都是空操作，没必要遍历。

### 第三步：为什么要从后往前

非叶节点要依赖“两个子树已经是合法堆”。从 `n/2-1` 向 0 遍历时，当前节点的孩子下标一定更大，而所有更大的非叶节点已经处理过；叶子天然满足堆性质。因此处理当前节点时，两边前提已经成立，归纳法保证整棵树最终成为堆。

### 手算：`[9,6,4,6,5,2,3,1]`

`n=8`，最后一个非叶节点是 `8/2-1=3`。

| 处理下标 | 与孩子比较 | 结果数组 |
| --- | --- | --- |
| 3（值 6） | 孩子 1，已是局部堆 | `[9,6,4,6,5,2,3,1]` |
| 2（值 4） | 孩子 2、3，保持 | `[9,6,4,6,5,2,3,1]` |
| 1（值 6） | 孩子 6、5，保持 | `[9,6,4,6,5,2,3,1]` |
| 0（值 9） | 孩子 6、4，保持 | `[9,6,4,6,5,2,3,1]` |

再换一个交错数组 `[1,2,3,4,5,6,7]`：处理 2 时 7 上浮，处理 1 时 6 上浮，处理 0 时 7 最终到根，最终形成合法大根堆。

### 为什么它总共是 O(n)，不是 O(n log n)

设高度为 `h` 的节点最多有 `n / 2^(h+1)` 个；高度指该节点到最底层叶子的最长距离。一次 `heapify` 最多下沉 `h` 层，因此总工作量上界为：

```text
Σ(h * n / 2^(h+1)) = n/2 * Σ(h / 2^h)
```

而 `Σ(h / 2^h)` 收敛到常数 2，所以总代价是 O(n)。

直观理解：绝大多数节点在底部，只需下沉很少几层；只有接近根的极少数节点才可能下沉很深。不能把所有节点都按最坏 O(log n) 相加。

### 与从顶向下建堆的对比

依次 `heapInsert` 的建堆方式，每个新节点最坏都从叶子浮到根，总代价：

```text
Σh = O(n log n)
```

但堆排序弹出阶段的每次删除确实需要 O(log n)，共 n 次，因此**建堆 O(n) + 弹出 O(n log n) = 总 O(n log n)**。不要把“建堆线性”误认为“堆排序线性”。

## 适用特征（看到这些信号就选它）

- 数据**动态变化**（边插边问极值），且询问次数多；
- 要 O(1) 取极值 + O(log n) 增删；
- 题目要"第 K 大/小"但数据是**流式**的（不能随机选择那种离线打乱）；
- 需要一个 O(1) 额外空间的 O(n log n) 排序 → 堆排序（但真正比赛更常用 `priority_queue`）。

## 复杂度

| 操作 | 时间 |
| --- | --- |
| heapInsert | O(log n) |
| heapify | O(log n) |
| 从底到顶建堆 | O(n) |
| 堆排序整体 | O(n log n)，额外空间 **O(1)** |

## 易错点

1. **size 与数组长度必须分开**：堆排序里 `heapify` 的边界是 `size`，不是 `length`；
2. `heapInsert` 第一个元素（i=0）时 `(0-1)/2 == 0`，会自己和自己比，虽然不死循环但要注意语义，标准写法用 `while (arr[i] > arr[(i-1)/2])` 时到达根会自动停下；
3. `heapify` 里"较大孩子"要先判断右孩子存在（`r < size`）再比；
4. 笔记里 `heapSort2` 的循环初值写成了 `for (int i = i - 1; ...)`（应为 `length / 2 - 1`），实战要写成 `for (int i = n / 2 - 1; i >= 0; i--)`；
5. 小根堆只需把比较方向整体反转；
6. **记住结论：堆结构本身比堆排序更有价值**，和比较器结合后才是主战场。

## 模板（可直接编译运行）

`cpp
// 堆结构 + 堆排序模板（大根堆）
// heapInsert / heapify 均 O(log n)；从底到顶建堆 O(n)；堆排序 O(n log n)，额外空间 O(1)
#define _CRT_SECURE_NO_WARNINGS
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

// -------- 向上调整：i 位置新插入的值 --------
void heapInsert(vector<int>& heap, int currentIndex) {
    while (currentIndex > 0 &&
           heap[currentIndex] > heap[(currentIndex - 1) / 2]) {
        swap(heap[currentIndex], heap[(currentIndex - 1) / 2]);
        currentIndex = (currentIndex - 1) / 2;
    }
}

// -------- 向下调整：i 位置的值变小了，堆大小为 size --------
void heapify(vector<int>& heap, int currentIndex, int heapSize) {
    int leftChild = 2 * currentIndex + 1;
    while (leftChild < heapSize) {
        int rightChild = leftChild + 1;
        int largerChild = (rightChild < heapSize &&
                           heap[rightChild] > heap[leftChild])
                              ? rightChild
                              : leftChild;
        if (heap[largerChild] <= heap[currentIndex]) {
            break;
        }
        swap(heap[currentIndex], heap[largerChild]);
        currentIndex = largerChild;
        leftChild = 2 * currentIndex + 1;
    }
}

// -------- 堆排序 --------
void heapSort(vector<int>& heap) {
    int heapSize = static_cast<int>(heap.size());
    for (int index = heapSize / 2 - 1; index >= 0; index--) {
        heapify(heap, index, heapSize);
    }
    while (heapSize > 1) {
        swap(heap[0], heap[--heapSize]);
        heapify(heap, 0, heapSize);
    }
}

int main() {
    int length;
    if (!(cin >> length) || length <= 0) {
        return 0;
    }
    vector<int> heap(length);
    for (int& value : heap) {
        cin >> value;
    }
    heapSort(heap);
    for (int index = 0; index < length; index++) {
        cout << heap[index] << (index + 1 == length ? "\n" : " ");
    }
    return 0;
}
`

## 正确性归纳

1. 初始时，所有叶子各自都是合法堆；
2. 从 `n/2-1` 到 0 处理节点 `i` 时，它的两个孩子根据归纳假设已经是合法堆；
3. `heapify(i)` 解决 `i` 与孩子之间的唯一可能违规，并在交换后沿受影响路径继续修复；
4. 因此每个节点处理完后，以它为根的子树是合法堆；处理到 0 时整棵树是堆。

## 反例与边界

| 输入 | 预期 | 容易写错的地方 |
| --- | --- | --- |
| 空数组 | 不操作 | `n/2-1` 在 int 下为负数，循环仍可能处理，应先判空 |
| 单元素 | 已有序 | `heapify` 不应访问左孩子 |
| 全相等 | 保持任意顺序 | 用 `>` 时不会交换，仍满足堆性质 |
| 小根堆 | 方向全部反转 | 只改一个比较会破坏堆 |
| 有重复最大值 | 都合法 | 选左/右孩子中的任一较大者均可 |
