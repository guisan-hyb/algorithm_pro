# 根据数据量猜解法（天字第一号重要技巧）

> 来源笔记：`1221根据数据量猜解法的技巧-天字第一号重要技巧.cpp`｜核心程度：必背（做题第一步）｜分类：01 基础与排序

## 一句话

拿到题先看**数据范围**，用 "n × 复杂度" 去卡 `10^7 ~ 10^8`，就知道你的想法能不能过，也就知道该往哪个方向想。

## 解决什么问题

- 一题多解时，快速判断"哪个解法够用、哪些解法是白想"；
- 想不出最优解时，先写一个"数据量允许的次优解"拿部分分；
- 面试/笔试中和面试官确认范围，避免在错的复杂度上浪费时间。

## 核心思想

**基本事实**：C/C++ 1 秒能执行约 **10^7 ~ 10^8** 次常数操作（Java/Python/Go 等语言要按 1~2 秒的常数换算）。不管什么评测平台、什么 CPU，都是这个数量级。

使用前提（缺一不可）：

1. 题目**必须给了各入参的最大范围**（正式笔试、比赛一定给；面试要主动问）；
2. 你要能**准确估计自己算法的时间复杂度**。

## 数据规模与可接受复杂度对照表

| 数据规模 n | 可接受的最大时间复杂度 | 常见对应算法方向 | 备注 |
| --- | --- | --- | --- |
| n <= 10 ~ 20 | O(n!) / O(2^n) | 暴力搜索、全排列、回溯剪枝、状压 DP | 数据极小，怎么暴力怎么来 |
| n <= 50 ~ 100 | O(n^3) | 三重循环、Floyd 最短路、部分区间 DP | |
| n <= 500 ~ 1000 | O(n^2) | 双重循环、简单动态规划、稠密图算法 | |
| n <= 10^4 | O(n sqrt(n)) | 莫队算法、分块 | 10^4 x 100 约等于 10^6 |
| n <= 10^5 ~ 10^6 | O(n log n) | 排序、二分查找、线段树、树状数组、堆 | 最常见的笔试题范围 |
| n <= 10^7 | O(n) | 线性扫描、双指针、滑动窗口、前缀和、差分 | 需避免频繁创建大对象 |
| n >= 10^9 | O(log n) / O(1) | 二分答案、数学推导、快速幂 | 线性遍历必死 |

## 实战口诀

- **n 在十到百级**：想暴力、DFS、状压；
- **n 在千级**：想 O(n^2) 的 DP 或双重循环；
- **n 在十万级（最常见）**：想排序、二分、树状数组、单调栈/队列；
- **n 在百万到千万级**：只能想 O(n)：双指针、前缀和、一次遍历；
- **n 是十亿级**：放弃遍历，想二分答案或数学公式。

## 适用特征（看到这些信号就选它）

- 每道题的第一步都适用（这是它被叫作"天字第一号"的原因）；
- 一题有多档暴力/优化解，需要决定投入哪个方向；
- 需要给"部分分策略"定档：先写 O(n^2) 拿 60 分，再冲 O(n log n)。

## 易错点

1. **别只看 n**：有多个规模参数（n 个点、m 条边）时，总量是两者之和/乘积，例如图论 O(n + m) 必须把 m 也代进去估；
2. **常数因子也能坏事**：同为 O(n log n)，`std::sort` 能过 10^6，自己写的重量级线段树可能 10^5 就超时，估算时要在 10^7~10^8 基础上留余量；
3. `10^8` 是上限不是目标，卡在边界的解在慢评测机或多组数据上会挂；
4. 题目没给范围时必须主动确认（面试场景这是加分动作）。

## 模板（可直接编译运行）

```cpp
// 根据数据量猜解法：示例（n<=10 用全排列枚举）+ 复杂度速查
// 核心：n * 复杂度 <= 1e8 才算安全
#define _CRT_SECURE_NO_WARNINGS
#include <algorithm>
#include <climits>
#include <cmath>
#include <iostream>
#include <numeric>
#include <vector>
using namespace std;

// ---------- 示例：打怪（n 个技能各用一次，最少几次打完） ----------
// 数据范围 1 <= n <= 10  ->  直接全排列枚举 O(n!)
int n, m;
vector<int> hurt(12);
vector<int> blood(12);

int dfs(vector<int>& a, int idx, int rest, int used) {
    if (rest <= 0) return used;                  // 已打死
    if (idx == n) return INT_MAX;                // 技能用完还没死
    int ans = INT_MAX;
    for (int j = idx; j < n; j++) {
        swap(a[idx], a[j]);
        int dmg = (rest <= blood[a[idx]]) ? 2 * hurt[a[idx]] : hurt[a[idx]];
        ans = min(ans, dfs(a, idx + 1, rest - dmg, used + 1));
        swap(a[idx], a[j]);
    }
    return ans;
}

int main() {
    int T;
    if (!(std::cin >> T)) return 0;
    while (T--) {
        std::cin >> n >> m;
        for (int i = 0; i < n; i++) (std::cin >> hurt[i] >> blood[i]);
        vector<int> order(n);
        iota(order.begin(), order.end(), 0);
        int ans = dfs(order, 0, m, 0);
        std::cout << (ans == INT_MAX ? -1 : ans) << "\n";
    }
    return 0;
}

// ---------- 附：复杂度速查（写代码前先过一遍） ----------
// n<=20        -> O(n!) / O(2^n)    暴力 / 状压 / 全排列
// n<=100       -> O(n^3)            三重循环 / Floyd / 区间 DP
// n<=1000      -> O(n^2)            双重循环 / 简单 DP
// n<=1e4       -> O(n*sqrt(n))      莫队 / 分块
// n<=1e5~1e6   -> O(n log n)        排序 / 二分 / 树状数组 / 堆
// n<=1e7       -> O(n)              双指针 / 前缀和 / 差分
// n>=1e9       -> O(log n) / O(1)   二分答案 / 数学 / 快速幂
```

## 笔记里的题目

- **打怪**（NowCoder）：`1 <= n <= 10`（技能数），`m, x[i], y[i] <= 10^6`。因为 n <= 10，全排列 O(n!) 枚举技能顺序即可，不需要任何高级 DP；
- **超级回文数**（LeetCode 906）：`L, R < 10^18`。因为 10^18 开方只有 10^9，而回文种子只有 10^5 量级，于是枚举**回文种子再平方**，把问题降到 O(10^5)；笔记还给了第二种解法：把全部超级回文数提前打表成 60 个常量的 `record` 数组，查询退化成扫描。

## 专题深化：为什么成立

算法选型先看规模上界和多组数据总工作量，再看状态数乘转移代价。大 O 给增长趋势，实际还要乘常数、内存和输入组数。

## 专题深化：手算与边界

n=2000、20 组时 O(n²) 约 8000 万次，常数大就可能危险；n=10^5 时 O(n²) 是 10^10，通常直接排除。

### 对照与取舍

n≤10 可考虑 n!；n≤20 可考虑 2^n；n≤500 可考虑 n³；n≤5000 可考虑 n²；n≤10^5 优先 n log n；n≤10^6 优先线性。

### 易错点与反例

1. 多组测试的总复杂度要相加
2. 递归栈和内存可能先于时间成为瓶颈
3. 排序和哈希的常数与数据分布不同
4. 理论复杂度和最大样例实测必须结合

## 专题深化：进阶拓展

通过数据分档设计多个算法，例如小 n 用搜索、大 n 用构造或离线结构；这在高难度题中很常见。
