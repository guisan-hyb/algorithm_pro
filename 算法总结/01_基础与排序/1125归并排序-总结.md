# 归并排序（递归版 + 迭代版）

> 来源笔记：`1125归并排序.cpp`｜核心程度：必背（一切归并分治的母体）｜分类：01 基础与排序

## 一句话

左半排好、右半排好，再用 merge 过程把两半合成整体有序；它是**稳定排序**里唯一能做到 O(n log n) 的常用算法。

## 解决什么问题

1. 稳定地 O(n log n) 排序；
2. 提供 merge 过程这个"工具"——凡是"答案 = 左边 + 右边 + 跨左右"的题，都能挂到它上面（见 `1126归并分治`）；
3. 作为分治思想的第一个标准模板（`1124递归与master公式` 的直接应用）。

## 核心思想

- 分：`mid = (l + r) / 2`，递归排序 `[l, mid]` 与 `[mid+1, r]`；
- 治（merge）：两个指针分别从左、右段头部开始，**谁小拷贝谁**到辅助数组 `help`；
- 收尾：某一段耗尽后，把另一段剩下的整体拷进 `help`；
- 回写：把 `help[l..r]` 覆盖回 `arr[l..r]`；
- 复用的关键点：每次 merge 前左右两段各自**已经有序**，所以指针可以一路向右不回头。

递归式：`T(n) = 2T(n/2) + O(n)` → **O(n log n)**；额外空间 **O(n)**（辅助数组）。

## 适用特征（看到这些信号就选它）

- 要求稳定排序且数据量大（n ≥ 10^5）；
- 需要"左右各自有序之后，跨左右统计某些信息"，例如逆序对、翻转对、小和、右侧比它小的个数；
- 需要把"每个元素与左侧/右侧元素的比较"平摊到 log 层上（避免 O(n²) 枚举）。

## 复杂度

| 版本 | 时间 | 额外空间 | 稳定性 |
| --- | --- | --- | --- |
| 递归版 | O(n log n) | O(n) + O(log n) 栈 | 稳定 |
| 迭代版（步长翻倍） | O(n log n) | O(n) | 稳定 |

## 易错点

1. `help` 是**全局/共用**的，不要每次 merge 都新建数组（比赛里会慢）；但多组数据时要记得清空或至少覆盖用到的区间；
2. merge 里的 `<=` 决定了稳定性：`arr[a] <= arr[b]` 取左边，相等时先左后右，稳定；写成 `<` 就不稳定；
3. 迭代版的右边界：`r = min(l + 2 * step - 1, limit - 1)`，漏掉这个 `min` 会越界；
4. 迭代版里 `if (m + 1 > limit - 1) break;` 表示"没有右段了，这一轮不用 merge"，漏掉就崩；
5. 不要浪费时间去学"原地归并"：它能省到 O(1) 空间，但时间会退化到 O(n²)。

## 为什么这样做（两条不变量）

理解归并，只要抓住 merge 前后必须成立的两条不变量：

1. **merge 之前**：`[l, mid]` 与 `[mid+1, r]` 两段**各自已经有序**——这是递归的归纳假设；
2. **merge 过程中**：`help[l..i-1]` 恰好是"已经比较过的元素中最小的 i-l 个"，且保持有序——所以每次"谁小拷谁"都不会破坏有序性；
3. **回写之后**：`[l, r]` 整体有序，供上一层使用。

如果第 1 条不成立（比如忘了先递归左右），merge 只是把两段乱序数据拼在一起，整个算法就错了；如果第 2 条不成立（比如两个指针没有各自单调前进），就会漏元素或重复拷贝。

## 手算演练（顺带看清稳定性的来历）

**例 1：merge `[1,3,5]` 与 `[2,4,6]`**

| 步骤 | 左指针 p | 右指针 q | 比较 | 写入 help |
| --- | --- | --- | --- | --- |
| 1 | 1 | 2 | 1 vs 2 | 1 |
| 2 | 3 | 2 | 3 vs 2 | 2 |
| 3 | 3 | 4 | 3 vs 4 | 3 |
| 4 | 5 | 4 | 5 vs 4 | 4 |
| 5 | 5 | 6 | 5 vs 6 | 5 |
| 6 | 越界 | 6 | 左段耗尽 | 6 |

结果 `[1,2,3,4,5,6]`。注意第 6 步：左段耗尽后，右段剩余元素**整体拷入**，不需要再比较。

**例 2：稳定性从哪来**

设数组为 `[3, 1, 3', 2]`（`3'` 表示另一个值为 3 的元素）：

1. 递归到长度 2：`[3,1] → [1,3]`，`[3',2] → [2,3']`；
2. merge：1 vs 2 取 1；3 vs 2 取 2；此时比较 3 与 3'——因为写法是 `a[p] <= a[q]`，**相等时取左边**，所以先写 3、再写 3'；
3. 最终 `[1,2,3,3']`，两个 3 的原始相对顺序被保留。

若把 `<=` 改成 `<`，相等时会先取右段的 3'，得到 `[1,2,3',3]`——排序结果依然"有序"，但**稳定性被破坏**。

## 与相似算法对比

| 维度 | 归并排序 | 随机快排 | 堆排序 | 插入排序 |
| --- | --- | --- | --- | --- |
| 时间 | O(n log n) | 期望 O(n log n) | O(n log n) | O(n²) |
| 额外空间 | O(n) | O(log n) | O(1) | O(1) |
| 稳定性 | **稳定** | 不稳定 | 不稳定 | 稳定 |
| 典型场景 | 要稳定，或要在 merge 里挂统计 | 通用、追求常数 | 空间紧 | n 很小或近乎有序 |

另一个容易混淆的对象是**归并分治**：归并排序的 merge 只做"合并"；归并分治则在 merge 里额外统计"跨左右"的贡献（小和、翻转对），这是两个不同的目的、同一套骨架。

## 模板（可直接编译运行）

```cpp
// 归并排序模板：递归版 + 迭代版
// 时间 O(n log n)，额外空间 O(n)，稳定排序
#define _CRT_SECURE_NO_WARNINGS
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

vector<int> a, help;

// -------- merge：谁小拷贝谁，<= 保证稳定 --------
void merge(int l, int mid, int r) {
    int i = l, p = l, q = mid + 1;
    while (p <= mid && q <= r)
        help[i++] = (a[p] <= a[q]) ? a[p++] : a[q++];
    while (p <= mid) help[i++] = a[p++];
    while (q <= r)   help[i++] = a[q++];
    for (int k = l; k <= r; k++) a[k] = help[k];
}

// -------- 递归版 --------
void mergeSort(int l, int r) {
    if (l >= r) return;
    int mid = l + ((r - l) >> 1);
    mergeSort(l, mid);
    mergeSort(mid + 1, r);
    merge(l, mid, r);
}

// -------- 迭代版：步长 1,2,4,... 自底向上 --------
void mergeSortIterative(int n) {
    for (int step = 1; step < n; step <<= 1) {
        for (int l = 0; l < n; l += 2 * step) {
            int m = l + step - 1;
            if (m + 1 > n - 1) break;              // 只剩左段，无需 merge
            int r = min(l + 2 * step - 1, n - 1);
            merge(l, m, r);
        }
    }
}

int main() {
    int n;
    if (!(std::cin >> n) || n <= 0) return 0;
    a.resize(n);
    help.resize(n);
    for (int& x : a) (std::cin >> x);
    mergeSort(0, n - 1);
    // mergeSortIterative(n);   // 二选一
    for (int i = 0; i < n; i++) std::cout << a[i] << " \n"[i == n - 1];
    return 0;
}
```

## 延伸

- 为什么归并比三傻快：**比较行为没有被浪费**，每一层的比较结果都被保留到下一层使用；
- 归并分治的判别三步法：① 大范围答案 = 左 + 右 + 跨左右？② 加上"左右有序"能否让跨越部分好算（形成不回头滑窗）？③ 都成立 → 挂到归并上；
- 同类问题往往也能用线段树/树状数组解，复杂度同为最优。

## 边界与反例

| 输入 | 会发生什么 | 结论 |
| --- | --- | --- |
| 空数组 / 单元素 | 递归版 `l >= r` 直接返回；迭代版 `step < n` 不进入循环 | 安全 |
| 全部相等 | merge 时 `<=` 一直取左边，元素顺序不变 | 结果正确且稳定，仍是 O(n log n) |
| 完全逆序 | 每层比较次数最多，但仍是 O(n log n) | 不会退化到 O(n²) |
| 近乎有序 | 归并不会因此变快（每层照样要 merge） | 近乎有序时插入排序才是 O(n) |
| 链表 | 数组归并需要 O(n) 辅助数组 | 链表归并可以做到 O(1) 额外空间（见链表排序） |
| 要求 O(1) 空间 | 原地归并会让时间退化到 O(n²) | 不值得，改用堆排序 |

## 面试追问

1. **merge 为什么是 O(n)？** 两个指针各自只向右走一遍，比较与拷贝共 O(n)，回写再 O(n)。
2. **总复杂度为什么是 O(n log n)？** 每层 merge 的总代价是 O(n)，共 log n 层；也可直接用 master 公式 `T(n)=2T(n/2)+O(n)`。
3. **为什么归并稳定？** 相等时先取左段元素（`<=`），右段相等元素永远排在左边之后。
4. **空间能不能省？** 数组归并必须 O(n) 辅助空间；链表归并利用节点指针可以做到 O(1)。
5. **迭代版为什么 step 每次翻倍？** 自底向上把长度为 step 的相邻两段合并，step 从 1 翻倍到 ≥ n，正好覆盖所有层。
6. **为什么外部排序用归并？** 它可以把大文件分块读入、逐块排序后两两归并，天然适合"内存装不下"的场景。

## 专题深化：为什么成立

递归保证左右段有序，合并过程每次取两段当前最小者，因此输出有序；相等时优先左段保持稳定性。递归树每层 O(n)、深度 O(log n)。

## 专题深化：手算与边界

`[4,1,3,2]` 分成 `[4,1]` 与 `[3,2]`，得到 `[1,4]` 和 `[2,3]`；最终合并时依次取 1、2、3、4。

### 对照与取舍

归并稳定且最坏稳定，代价是 O(n) 临时空间；快速排序平均常数小但最坏可能退化；堆排序 O(1) 额外空间但不稳定。

### 易错点与反例

1. 临时数组只开一次可避免 O(n log n) 次分配
2. 相等时取左段可保持稳定
3. 区间左闭右闭时中点公式要覆盖中点
4. 空段和单元素必须直接返回

## 专题深化：进阶拓展

归并可求逆序对、小和、跨区最优，并扩展为 CDQ 分治。小数组改用插入排序可改善常数。
