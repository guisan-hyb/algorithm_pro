## 一、核心准则：常数操作量估算

竞赛/笔试中通常假设 1 秒能执行 **10^7 ~ 10^8 次常数操作**。

**抉择逻辑**：拿到题先看数据量 n，用 `n × 你设想算法的复杂度` 估一遍；落在 10^7 ~ 10^8 内就可做，超出就会 TLE，需要换更优解法。

## 二、数据规模与可用时间复杂度对照表

| 数据规模 n | 可接受的最大时间复杂度 | 常见对应算法方向 | 备注 |
| --- | --- | --- | --- |
| n <= 10 ~ 20 | O(n!) 或 O(2^n) | 暴力搜索、全排列、回溯剪枝、状压 DP | 数据极小，怎么暴力怎么来 |
| n <= 50 ~ 100 | O(n^3) | 三维循环、Floyd 最短路、部分区间 DP | |
| n <= 500 ~ 1000 | O(n^2) | 二维循环、简单动态规划、稠密图算法 | |
| n <= 10^4 | O(n sqrt(n)) | **莫队算法**、分块 | 10^4 x 100 约 10^6 |
| n <= 10^5 ~ 10^6 | O(n log n) | 排序、二分查找、线段树、树状数组、堆 | 最常见的笔试题数据量 |
| n <= 10^7 | O(n) | 线性扫描、双指针、滑动窗口、前缀和、差分 | 需避免频繁创建大对象 |
| n >= 10^9 | O(log n) 或 O(1) | 二分答案、数学推导、快速幂 | 线性遍历必死 |

## 三、注意事项

1. **O(n sqrt(n)) 与莫队**：n 约 10^4 ~ 10^5 时操作量在 10^6 ~ 10^7，刚好卡时限边缘；典型来源是莫队算法（通过调整询问顺序优化区间统计）或分块思想。
2. **表格作用有限，要结合常数**：同为 O(n log n)，内置排序能过 10^6，自己写的重量级线段树可能 10^5 就超时；估算时要在 10^7~10^8 上留余地。
3. **多参数复杂度**：有多个规模参数（n 个点、m 条边）时不能只看 n。图论 O(n + m) 要分别代 n、m；若 n = m = 10^5，总操作量约 2 x 10^5，非常安全。

## 四、实战抉择口诀

- n 在十百级 → 想暴力、DFS、状压；
- n 在千级 → 想 O(n^2) 的 DP 或双循环；
- n 在十万级（最常见）→ 想排序、二分、树状数组、单调栈/队列；
- n 在百万/千万级 → 只能想 O(n) 的双指针、前缀和、一次遍历；
- n 是十亿级 → 放弃遍历，想二分答案或数学公式。

## 专题深化：手算与边界

若 DP 有 500×500 状态、每个状态枚举 500 个划分点，总量是 1.25 亿；即使状态矩阵只有 25 万个元素，转移仍可能超时。

### 对照与取舍

| n | 常见预算 |
| --- | --- |
| ≤10 | n! |
| ≤20 | 2^n n |
| ≤500 | n² / 小常数 n³ |
| ≤10^5 | n log n |
| ≤10^6 | n |

### 易错点与反例

1. 容器扩容会带来额外复制
2. 递归深度和内存分配可能先失败
3. 哈希最坏情况可退化
4. 最大规模且多组样例才是最终证据
