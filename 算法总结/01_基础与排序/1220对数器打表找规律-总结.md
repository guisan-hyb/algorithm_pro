# 对数器打表找规律

> 来源笔记：`1220对数器打表找规律的技巧.cpp`｜核心程度：高频技巧（规律题的通用解法）｜分类：01 基础与排序

## 一句话

入参和返回值都是简单类型时，先用暴力递归求出小范围的**所有答案并打印**，从表里看出规律，再把规律写成 O(1) / O(log n) 代码。

## 解决什么问题

题目看起来是"博弈 / 数学 / 构造"，想不出正解，但：

- 输入是 1~2 个简单参数（一个整数 n，或两个整数）；
- 输出也是简单类型（个数、谁赢、真/假）；
- n 小的时候可以用暴力递归求出正确答案。

## 核心思想（三步）

1. **暴力求小范围答案**：用最朴素的递归/枚举，只要求入参不大时能算对（不需要任何优化）；
2. **打表**：把 `n = 0,1,2,...,50/100/200` 的答案全部打印出来；
3. **找规律**：观察表格里的周期/分段，把规律写成代码（这一步往往是 O(1) 的闭式）。

## 适用特征（看到这些信号就选它）

- `n` 给到 10^9，但答案有明显的分段或周期；
- 题目是博弈类（当前选手必胜/必败）、数学性质类（能否表示成某种形式）；
- 你写得出暴力递归，但写不出正解。

## 笔记里的四个例子（规律都值得记）

### 例 1：苹果袋子（6 个/袋、8 个/袋，必须装满）

- 暴力：`bag1_operate(rest)` 递归试 6 和 8，无解返回 `INT_MAX`；
- 规律（`bags2`）：奇数 → -1；`n < 18` 时 0→0 个、6 或 8→1 个、12/14/16→2 个、其余 -1；`n >= 18` → `(n - 18) / 8 + 3`。

### 例 2：吃草博弈（每次吃 4 的幂，吃完者赢，A 先手）

- 暴力：`win1_operate(rest, cur)`，枚举 `pick = 1,4,16,64...` 递归；
- 规律（`win2`）：**`n % 5 == 0 || n % 5 == 2` 则 B 赢，否则 A 赢**（周期 5）。

### 例 3：判断 num 是否为若干（>1）个连续正整数之和

- 暴力：枚举起点与终点累加；
- 规律（`is2`）：`num > 0 && num == (num & -num)`，等价于 **num 是 2 的幂**（即 `(num & (num - 1)) == 0`）。

### 例 4：好串计数（r/e/d 三种字符，恰好有 1 个长度 ≥2 的回文子串）

- 暴力：DFS 枚举所有长度为 n 的串并统计回文子串个数（n ≤ 10 时可跑）；
- 规律（`num2`）：n=1→0，n=2→3，n=3→18，n≥4 → `6 * (n + 1) % 1000000007`。

## 复杂度

- 暴力打表：O(答案规模 × 单次递归代价)，只在离线阶段跑；
- 规律解：一般 O(1) 或 O(log n)；
- 结论：**打表是一次性的探索工具，最终提交的是规律解**。

## 易错点

1. 表的范围要够大才看得出周期（例 2 的周期 5、例 1 的阈值 18，都是多打几行才发现的）；
2. 规律要**分段验证**：小 n 往往是特例（例 1 的 n<18、例 4 的 n≤3），直接套闭式会挂；
3. 暴力必须真暴力（DFS 全枚举），不小心用了"自己也觉得对"的优化会把错误带进规律；
4. 结果要取模时（例 4）注意中间过程用 long long；
5. 打表只证明"小范围成立"，大范围仍需对数器 + 数学论证。

## 模板（可直接编译运行）

```cpp
// 对数器打表找规律模板：暴力 -> 打表 -> 规律
// 适用于：入参/返回值都是简单类型、n 很大但有周期或分段的题
#define _CRT_SECURE_NO_WARNINGS
#include <iomanip>
#include <iostream>
using namespace std;

// ---------- 示例：吃草博弈（每次吃 4 的幂，吃完者赢，A 先手） ----------
// 第一步：暴力递归，只要求小范围正确
char brute(int rest, char cur) {
    char enemy = (cur == 'A') ? 'B' : 'A';
    if (rest < 5) {                        // 0 或 2 留给对手，当前选手必胜
        if (rest == 0 || rest == 2) return enemy;
        return cur;
    }
    for (long long pick = 1; pick <= rest; pick *= 4)
        if (brute(rest - (int)pick, enemy) == cur)
            return cur;                    // 存在一步让对手必败 -> 我必胜
    return enemy;
}

// 第二步：打表
void printTable(int up) {
    for (int n = 0; n <= up; n++)
        std::cout << std::setw(2) << n << " -> " << brute(n, 'A') << "\n";
}

// 第三步：把观察到的规律写成代码（周期 5：余 0 或 2 则 B 赢）
char byPattern(long long n) {
    return (n % 5 == 0 || n % 5 == 2) ? 'B' : 'A';
}

int main() {
    printTable(50);                        // 1) 看表找规律

    long long n;                           // 2) 锁定规律后用闭式提交
    if ((std::cin >> n))
        std::cout << byPattern(n) << "\n";
    return 0;
}
```

## 笔记里的题目

苹果袋子最少袋子数、吃草博弈胜负、连续正整数之和的判定、r/e/d 好串计数（结果对 10^9+7 取模，n ≤ 10^9）。

## 延伸

- 与 `1119对数器` 的分工：对数器验证"你的最优解"，打表找规律负责"从暴力结果里发现最优解"；
- 打表得到的规律，最终建议用对数器在更大范围内再验证一遍。

## 专题深化：为什么成立

先用可靠暴力得到小规模真值，再从差分、比值、周期或组合结构提出规律。有限表项可以被无穷多公式拟合，因此规律必须经过更大随机范围验证。

## 专题深化：手算与边界

前四项是 1,2,4,8 时可以猜倍增；若第五项变成 17，倍增假设立刻被推翻，说明需要继续打表并寻找分段或递推规律。

### 对照与取舍

| 规律 | 观察方法 |
| --- | --- |
| 多项式 | 一阶/二阶差分 |
| 指数 | 相邻比值 |
| 周期 | 对小模数取余 |
| 组合结构 | 与二项式/Fibonacci 对照 |

### 易错点与反例

1. 表项太少会产生错误拟合
2. 暴力本身错误会污染整个观察
3. 未证明的规律不能直接用于大数据
4. 忽略取模后的周期可能误判
