# 对数器（随机对拍验证正确性）

> 来源笔记：`1119对数器.cpp`｜核心程度：必建资产（计划里 W0 三件套之一）｜分类：01 基础与排序

## 一句话

用一个"慢但一定对"的暴力方法，去自动验证"快但可能错"的解法：随机生成海量小样本，两条路跑出不同结果就说明至少有一个错了。

## 解决什么问题

- 写完一个思路有点绕的解法（贪心、规律、优化 DP），不确定对不对；
- 找不到反例，靠手造样例效率低；
- 竞赛中"想出来了但怕挂"的最后一层保险。

## 核心思想（笔记原文六步）

1. 写出你想要测试的方法 **a**（通常是"有想象力的最优解"）；
2. 写出时间复杂度不好、但容易实现的正确方法 **b**（暴力）；
3. 实现一个**随机样本产生器**；
4. 把方法 a 和方法 b 跑**相同的随机样本**，比较结果是否一致；
5. 一旦出现不一致，**打印出这个样本**，人工干预，改对 a 或 b；
6. 当样本数量足够多、比对仍然一致，才可以认为 a 正确。

第 5 步是灵魂：对数器的价值不是"告诉你错了"，而是**给你一个数据量很小的、可复现的错误样本**，然后你可以用 print 大法、断点技术单步排查。

## 适用特征（看到这些信号就选它）

- 你写出的是一个"我认为它是对的"的算法（贪心正确性、规律题、优化过的 DP）；
- 暴力解法存在且好写（O(n!) 枚举、模拟、递归）；
- **输入参数与返回值都是简单类型**时，还能升级成"对数器打表找规律"（见 `1220对数器打表找规律的技巧`）。

## 复杂度 / 代价

- 门槛其实不低：需要在**两种不同思路**下实现功能相同的两个方法（暴力一个、最优一个）；
- 代价是写两份代码 + 一次随机跑批；收益是把"我觉得对"变成"大量样本下都对"。

## 易错点

1. 两个方法必须吃**同一份随机样本**（先复制一份给 a、一份给 b），否则比对无意义；
2. 随机样本的范围要先小后大：小范围先暴露错误，大范围容易掩盖（日志难读）；
3. 比较要输出**出错样本本身**（数组内容、参数值），只输出"不相等"帮不上忙；
4. 对数器只能证伪不能证明：跑通只能提高信心，不能数学上证明贪心正确；
5. 别把 a 和 b 写成同一种思路（那就变成自己验证自己）。

## 模板（可直接编译运行）

```cpp
// 对数器模板：随机样本 + 双解法比对
// 用法：把 solveA / solveB 换成你要验证的两个实现，先跑小数据量
#define _CRT_SECURE_NO_WARNINGS
#include <algorithm>
#include <chrono>
#include <iostream>
#include <random>
#include <vector>
using namespace std;

static mt19937 gen(chrono::steady_clock::now().time_since_epoch().count());

// ================= 待替换的三个部分 =================
// 方法 a：要验证的解法（贪心 / 规律 / 优化 DP ...）
long long solveA(vector<int> v) {
    sort(v.begin(), v.end());
    long long s = 0;
    for (int x : v) s += x;
    return s;
}

// 方法 b：暴力解，复杂度差但一定正确
long long solveB(vector<int> v) {
    long long s = 0;
    for (size_t i = 0; i < v.size(); i++)
        for (size_t j = 0; j <= i; j++)
            if (j == 0) s += v[i];          // 仅示范"思路不同"，实际请换成真暴力
    return s;
}

// 随机样本产生器
vector<int> randomSample(int maxN, int maxV) {
    uniform_int_distribution<int> dn(1, maxN), dv(0, maxV);
    int n = dn(gen);
    vector<int> v(n);
    for (int& x : v) x = dv(gen);
    return v;
}
// ===================================================

int main() {
    const int TEST = 100000;
    for (int t = 0; t < TEST; t++) {
        vector<int> a = randomSample(8, 20);      // 先小数据量：更容易暴露错误
        vector<int> b = a;                        // 两份相同样本
        long long ra = solveA(a), rb = solveB(b);
        if (ra != rb) {
            std::cout << "发现不一致！样本 n=" << (int)b.size() << "\n";
            for (int x : b) std::cout << x << " ";
            std::cout << "\na = " << ra << ", b = " << rb << "\n";
            return 0;                             // 打印错误样本，人工干预
        }
    }
    std::cout << "全部 " << TEST << " 组样本一致\n";
    return 0;
}
```

## 笔记里的题目

- 笔记只有方法论，没有具体题目；它是后面所有"贪心/规律/优化解"验证工作的公共基础设施。

## 延伸

- 打表找规律 = 对数器的参数被限制为"简单类型"时的专门用法：把暴力结果打印出来，人肉/程序观察规律，再写最优解；
- 计划中要求的"对拍三件套"（暴力程序、随机数据生成器、比较脚本）本质上是同一件事在 ACM 模式下的工程化。

## 专题深化：为什么成立

对数器用独立暴力模型和随机输入寻找反例。它不是数学证明，而是发现实现错误的高效工程手段；固定随机种子后，失败样本必须可复现，并继续加入空输入、单元素、极值、重复值和最大规模样本。

## 专题深化：手算与边界

排序样例 `[3,1,2]` 的正确答案是 `[1,2,3]`。故意把内层边界少写一位，某些长样本可能碰巧正确，而最小反例 `[2,1]` 会立即暴露。找到失败输入后应删去无关元素，再追踪循环不变式。

### 对照与取舍

| 方法 | 优点 | 局限 |
| --- | --- | --- |
| 固定样例 | 可复现、适合回归 | 覆盖有限 |
| 单元测试 | 语义清楚 | 依赖人工想边界 |
| 对数器 | 自动探索组合 | 依赖独立暴力模型 |
| 形式化证明 | 普适保证 | 成本高 |

### 易错点与反例

1. 两边共用同一个辅助函数时，公共错误不会被发现
2. 随机范围只含正数会漏掉负数分支
3. 只比较数值、不比较下标会漏掉方案错误
4. 每次重新随机播种会导致失败样本不可复现

## 专题深化：进阶拓展

把随机测试升级为性质测试：排序检查有序性和元素多重集不变；图算法检查最短路三角不等式；数据结构检查操作前后的代数不变量。
