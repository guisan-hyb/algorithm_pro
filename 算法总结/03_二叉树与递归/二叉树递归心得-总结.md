# 二叉树递归心得（心法）

> 来源笔记：`二叉树递归心得.md`｜性质：方法论（无独立 .cpp）｜分类：03 二叉树与递归

## 一句话

树的递归题逃不出三个维度：**信息流向（上下）**、**处理时机（前中后）**、**边界控制（空/叶）**。遇到题先想清这三件事，代码自然出来。

## 一、递归边界：用空节点，还是额外用叶子节点？

**默认：空节点作为边界**（`if (!node) return;`）。理由：统一处理所有叶子的左右空指针，避免访问 `node->left->val` 时崩。

**需要额外把叶子当边界的情况**（核心动机：避免**重复计算**或**逻辑重叠**）：

1. **路径问题**（根到叶路径和）：只判空的话，叶子会被左右两个空孩子各触发一次，路径被算两遍；应在叶子处拦截 `if (!node->left && !node->right) {...return;}`；
2. **找特定节点**（如"左叶子之和"）：判断"是不是左叶子"只能在其**父节点**完成；
3. **剪枝**：叶子有特殊属性时提前截断，能省掉一半的递归调用（不再走两个空节点）。

## 二、返回值：什么时候需要，什么时候不需要？

核心是**信息流动的方向**。

| | 不需要返回值（void） | 需要返回值 |
| --- | --- | --- |
| 方向 | 自顶向下 | 自底向上 |
| 手段 | 参数传父状态 + 全局变量/引用收集结果 | 子树把结果返回给父节点汇总 |
| 例子 | 打印/收集遍历序列、找路径（path 与 sum 作参数下传） | 最大深度、平衡判断、LCA、树形 DP |

**口诀：向下传参，向上返值。**

## 三、自顶向下 vs 自底向上

| | 自顶向下（前序思维） | 自底向上（后序思维） |
| --- | --- | --- |
| 逻辑 | 先处理当前节点，再递归左右 | 先递归左右，拿到结果再处理当前 |
| 适用 | 当前节点不依赖子树结果，只依赖父传下来的状态 | 当前节点**完全依赖**左右子树的结果（树形 DP） |
| 例子 | 前序遍历、根到叶路径、从根出发的搜索 | 后序遍历、直径、最大路径和、子树统计 |
| 优势 | 直观 | 每节点只访问一次，常把 O(n^2) 优化到 O(n) |

## 四、前序 / 中序 / 后序怎么选？

本质是选"当前节点与左右子树的处理先后"。

| 遍历 | 时机 | 代码位置 | 适用场景 |
| --- | --- | --- | --- |
| 前序 | 根 -> 左 -> 右 | 处理 -> f(left) -> f(right) | 进节点时做事：自顶向下传信息、构造/复制二叉树、搜索剪枝 |
| 中序 | 左 -> 根 -> 右 | f(left) -> 处理 -> f(right) | 处理**有大小关系**的数据：几乎只在 **BST**（中序有序，可验证 BST、找第 K 小、恢复 BST、累加树用"右根左"） |
| 后序 | 左 -> 右 -> 根 | f(left) -> f(right) -> 处理 | 离开节点时做事：自底向上汇总（树形 DP）、**修改/删除树结构**、算子树统计量 |

## 五、四条心法

1. **把大树拆成"单节点职责"**：不要在脑子里展开整棵递归树。只需问——宏观上这个函数要完成什么（假设左右子树已完美完成）？微观上当前节点要做什么、要从左右各要什么信息、怎么合并？
2. **回溯与树 DFS 的关系**：自顶向下收集路径时，递归完必须 `pop_back`。**前序位置做选择，后序位置撤销选择。**
3. **引入虚拟节点（Dummy）**：涉及根节点变更的题，加一个虚拟根指向 `root`，让所有节点平等地走"被父节点检查"的逻辑。
4. **树形 DP 通用模板**：
   - 定义状态：递归函数向上返回什么（通常结构体/数组，含多个维度）；
   - base case：`null` 返回什么基础状态；
   - 后序汇总：由左右返回的状态算当前状态，更新全局最优，再返回；
   - 例（最大路径和）：状态 = "以当前节点为端点向下延伸的最大单臂路径和"；汇总 = `max(0, left) + max(0, right) + val`；同时用 `left + right + val` 更新全局答案。

## 适用特征（看到这些信号就选它）

- 写完递归不确定对不对、不知道怎么设边界 -> 回到这三个维度检查；
- 题目要"子树信息" -> 自底向上（后序）；
- 题目要"从根出发的路径/状态" -> 自顶向下（前序）+ 回溯；
- 题目是 BST -> 优先想中序。

## 易错点

1. 路径题在空节点处收集 -> 结果重复；
2. 自顶向下忘了回溯 `pop_back` -> 路径污染；
3. 自底向上却用单个全局变量 -> 多个子问题互相覆盖；
4. 修改树结构（删除/剪枝）必须用后序，否则会丢失未处理的子树；
5. BST 题用普通二叉树的思路 -> 白丢 O(log n)。
