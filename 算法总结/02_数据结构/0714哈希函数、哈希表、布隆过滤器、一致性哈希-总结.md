# 哈希函数、哈希表、布隆过滤器、一致性哈希

> 来源笔记：`0714哈希函数、哈希表、布隆过滤器、一致性哈希.cpp`｜核心程度：工程/面试高频（含 MD5 手写实现）｜分类：02 数据结构

## 一句话

哈希函数的**核心作用是均匀性**——把样本均匀分组、均匀分散到多台机器；顺着这条线，就有了哈希表（内存里分组）、布隆过滤器（用位图做超省内存的存在性判断）、一致性哈希（分布式里减少迁移代价）。

## 一、哈希函数与它的"扩展作用"

- 工程上常用：MD5、SHA-1、SHA-256、SHA3 系列等（笔记列了一串）；
- **核心用途（笔记原话）**：利用哈希函数的均匀性，把样本进行**均匀分组**；
- 笔记里手写了一份完整的 **MD5 实现**（`class MD5`：`F/G/H/I` 四个轮函数 + 64 步常量 + padding + 大端转小端输出），并用它做了两个实验：
  1. 7 个只差一两个字符的字符串，哈希值完全不同（雪崩效应）；
  2. 生成长度 20、字符集 `{a,b}` 的全部 `2^20` 个字符串，统计哈希值取模 13 后的分布——**各余数几乎均匀**，这就是"均匀性"的直观证据。
- 关键词：`hexMod(hexStr, m)` 用 `result = (result * 16 + digit) % m` 逐位取模，避免大数溢出。

## 二、哈希表原理与扩容

- 增删改查**均摊复杂度 O(k)**，k 是样本平均长度；对 `int / long long` 这类定长类型就是 O(1)；
- 可定制的细节（笔记列的 5 项）：
  1. 初始桶空间（一开始准备多少桶）；
  2. 扩容阈值（链表多长时扩容）；
  3. 扩容因子（一次加多少桶）；
  4. 哈希函数的选择（简单 or 复杂）；
  5. 桶结构（链表 / 开放地址 / 红黑树）；
- **结论**：所有定制都只是优化常数，**时间复杂度无法再优化**。

## 三、布隆过滤器（位图 + 多个哈希函数）

**背景题**：100 亿个 url（每个 100 字节）进黑名单，能判断任意 url 在不在其中，预期失误率万分之一，内存不超过 30G。

**关键公式**（笔记给出，必须背）：

```
m = -(n * ln p) / (ln 2)^2        // 需要多少 bit（向上取整；字节数 = m / 8）
k = ln2 * (m / n)                 // 需要多少个哈希函数（向上取整）
p_true = (1 - e^(-n*k/m))^k       // 用取整后的 m、k 算真实失误率
```

要点：

- 布隆过滤器的空间**与样本大小无关**，只与样本数量 n 和失误率 p 有关；
- 只会**误报（false positive）**，不会漏报：说"不在"一定不在，说"在"可能不在；
- 不支持删除（删除会破坏其他元素的位）；
- 用途：黑名单、爬虫去重、数据定位。

## 四、一致性哈希（分布式存储）

笔记列出的四个要点：

1. **简单存储结构的弱点**：经典做法是 `hash(key) % 机器数`；一旦增删机器，**数据迁移代价是全量的**；
2. **哈希 key 的选择**：要选分布均匀、且业务上有意义的字段；
3. **哈希域变环 + 机器进环**：把哈希值空间首尾相接成一个环，机器（按 IP/名字哈希）落在环上，数据顺时针找到第一台机器；
4. **虚拟节点技术**：一台物理机在环上放多个虚拟节点，用来规避**数据倾斜**、实现负载均衡与负载管理。

## 五、大文件 top-k 的通用思路

**题目**（笔记里只要求讲原理）：内存只有 4G，硬盘上有 100 亿个字符串（每行 100 字节），统计出现次数最多的字符串。

**思路**：用哈希函数把大文件**均匀拆成多个小文件**：

1. 对每个字符串取哈希，`% k` 决定它去第几个小文件；
2. **同一个字符串一定落到同一个小文件**（这是哈希的确定性）；
3. 每个小文件单独读进内存，用哈希表统计词频，取各自的最大值；
4. 在所有小文件的最大值里再取最大。

**核心结论**：工程上处理大数据量，就是"哈希函数把样本均匀分散到多台机器/多个小文件"，同时保证同样的样本一定聚在一起。

## 适用特征（看到这些信号就选它）

- 面试问"海量数据去重 / top-k / 黑名单"，内存装不下；
- 问"哈希表怎么扩容、为什么均摊 O(1)"；
- 问"分布式缓存怎么分片、为什么用一致性哈希"；
- 需要"允许极低误报、但不允许漏报"的存在性判断 → 布隆过滤器。

## 复杂度 / 代价

| 结构 | 查询 | 空间 | 备注 |
| --- | --- | --- | --- |
| 哈希表 | 均摊 O(1) | O(n) | 最坏 O(n)（哈希被卡） |
| 布隆过滤器 | O(k) 次哈希 | m bit（与样本大小无关） | 有误报、无漏报、不可删 |
| 一致性哈希 | O(log 机器数) | O(机器数 + 虚拟节点数) | 增删机器只迁移一小段数据 |

## 易错点

1. 布隆过滤器的 `m` 是 **bit 数**，算内存时要 `/8`；`k` 必须是整数，取整后真实失误率要用第三个公式重算；
2. 布隆过滤器不能说"一定有"，只能说"**可能存在**"；不能删元素；
3. 一致性哈希里"数据倾斜"是**机器太少**导致的，靠虚拟节点解决；
4. 哈希表扩容时的均摊 O(1) 靠"每次扩容至少翻倍"，扩容因子太小会退化；
5. 手写 MD5 只是理解哈希的教具，工程里直接用库（`std::hash`、OpenSSL 等）。

## 模板（默写骨架）

```text
【布隆过滤器设计三步】
1. 已知：样本数量 n，期望失误率 p
     m = ceil( -(n * ln p) / (ln 2)^2 )      // 需要的 bit 数
     字节数 = m / 8
2. 哈希函数个数
     k = ceil( ln2 * m / n )
3. 真实失误率
     p_true = (1 - e^(-n*k/m))^k
操作：插入 -> 用 k 个哈希函数算出 k 个位置，全部置 1
      查询 -> k 个位置全是 1 则"可能存在"，否则"一定不存在"

【一致性哈希】
1. 把 hash 空间 [0, 2^32) 首尾相接成一个环
2. 每台机器按 IP/名字哈希，落在环上（一个物理机放多个虚拟节点）
3. 数据按 key 哈希落环，顺时针找到第一台机器即为归属
4. 增删机器只影响相邻一段数据 -> 迁移代价从 O(全部) 降到 O(1/机器数)

【海量数据 top-k】
1. 用哈希函数 % k 把大文件拆成 k 个小文件（同 key 必在同一文件）
2. 逐个读进内存，用哈希表统计
3. 各文件取局部最优，再全局取最优
```

## 专题深化：为什么成立

哈希用固定长度摘要把大对象映射到桶，平均 O(1) 的前提是哈希分布均匀且装载因子受控。布隆过滤器用多个位和多个哈希函数换空间，查询“不存在”一定正确，查询“存在”可能误判。一致性哈希把桶放在环上，节点增删只影响邻近键区间。

## 专题深化：手算与边界

16 个桶装入 12 个键，装载因子 0.75。若所有键落到同一桶，查询退化 O(n)。布隆过滤器插入 `x` 后把三个位设为 1；未插入的 `y` 若三个位都碰巧为 1，就会误判存在但不会漏判。

### 对照与取舍

| 结构 | 空间 | 查询 | 关键误差 |
| --- | --- | --- | --- |
| 哈希表 | O(n) | 平均 O(1) | 冲突最坏 O(n) |
| 布隆过滤器 | 位数组 | O(k) | 假阳性 |
| 一致性哈希 | O(节点数) | O(log n) 查找 | 虚拟节点分布 |

### 易错点与反例

1. 普通哈希不能保证顺序
2. 当前加载因子过高应扩容并重哈希
3. 布隆过滤器不支持删除，计数布隆才可近似删除
4. 一致性哈希不加虚拟节点时容易倾斜
