# 内存安全的前缀树（析构 / 智能指针）

> 来源笔记：`内存安全的前缀树.md`｜性质：工程改进（针对 `1222前缀树原理和代码详解` 的类实现）｜分类：02 数据结构

## 一句话

指针版前缀树最常见的两个坑是**内存泄漏**和**`erase` 没真正释放子树**；补上递归析构 + 正确的 `delete`，或直接用 `unique_ptr`，就能同时解决。

## 问题一：传统指针实现会内存泄漏

传统写法的 `TrieNode` 只有 `new` 没有 `delete`：

- 类的析构函数缺失 → 整棵树的内存永不释放；
- `erase` 里只写 `node->nexts[path] = nullptr;` → **把子树"孤立"了，节点本身没被释放，泄漏更严重**。

## 方案一：补全析构 + 修复 erase（传统 C++ 做法）

```cpp
struct TrieNode {
    int pass, end;
    vector<TrieNode*> nexts;
    TrieNode() : pass(0), end(0), nexts(26, nullptr) {}
    ~TrieNode() {                       // 递归析构：释放所有子节点
        for (TrieNode* child : nexts)
            if (child) delete child;    // delete 会继续触发子节点的析构
    }
};

class Trie1 {
    TrieNode* root;
public:
    Trie1() { root = new TrieNode(); }
    ~Trie1() { delete root; }           // 触发整棵树的递归析构

    void erase(string word) {
        if (countWordsEqualTo(word) > 0) {
            TrieNode* node = root;
            node->pass--;
            for (int i = 0; i < (int)word.length(); i++) {
                int path = word[i] - 'a';
                if (--node->nexts[path]->pass == 0) {
                    delete node->nexts[path];      // 关键：delete 而不是只置空
                    node->nexts[path] = nullptr;
                    return;
                }
                node = node->nexts[path];
            }
            node->end--;
        }
    }
};
```

## 方案二：智能指针（现代 C++ 推荐）

把 `vector<TrieNode*>` 换成 `vector<unique_ptr<TrieNode>>`，根节点也用 `unique_ptr`：

```cpp
#include <memory>

struct TrieNode {
    int pass, end;
    vector<unique_ptr<TrieNode>> nexts;
    TrieNode() : pass(0), end(0), nexts(26) {}
};

class Trie1 {
    unique_ptr<TrieNode> root;
public:
    Trie1() : root(new TrieNode()) {}
    // 不需要写析构函数：unique_ptr 自动递归释放

    void erase(string word) {
        if (countWordsEqualTo(word) > 0) {
            TrieNode* node = root.get();
            node->pass--;
            for (int i = 0; i < (int)word.length(); i++) {
                int path = word[i] - 'a';
                if (--node->nexts[path]->pass == 0) {
                    node->nexts[path].reset();    // reset 自动 delete 整棵子树
                    return;
                }
                node = node->nexts[path].get();
            }
            node->end--;
        }
    }
    // 其余 countWordsEqualTo / countWordsStartingWith / insert 同前，只需 .get()
};
```

## 三种写法的选择建议

| 写法 | 内存安全 | 适用场景 |
| --- | --- | --- |
| 裸指针 + 手写析构 | 需要小心 | 课程作业、需要讲清原理时 |
| `unique_ptr` | 自动 | 现代 C++ 工程代码，推荐 |
| 静态数组（见 `1222前缀树`） | 无需管理 | **笔试/竞赛主力**，速度最快最省心 |

## 易错点

1. `delete node->nexts[path]` 之前不要把指针改成别的，先 delete 再置空；
2. 递归析构在树极深时仍有栈溢出风险（一般不会遇到，因为深度=串长）；
3. `unique_ptr` 版本的 `nexts[path] == nullptr` 仍可正常比较（`unique_ptr` 支持与 `nullptr` 比较）；
4. 竞赛里别用类 + 指针版，直接上静态数组——又快又不会有内存问题。

## 专题深化：为什么成立

静态二维数组 Trie 用 0 表示空指针，但节点分配、清零和边界不透明，容易因总字符数估小越界。用 `vector<array<int,26>>` 和动态节点池能把容量与生命周期交给容器，并用节点计数避免越界。

## 专题深化：手算与边界

插入长度 L 的单词最多新增 L 个节点；总插入字符数 sumLen 决定上限。若数组只开 n 而不是 sumLen，会在长单词时越界。

### 对照与取舍

静态数组快但需精确容量；vector 安全但动态扩展开销；unordered_map 子节点适合大字符集但常数更高。

### 易错点与反例

1. 根节点不要放在 0 或要明确 0 表示空
2. clear 只重置已使用节点，不必每次清整个巨大数组
3. 析构和多次测试要释放或复用节点
4. 节点编号溢出要检查

## 专题深化：进阶拓展

内存池、智能指针、arena 分配器可在保持安全的同时减少小对象分配开销。
