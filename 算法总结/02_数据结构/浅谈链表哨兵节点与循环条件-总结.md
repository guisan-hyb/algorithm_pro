# 浅谈链表哨兵节点与循环条件

> 来源笔记：`浅谈链表哨兵节点与循环条件.md`｜性质：工程技巧总结（无独立 .cpp）｜分类：02 数据结构

## 一句话

**哨兵节点**消掉"头结点特判"，**循环条件的选择**消掉"空指针解引用"——这两件事能避开链表题里 90% 的空指针异常。

## 一、什么时候用哨兵节点（dummy）

**判断依据**：只要操作可能改变头节点，或需要统一对第一个节点的处理逻辑，就用 dummy。

三种典型场景：

1. **删除节点**（头节点可能被删）：LeetCode 203 移除链表元素。有 dummy 后头节点只是 `prev->next`，统一写 `prev->next = prev->next->next`；
2. **合并 / 重组链表**：LeetCode 21 合并有序链表、LeetCode 24 两两交换。需要"尾巴指针"不断拼接时，dummy 让**第一个节点也能用 `tail->next` 挂载**，逻辑完全统一；
3. **局部反转**：LeetCode 92 反转链表 II。`left = 1` 时反转区间的前驱不存在；有了 dummy，前驱至少是 dummy，新头永远是 `dummy->next`。

标准写法：

```cpp
ListNode* dummy = new ListNode(0);   // 值无所谓
dummy->next = head;
// ... 操作 ...
ListNode* result = dummy->next;      // 注意：不要 return head（head 可能已被删）
delete dummy;                        // 面试加分项
return result;
```

## 二、`while (cur != nullptr)` 还是 `while (cur->next != nullptr)`

**判断依据**：循环体里你要访问的是**当前节点**，还是**下一个节点**。

| 循环条件 | 使用场景 | 循环结束时 `cur` 的位置 |
| --- | --- | --- |
| `cur != nullptr` | 只处理当前节点：求和、计数、找特定值 | `nullptr`（**尾节点信息丢了**） |
| `cur->next != nullptr` | 要操作 `cur->next`：找尾节点、删除后继、两两交换 | 尾节点（正好停住） |

典型写法：

```cpp
// 只用当前节点
while (cur) { sum += cur->val; cur = cur->next; }

// 想停在尾节点
while (cur->next) cur = cur->next;              // 结束后 cur 是尾节点

// 删除后继
while (cur->next) {
    if (cur->next->val == target) cur->next = cur->next->next;
    else cur = cur->next;
}

// 两两交换：必须同时保护 next 和 next->next
while (cur->next && cur->next->next) { /* 安全访问两跳 */ }
```

## 三、终极总结与避坑

| 技巧 | 判断依据 | 常见错误 |
| --- | --- | --- |
| 用不用 dummy | 头节点会不会变？要不要统一首次插入/删除逻辑？ | 用了 dummy 却 `return head`（head 可能已被删） |
| `cur != nullptr` | 只关心当前节点本身 | 循环结束时 `cur` 是空，想取尾节点信息时空指针异常 |
| `cur->next != nullptr` | 要操作/访问 `cur->next`，或想让 `cur` 停在尾节点 | **调用前没判空**：链表为空时 `cur` 就是 `nullptr`，判断 `cur->next` 直接段错误 |

**C++ 最致命的坑**：写 `while (node->next != nullptr)` 的前提是 `node` 本身非空。链表可能为空时防御写法：

```cpp
// 错误：head 为空时 head->next 段错误
while (head->next) { ... }

// 正确
while (head && head->next) { ... }
```

这也是 dummy 好用的原因之一：**dummy 永远不是 `nullptr`**，所以 `while (dummy->next)` 永远安全。

## 专题深化：为什么成立

哨兵节点把“头节点特殊处理”统一成普通节点删除；循环条件应直接表达还剩多少可处理节点。`while(cur)` 适合遍历全表，`while(cur->next)` 适合需要查看下一个节点。

## 专题深化：手算与边界

删除头节点时，无哨兵要单独改 head；有哨兵只需让 `dummy.next` 指向后继。遍历删除满足条件的节点时必须先保存 next，否则删后无法继续。

### 对照与取舍

| 写法 | 优点 | 风险 |
| --- | --- | --- |
| cur | 简洁遍历 | 访问 cur->next 前需判空 |
| cur->next | 便于删除后继 | 空表必须先处理 |
| dummy | 统一头节点 | 返回 dummy.next |

### 易错点与反例

1. 空链表不能让哨兵指向未定义节点
2. 删除后 cur 不一定前进
3. 返回不能返回 dummy 本身
4. 环形链表没有自然终止，需要计数或快慢指针

## 专题深化：进阶拓展

双向链表哨兵形成环可消除头尾特殊分支；区间反转也可用虚拟头统一边界。
