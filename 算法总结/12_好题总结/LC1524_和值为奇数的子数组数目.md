# LC1524 和值为奇数的子数组数目

> **好题总结条目**｜标签：前缀奇偶性 / 计数 / 记忆化搜索 / 子数组
> **难度**：中等 ｜ **核心结论**：子数组和为奇数，当且仅当两个前缀和的奇偶性不同

---

## 一、一句话解法与适用特征

### 1.1 一句话概括

扫描数组并维护前缀和的奇偶性：

- 当前前缀是奇数时，它与之前每一个偶数前缀组成一个和为奇数的子数组；
- 当前前缀是偶数时，它与之前每一个奇数前缀组成一个和为奇数的子数组。

因此只需要记录“此前出现过多少个奇数前缀、多少个偶数前缀”。

### 1.2 看到什么信号，应该想到前缀奇偶性

| 题目信号 | 可联想到的模型 |
|---|---|
| 只关心子数组和的奇偶性 | 前缀和压缩为 `0/1` |
| 求满足某种关系的子数组数量 | 枚举右端点，统计符合条件的左端点 |
| `(sum[l..r]) % 2 == 1` | `prefixParity[r] != prefixParity[l]` |
| 元素正负均可 | 奇偶性仍然成立，不必依赖前缀和单调 |
| 答案很大，需要取模 | 每个右端点贡献中对已有计数取模 |

本质与 LC560「和为 K 的子数组」相同：

> **枚举右端点，查询此前满足条件的前缀有多少个。**

区别是本题的目标值只有两种状态，所以一个奇偶计数器就够了，不需要哈希表。

## 二、题目与关键转化

### 2.1 题目

给定整数数组 `arr`，返回和为奇数的非空连续子数组数目。由于答案可能很大，结果对 `10^9 + 7` 取余。

### 2.2 示例

```
输入：arr = [1, 3, 5]
输出：4
```

和为奇数的子数组有：

```
[1]、[3]、[5]、[1, 3, 5]
```

单独一个奇数元素的和是奇数；三个奇数相加仍然是奇数。

另一个 LeetCode 示例：

```
输入：arr = [1, 2, 3, 4, 5, 6, 7]
输出：16
```

### 2.3 从“区间和”转为“两个前缀”的关系

定义普通前缀和：

```text
pref[0] = 0
pref[i + 1] = arr[0] + arr[1] + ... + arr[i]
```

那么：

```text
sum(arr[l..r]) = pref[r + 1] - pref[l]
```

在奇偶意义下，加法和减法等价，因为：

```text
(a - b) mod 2 = (a + b) mod 2
```

所以：

```text
sum(arr[l..r]) 是奇数
⇔ pref[r + 1] 与 pref[l] 的奇偶性不同
```

这是整道题的第一块基石。我们完全不需要保存完整前缀和，只需要保存它的最低二进制位。

### 2.4 前缀奇偶性的递推

设 `arr[i] & 1` 表示当前元素的奇偶性，则：

```text
prefixParity[i + 1]
= prefixParity[i] xor (arr[i] & 1)
```

这比直接写 `sum += arr[i]` 更安全：

- `sum & 1` 和 `sumParity ^= arr[i] & 1` 在正常情况下等价；
- 异或写法不依赖整数总和本身，天然避免潜在的总和溢出；
- 题目只关心奇偶性，不应保留无关的高位信息。

初始空前缀的奇偶性为：

```text
prefixParity[0] = 0
```

它必须计入“此前偶数前缀数量”：

```text
cntEven = 1
cntOdd  = 0
```

这一步是典型的 off-by-one 来源。

## 三、法一：前缀和 + 分别统计奇偶

### 3.1 算法流程

初始化：

```text
parity = 0
cntEven = 1
cntOdd = 0
answer = 0
```

从左到右扫描 `arr[i]`：

1. `parity ^= arr[i] & 1`，得到当前前缀的奇偶性；
2. 如果 `parity == 1`：
   - 当前前缀与之前每个偶数前缀都能组成奇数和；
   - `answer += cntEven`；
   - 当前奇数前缀数量加一。
3. 如果 `parity == 0`：
   - 当前前缀与之前每个奇数前缀都能组成奇数和；
   - `answer += cntOdd`；
   - 当前偶数前缀数量加一。

### 3.2 C++ 实现

```cpp
class Solution {
public:
    int numOfSubarrays(vector<int>& arr) {
        static constexpr int MOD = 1'000'000'007;

        int oddPrefixCount = 0;
        int evenPrefixCount = 1;  // 空前缀的奇偶性为偶数
        int answer = 0;
        int prefixParity = 0;

        for (int value : arr) {
            prefixParity ^= value & 1;

            if (prefixParity == 1) {
                answer = (answer + evenPrefixCount) % MOD;
                ++oddPrefixCount;
            } else {
                answer = (answer + oddPrefixCount) % MOD;
                ++evenPrefixCount;
            }
        }

        return answer;
    }
};
```

### 3.3 为什么当前“奇”要配之前的“偶”

假设当前前缀的奇偶性是 `1`。要让区间和是奇数：

```text
currentParity xor previousParity = 1
```

如果 `currentParity == 1`，根据异或性质，`previousParity` 必须为 `0`。

例如：

```text
arr = [1, 3]
```

前缀序列为：

```text
pref[0] = 0
pref[1] = 1
pref[2] = 4

对应的奇偶序列：
0, 1, 0
```

扫描到 `pref[1]` 时，当前是奇数，之前的偶数前缀只有 `pref[0]`，因此新增一个奇数和子数组 `[1]`。

扫描到 `pref[2]` 时，当前是偶数，之前的奇数前缀只有 `pref[1]`，因此新增一个奇数和子数组 `[3]`。

答案一共是 `2`。

### 3.4 用示例完整手算

输入：

```text
arr = [1, 2, 3, 4, 5, 6, 7]
```

| 当前元素 | 当前前缀奇偶 | 加入前 `(偶, 奇)` | 当前贡献 | 累计答案 | 加入后 `(偶, 奇)` |
|---:|---:|---:|---:|---:|---:|
| 1 | 奇 | (1, 0) | +1 | 1 | (1, 1) |
| 2 | 奇 | (1, 1) | +1 | 2 | (1, 2) |
| 3 | 偶 | (1, 2) | +2 | 4 | (2, 2) |
| 4 | 偶 | (2, 2) | +2 | 6 | (3, 2) |
| 5 | 奇 | (3, 2) | +3 | 9 | (3, 3) |
| 6 | 奇 | (3, 3) | +3 | 12 | (3, 4) |
| 7 | 偶 | (3, 4) | +4 | 16 | (4, 4) |

最终答案是 `16`。

### 3.5 正确性证明

**引理 1：区间和奇偶性的转化成立。**

对任意 `l <= r`：

```text
sum(l..r) = pref[r + 1] - pref[l]
```

模 `2` 下减法与加法相同，所以：

```text
sum(l..r) 是奇数
⇔ pref[r + 1] mod 2 != pref[l] mod 2
```

**引理 2：扫描到位置 `i` 时，加入的贡献没有遗漏和重复。**

当前前缀是 `pref[i + 1]`。所有以 `i` 结尾的子数组，与所有满足 `l <= i` 的 `pref[l]` 一一对应。

根据引理 1：

- 当前前缀为奇数，只有此前偶数前缀能形成奇数区间；
- 当前前缀为偶数，只有此前奇数前缀能形成奇数区间。

当前奇偶计数恰好记录了这些前缀的数量，因此本步加入的就是“所有以 `i` 结尾、和为奇数”的子数组数量。

**定理：算法返回全部答案。**

每个非空子数组都有唯一的右端点。算法对每个右端点分别统计，并且每个子数组恰好被统计一次，所以最终累计值就是全部子数组答案。

### 3.6 复杂度

| 指标 | 复杂度 | 说明 |
|---|---|---|
| 时间复杂度 | `O(n)` | 每个元素只处理一次 |
| 额外空间复杂度 | `O(1)` | 只有两个计数和当前奇偶性 |

## 四、法二：记忆化搜索

### 4.1 先把 `s` 的真实含义定义清楚

原始代码中的状态是：

```cpp
f(arr, i, s, dp)
```

如果把 `s` 理解为“当前元素左侧的奇偶性”，递推很容易写反。更准确的定义是：

> `s` 表示当前右端已经确定的一段后缀的奇偶性。

对于固定的右端点 `end`：

```text
f(i, s)
= 有多少个左端点 j ∈ [0, i]
  使得 parity(arr[j..i]) xor s == 1
```

最外层调用 `f(end, 0, dp)`：

```text
s = 0
```

表示位置 `end` 的右侧没有额外后缀，因此：

```text
parity(arr[j..end]) xor 0 == 1
⇔ arr[j..end] 的和为奇数
```

于是 `f(end, 0)` 正好统计“以 `end` 结尾的奇数和子数组数量”。

### 4.2 状态转移

设：

```text
newParity = (arr[i] & 1) xor s
```

此时 `newParity` 表示 `arr[i..end]` 的奇偶性。

- 若 `newParity == 1`，左端点选择 `i` 本身就是一个奇数和子数组，贡献 `1`；
- 若继续向左扩展到 `i - 1`，整个后缀 `arr[i..end]` 的奇偶性会作为新的 `s`；
- 因此其余贡献是 `f(i - 1, newParity)`。

递推式为：

```text
f(i, s) = [newParity == 1] + f(i - 1, newParity)
```

其中 `[P]` 在条件为真时等于 `1`，否则等于 `0`。

### 4.3 C++ 实现

```cpp
class Solution {
public:
    static constexpr int MOD = 1'000'000'007;

    int dfs(const vector<int>& arr, int i, int suffixParity,
            vector<array<int, 2>>& memo) {
        if (i < 0) {
            return 0;
        }
        if (memo[i][suffixParity] != -1) {
            return memo[i][suffixParity];
        }

        int newParity = ((arr[i] & 1) ^ suffixParity);
        int result = (newParity == 1 ? 1 : 0);
        result += dfs(arr, i - 1, newParity, memo);

        return memo[i][suffixParity] = result % MOD;
    }

    int numOfSubarrays(vector<int>& arr) {
        int n = static_cast<int>(arr.size());
        vector<array<int, 2>> memo(n, array<int, 2>{-1, -1});

        int answer = 0;
        for (int end = 0; end < n; ++end) {
            answer += dfs(arr, end, 0, memo);
            answer %= MOD;
        }
        return answer;
    }
};
```

### 4.4 手算片段：`arr = [1, 3, 5]`

最外层枚举三个右端点。

#### 右端点为 `2`，值为 `5`

调用：

```text
f(2, 0)
```

| 当前索引 | 当前元素 | 进入时 `s` | `newParity` | 本层贡献 | 下一步 |
|---:|---:|---:|---:|---:|---|
| 2 | 5 | 0 | 1 | 1 | `f(1, 1)` |
| 1 | 3 | 1 | 0 | 0 | `f(0, 0)` |
| 0 | 1 | 0 | 1 | 1 | `f(-1, 1)` |
| -1 | — | 1 | — | 0 | 返回 |

因此：

```text
f(2, 0) = 2
```

对应两个子数组：

```text
[5]、[1, 3, 5]
```

其他右端点分别贡献：

```text
end = 0: f(0, 0) = 1  → [1]
end = 1: f(1, 0) = 1  → [3]
```

总答案是 `1 + 1 + 2 = 4`。

### 4.5 为什么时间复杂度仍然是 `O(n)` 而不是 `O(n²)`

每个状态由下标和奇偶性共同确定：

```text
(i, s),  i ∈ [0, n - 1],  s ∈ {0, 1}
```

总共只有 `2n` 个状态。每个状态第一次计算后都会写入 `memo`，之后直接返回，所以：

```text
状态数 O(n) × 单状态转移 O(1) = O(n)
```

虽然外层看似枚举了所有右端点，但不同右端点会复用大量相同状态。

| 指标 | 复杂度 |
|---|---|
| 时间复杂度 | `O(n)` |
| `memo` 空间 | `O(n)` |
| 递归栈 | `O(n)` |

### 4.6 这道题不适合把递归直接提交

LeetCode 1524 的数组长度可以达到 `10^5`。记忆化的最坏递归深度也是 `10^5`，存在栈溢出风险。

因此：

- 学习“暴力枚举左端点 → 找重复子问题 → 记忆化”时，法二很有价值；
- 真正提交时，优先使用法一的 `O(1)` 空间迭代写法；
- 或者把记忆化递推式改成自底向上的滚动 DP，消除递归栈。

### 4.7 把记忆化压缩成滚动 DP

原始递推只依赖 `i - 1` 的两个状态。令：

```text
prev[0] = f(i - 1, 0)
prev[1] = f(i - 1, 1)
```

则可以计算：

```cpp
array<int, 2> current{};
for (int s = 0; s < 2; ++s) {
    int newParity = ((arr[i] & 1) ^ s);
    current[s] = (newParity == 1 ? 1 : 0) + prev[newParity];
    current[s] %= MOD;
}
```

然后：

```text
answer += current[0]
```

最后执行：

```text
prev = current
```

这样仍然是 `O(n)` 时间，但空间从 `O(n)` 降为 `O(1)`。

它和法一的区别只是“换了一种统计视角”：

- 法一按当前右端点直接批量统计不同的左端点；
- 滚动 DP 从右端向左逐层累计，但最后也只保留两个奇偶状态。

## 五、两种方法对比

| 维度 | 法一：前缀奇偶计数 | 法二：记忆化搜索 |
|---|---|---|
| 状态定义 | 此前奇数 / 偶数前缀各有多少个 | `(i, suffixParity)` |
| 观察角度 | 当前前缀与历史前缀配对 | 固定右端点，向左扩展 |
| 时间复杂度 | `O(n)` | `O(n)` |
| 额外空间 | `O(1)` | `O(n)` |
| 递归栈 | 无 | 最坏 `O(n)` |
| 代码长度 | 短 | 较长 |
| 面试首选 | 是 | 更适合讲解思路 |
| 主要风险 | 忘记空前缀 | 状态含义混淆、栈溢出 |

### 5.1 两者为什么最终都只用到两种状态

区间和只需要区分奇数和偶数，因此任何前缀和都可以被压缩为一位：

```text
0 = 偶数
1 = 奇数
```

记忆化搜索的两个 `s` 值，与法一的两个计数器，本质上描述的是同一组奇偶信息。

### 5.2 面试时如何组织回答

建议顺序：

1. 写出区间和公式，说明“奇数区间 ⇔ 两个前缀奇偶不同”；
2. 初始化空前缀为偶数，维护两个计数；
3. 扫到当前前缀时，加入相反奇偶前缀的数量；
4. 说明每个以 `i` 结尾的区间都被统计一次；
5. 给出复杂度 `O(n) / O(1)`。

如果面试官继续追问“如何从暴力优化”，可以再补充记忆化搜索：

```text
枚举所有左右端点 O(n²)
→ 固定右端点后，奇偶状态只有两种
→ 状态数 O(n)，每次转移 O(1)
→ 最终还可以滚动压缩到 O(1) 空间
```

## 六、易错点与反例

### 坑 1：没有把空前缀算进偶数计数

错误初始化：

```text
cntEven = 0
cntOdd = 0
```

输入：

```text
arr = [1]
```

正确答案是 `1`，但扫描到当前奇数前缀时，此前偶数前缀为 `0`，会错误返回 `0`。

正确初始化：

```text
cntEven = 1
cntOdd = 0
```

### 坑 2：奇偶配对方向写反

当前前缀为奇数时，应加入 `cntEven`，因为：

```text
1 xor 0 = 1
```

当前前缀为偶数时，应加入 `cntOdd`，因为：

```text
0 xor 1 = 1
```

可以用极短数组 `[1]`、`[2]` 分别验证两条分支。

### 坑 3：先更新当前计数，再统计贡献

当前前缀不能和自己配对成非空子数组。

错误顺序：

```cpp
++oddPrefixCount;
answer += evenPrefixCount;
```

这个特定分支的表面结果未必立刻错误，但会破坏“此前前缀”的语义，在另一个分支或后续修改时极易引入重复计数。

更稳妥的表达是：

```cpp
// 始终使用处理当前前缀之前的计数
answer += targetCount;
// 再将当前前缀加入历史
++currentParityCount;
```

### 坑 4：把奇偶性当成完整前缀和保存

本题只需要一位信息。直接累计完整 `sum` 虽然不是错误，但会带来两个问题：

- 在更大数据范围下需要谨慎判断是否溢出；
- 代码表达不出“只关心奇偶”这一核心观察。

推荐写成：

```cpp
prefixParity ^= value & 1;
```

### 坑 5：只对最终结果取模，而中间用 `int` 累加

没有取模前，非空子数组上界是：

```text
n(n + 1) / 2
```

当 `n = 10^5` 时约为 `5 × 10^9`，超过 32 位有符号整数上限。

本题代码每次加入贡献后立即取模，因此 `answer` 始终小于模数，使用 `int` 是安全的。

如果采用另一种写法先累加、最后统一取模，则中间结果必须使用 `long long`。

### 坑 6：误以为负数会破坏前缀奇偶性

即使数组允许负数，公式：

```text
(a - b) mod 2 = (a + b) mod 2
```

仍然成立。奇偶性只取决于数值模 `2` 的结果，与大小顺序和正负无关。

### 坑 7：记忆化搜索的递归深度

`O(n)` 状态复杂度和 `O(n)` 递归深度是两件事。代码时间复杂度合格，不代表递归实现适合 `n = 10^5` 的线上评测。

## 七、闭卷自测

### 7.1 快速判断

1. 为什么空前缀的奇偶性要初始化为偶数？
2. 当前前缀是偶数时，为什么要加入此前的奇数前缀数量？
3. 为什么不需要哈希表，而 LC560 通常需要？
4. 如果数组中出现负数，算法是否需要修改？
5. 法二中的 `s` 到底表示左侧前缀还是右侧后缀的奇偶性？
6. 为什么法二的状态数量是 `2n`，而不是指数级？

### 7.2 小数据手算

分别手算并说明过程：

```text
[2]
[1]
[2, 4]
[2, 3]
[1, 2, 3]
```

参考答案：

```text
[2]       → 0
[1]       → 1
[2, 4]    → 0
[2, 3]    → 2
[1, 2, 3] → 4
```

对于 `[2, 3]`，奇数子数组为：

```text
[3]、[2, 3]
```

对于 `[1, 2, 3]`，奇数子数组为：

```text
[1]、[1, 2]、[3]、[2, 3]
```

## 八、举一反三

### 8.1 按“前缀状态”统一看子数组计数

| 题目类型 | 目标条件 | 需要维护的历史前缀信息 |
|---|---|---|
| LC1524 | 子数组和为奇数 | 奇数前缀数量、偶数前缀数量 |
| LC560 | 子数组和等于 `K` | `前缀和 → 出现次数` |
| LC974 | 子数组和能被 `K` 整除 | `前缀和 mod K → 出现次数` |
| LC523 | 是否存在长度至少为 2、和能被 `K` 整除的子数组 | 每个余数最早出现的位置 |
| LC930 | 二进制子数组和等于 `goal` | `0/1` 前缀和 → 出现次数 |

共通形式：

```text
枚举右端点
→ 计算当前前缀状态
→ 查询此前满足条件的前缀状态数量
→ 把当前前缀状态加入历史
```

### 8.2 从奇偶推广到模 `K`

如果把“奇数和”改成“和能被 `K` 整除”，则每个前缀压缩成：

```text
prefixSum mod K
```

条件也从“奇偶不同”变成“两个前缀的余数相同”。

这正是 LC974 的基本思路，也是前缀状态计数的一般模型：

| “相加得到目标”的条件 | 两个前缀需要满足的关系 |
|---|---|
| 区间和为奇数 | 奇偶性不同 |
| 区间和为偶数 | 奇偶性相同 |
| 区间和能被 `K` 整除 | 余数相同 |

### 8.3 如果要求“最长”而不是“数量”

本题求数量，所以维护每种状态的“出现次数”。

若改为“最长的奇数和子数组”，则对于当前前缀，应该维护：

```text
相反奇偶性的前缀最早出现位置
```

当前下标减去最早位置，就是最长长度。状态从“计数”变为“首次位置”，但核心仍然是前缀状态匹配。

### 8.4 如果要求在线流式返回

法一天然支持流式处理：每读入一个数，只需更新：

```text
prefixParity
oddPrefixCount
evenPrefixCount
answer
```

因此它适合数据逐项到达、不允许回看的场景。法二需要固定数组和记忆表，不适合这一场景。

## 九、最终复盘

| 维度 | 内容 |
|---|---|
| 核心观察 | 区间和奇数 ⇔ 两个前缀和的奇偶性不同 |
| 最优算法 | 前缀奇偶性 + 两状态计数 |
| 初始化关键 | 偶数前缀计数从 `1` 开始 |
| 转移关键 | 奇配偶、偶配奇 |
| 时间复杂度 | `O(n)` |
| 空间复杂度 | `O(1)` |
| 记忆化价值 | 展示如何从“枚举左端点”压缩到两个状态 |
| 记忆化风险 | `O(n)` 递归深度可能栈溢出 |
| 核心口诀 | **当前前缀奇配此前的偶，当前前缀偶配此前的奇；最后别忘了空前缀。** |

### 下次遇到“子数组和满足某条件”时的判断流程

1. 条件能否转化为**两个前缀之间的关系**？
2. 前缀有多少种必要状态？
   - 奇偶性 → 2 种；
   - 模 `K` 的余数 → `K` 种；
   - 完整和 → 可能需要哈希表。
3. 对每个右端点，需要查询哪种历史状态？
4. 历史状态维护“计数”“最早位置”还是“最近位置”？
5. 是否要处理空前缀？
6. 是否需要取模或使用 `long long`？

把这套流程用于 LC1524，答案自然就是：

```text
前缀状态只有奇 / 偶
→ 当前奇配历史偶
→ 当前偶配历史奇
→ 每个右端点分别贡献
→ O(n) 时间，O(1) 空间
```
