# LC1606 找到处理最多请求的服务器

> **错题本条目**｜标签：环形查找 / 双堆协作 / 状态语义识别 / 迭代器安全
> **难度**：困难 ｜ **演进**：bug 版（5 处错）→ AC 版
> **关联**：与已完成 LC1882 同为调度类，建议对照复习

---

## 一、题目描述与考察知识点

### 1.1 题目描述

你有 `k` 个服务器，编号为 `0` 到 `k-1`，可以同时处理多个请求组。每个服务器有无穷的计算能力但是**不能同时处理超过一个请求**。

请求分配到服务器的规则如下：

1. 第 `i`（序号从 0 开始）个请求到达
2. 如果所有服务器都已被占据，那么该请求被**舍弃**
3. 如果第 `(i % k)` 个服务器空闲，那么对应服务器会处理该请求
4. **否则，将请求安排给下一个空闲的服务器**（服务器构成一个环，必要的话可能从第 0 个服务器开始继续找下一个空闲的服务器）。比方说，如果第 `i` 个服务器在忙，那么会查看第 `(i+1)` 个服务器，第 `(i+2)` 个服务器等等

给你一个**严格递增**的正整数数组 `arrival`，表示第 `i` 个任务的到达时间；另一个数组 `load`，其中 `load[i]` 表示第 `i` 个请求的工作量（也就是服务器完成它所需要的时间）。

你的任务是找到**最繁忙的服务器**。最繁忙定义为**一个服务器处理的请求数是所有服务器里最多的**。

请你返回包含所有最繁忙服务器序号的列表，可以以任意顺序返回。

### 1.2 数据范围

| 参数 | 范围 |
|---|---|
| `k` | `1 <= k <= 10^5` |
| `arrival.length == n == load.length` | `1 <= n <= 10^5` |
| `arrival[i]` | `1 <= arrival[i] <= 10^9`，严格递增 |
| `load[i]` | `1 <= load[i] <= 10^9` |

> ⚠️ 注意 `arrival` 和 `load` 元素都可到 `10^9`，但 `end_time = arrival[i] + load[i]` 最大约 `2×10^9`，**勉强在 `int` 范围内**（`int` 上限约 `2.1×10^9`），但若累加或做差容易溢出，谨慎起见用 `long long` 更安全。

### 1.3 考察知识点

- **环形查找**：从指定起点 `(i % k)` 开始找下一个空闲，绕回 0 继续
- **双堆协作**：`work_server`（按 `end_time` 排）+ `idle_server`（按 `id` 排）
- **数据结构选型**：`set<int>` 用于有序存储 + `lower_bound` 二分查找
- **状态语义识别**：「最繁忙」指**请求数最多**，不是 `end_time` 最大
- **迭代器安全**：`erase` 后迭代器失效，避免访问已删除元素

## 二、思路分析（与 LC1882 关联）

### 2.1 与 LC1882 的相同与不同

| 维度 | LC1882 处理任务的服务器 | LC1606 找最繁忙的服务器 |
|---|---|---|
| **服务器选择规则** | 选**权重最小**的空闲服务器 | 从 `(i % k)` 起**环形查找**下一个空闲 |
| **任务到达** | 第 `j` 个任务在第 `j` 秒到达 | 第 `i` 个任务在 `arrival[i]` 时刻到达（严格递增） |
| **答案语义** | 每个**任务**分配到的服务器下标 | 处理**请求数最多**的服务器列表 |
| **任务舍弃** | 不会舍弃（一定等待） | 全部占满时**舍弃** |
| **核心数据结构** | 双堆协作 | `set<int>` + 优先队列 |

### 2.2 三步分配规则的算法翻译

题目给出的分配规则可以分解为三步：

| 规则 | 算法翻译 |
|---|---|
| ① 若 `(i % k)` 空闲 → 直接分配 | 用 `lower_bound(i % k)` 在 `idle_server` 中查找 |
| ② 否则查 `(i+1)`、`(i+2)`、... | `lower_bound` 自动返回首个 ≥ `i % k` 的元素 |
| ③ 必要时绕回 0 继续 | 若 `lower_bound` 返回 `end()`，从 `begin()` 取 |

### 2.3 双堆协作模式

继承 LC1882 的双堆思路：

```
       ┌──────────────────┐     分配任务      ┌──────────────────┐
       │   idle_server    │ ─────────────►  │   work_server    │
       │  按 server_id 排  │                  │  按 end_time 排   │
       │  (set<int>)      │ ◄─────────────  │  (优先队列)       │
       └──────────────────┘    任务完成释放    └──────────────────┘
```

**为什么 `idle_server` 用 `set<int>` 而非 `priority_queue`**？
- 需要支持 `lower_bound(start)` 二分查找：环形查找需要找到「首个 ≥ start 的元素」，`priority_queue` 不支持任意位置查找
- 需要支持任意删除（释放后某服务器又被选走）：`priority_queue` 只能 pop 堆顶

**为什么 `work_server` 用 `priority_queue`**？
- 只需每次取 `end_time` 最小的（最早释放的）
- 不需任意查找或删除
- `priority_queue` 常数更小

### 2.4 「最繁忙」语义识别

**关键洞察**：题目问的是**处理的请求数最多**，**不是** end_time 最大。

- 每次分配成功时，对应服务器的 `cnt[id]++`
- 主循环结束后，遍历 `cnt[]` 找最大值 `maxs`
- 收集所有 `cnt[i] == maxs` 的服务器

**这是 bug 版的核心错误**——把 `end_time` 当成「繁忙度」比较。

## 三、算法详解与手算示例

### 3.1 完整流程

```cpp
初始化：
  - idle_server = {0, 1, 2, ..., k-1}  // 全部空闲
  - work_server = {}（空）
  - cnt[k] = {0}                       // 请求数计数

主循环 for (int i = 0; i < n; i++):
  Step 1: 释放已完成服务器
    while (!work_server.empty() && work_server.top().end_time <= arrival[i]):
      id = work_server.top().server_id;
      work_server.pop();
      idle_server.insert(id);

  Step 2: 环形查找 + 分配
    if (idle_server.empty()) continue;       // 全占满，舍弃该请求

    start = i % k;
    it = idle_server.lower_bound(start);     // 找首个 >= start 的
    if (it == idle_server.end())             // 没找到 → 绕回到 begin
      it = idle_server.begin();

    id = *it;
    idle_server.erase(id);
    cnt[id]++;                               // 请求数 +1
    work_server.push({id, arrival[i] + load[i]});

后处理：
  maxs = max(cnt[0..k-1])
  ans = [所有 cnt[i] == maxs 的 i]
```

### 3.2 手算示例

`k = 3, arrival = [1,2,3,4,5], load = [5,2,2,3,1]`

初始：`idle = {0,1,2}`，`work = {}`，`cnt = [0,0,0]`

| i | arrival[i] | load[i] | start=i%3 | 释放 | 环形查找 | idle | work | cnt |
|---|---|---|---|---|---|---|---|---|
| 0 | 1 | 5 | 0 | — | lower_bound(0)=0 | {1,2} | {(0,6)} | [1,0,0] |
| 1 | 2 | 2 | 1 | — | lower_bound(1)=1 | {2} | {(0,6),(1,4)} | [1,1,0] |
| 2 | 3 | 2 | 2 | — | lower_bound(2)=2 | {} | {(0,6),(1,4),(2,5)} | [1,1,1] |
| 3 | 4 | 3 | 0 | (1,4) 释放（end_time=4≤4）→ idle={1} | lower_bound(0)=end → begin=1 | {} | {(0,6),(2,5),(1,7)} | [1,2,1] |
| 4 | 5 | 1 | 1 | (2,5) 释放（end_time=5≤5）→ idle={2} | lower_bound(1)=end → begin=2 | {} | {(0,6),(1,7),(2,6)} | [1,2,2] |

**后处理**：maxs = max([1,2,2]) = 2，`cnt[1]==2`、`cnt[2]==2` → 答案 `[1, 2]`

### 3.3 环形查找的边界细节

```cpp
auto it = idle_server.lower_bound(start);
if (it == idle_server.end()) {
    it = idle_server.begin();    // 跨转到最小元素
}
```

**为什么不直接 `if (idle_server.count(start))` 然后取 start**？
- `start` 不一定在 `idle_server` 里（可能正忙）
- `lower_bound` 找的是「首个 ≥ start」的元素，自动跳过繁忙的
- 若 `idle_server` 中所有元素都 < start（即 `lower_bound` 返回 `end()`），按规则③绕回到 0，取 `begin()`

**示例**：`k=5, idle={1,3}, start=4`
- `lower_bound(4)` 返回 `end()`（因为 1、3 都 < 4）
- 绕回 `begin()`，取 1
- 即「从位置 4 开始找，4 占据、0 不在 idle、找到 1」

## 四、代码实现（bug 版 vs AC 版）

### 4.1 Bug 版（多处错误）

```cpp
class Solution {
public:
    struct Info{
        int server_id;
        int end_time;
    };

    struct cmp1{
        bool operator()(const Info& a,const Info& b){
            if(a.end_time!=b.end_time) return a.end_time>b.end_time;
            return a.server_id>b.server_id;
        }
    };

    struct cmp2{
        bool operator()(const Info& a,const Info& b){
            return a.server_id>b.server_id;        // 仅比较 server_id，但 Info 含 end_time
        }
    };

    vector<int> busiestServers(int k, vector<int>& arrival, vector<int>& load) {
        map<Info,cmp2> idle_server;                 // ← Bug 1: 类型设计错误
        priority_queue<Info,vector<Info>,cmp1> work_server;
        for(int i = 0;i<k;i++){
            idle_server.insert({i,0});              // ← Bug 2: insert(pair) 与 map<Info> 类型不匹配
        }

        vector<Info> ans;
        int n = arrival.size();
        for(int i = 0;i<n;i++){
            int arrival_time = arrival[i];
            int need_time = load[i];

            while(!work_server.empty()&&arrival_time>=work_server.top().end_time){
                auto top = work_server.top();
                top.end_time = 0;
                work_server.pop();
                idle_server.insert(top);            // ← Bug 3: 把含 end_time=0 的 Info 插入 idle_server
            }

            if(idle_server.empty()) continue;

            auto it = idle_server.begin();          // ← Bug 4: 直接取 begin()，缺失环形查找
            idle_server.erase(it);
            it->end_time+=need_time;                // ← Bug 5: erase 后迭代器失效
            work_server.push(*it);

            if(ans.empty()||it->end_time==ans.back().end_time) ans.push_back(*it);
            else if(it->end_time>ans.back().end_time) {  // ← Bug 6: 用 end_time 判定「最繁忙」，语义错乱
                ans.pop_back();
                ans.push_back(*it);
            }
        }

        vector<int> ret;
        for(auto&ele:ans){
            ret.push_back(ele.server_id);
        }

        return ret;
    }
};
```

### 4.2 AC 版

```cpp
class Solution {
public:
    struct Info{
        int server_id;
        int end_time;
    };

    struct cmp1{
        bool operator()(const Info& a,const Info& b){
            if(a.end_time!=b.end_time) return a.end_time>b.end_time;  // 小根堆：end_time 升序
            return a.server_id>b.server_id;                          // tie-breaker: server_id 升序
        }
    };

    vector<int> busiestServers(int k, vector<int>& arrival, vector<int>& load) {
        set<int> idle_server;                                       // ← 修复 1: set<int>，只存 server_id
        priority_queue<Info,vector<Info>,cmp1> work_server;
        vector<int> cnt(k, 0);                                       // ← 修复 2: 用 cnt 数组统计请求数

        for(int i = 0;i<k;i++){
            idle_server.insert(i);
        }

        int n = arrival.size();
        for(int i = 0;i<n;i++){
            int arrival_time = arrival[i];
            int need_time = load[i];

            // 释放已完成服务器
            while(!work_server.empty() && arrival_time >= work_server.top().end_time){
                int id = work_server.top().server_id;
                work_server.pop();
                idle_server.insert(id);
            }

            if(idle_server.empty()) continue;                       // 全占满，舍弃

            // 环形查找
            int start = i % k;
            auto it = idle_server.lower_bound(start);               // ← 修复 3: 环形查找起点
            if(it == idle_server.end()){
                it = idle_server.begin();                           // ← 修复 3: 跨转到最小元素
            }

            int id = *it;
            idle_server.erase(id);

            cnt[id]++;                                              // ← 修复 4: 用 cnt[id]++ 统计请求数
            work_server.push({id, arrival_time + need_time});
        }

        // 后处理：找最大请求数
        int maxs = 0;
        for(int x:cnt){
            maxs = max(x, maxs);
        }

        vector<int> ret;
        for(int i = 0;i<k;i++){
            if(cnt[i]==maxs){
                ret.push_back(i);
            }
        }
        return ret;
    }
};
```

### 4.3 修复要点总结

| Bug | 修复方式 |
|---|---|
| 1. `map<Info,cmp2>` 类型设计错 | 改用 `set<int>`，仅存 server_id |
| 2. `insert({i,0})` 类型不匹配 | 改为 `insert(i)` |
| 3. 把含 end_time 的 Info 插入 idle_server | idle_server 只存 id，end_time 由 work_server 维护 |
| 4. 缺失环形查找（直接取 `begin()`） | `lower_bound(i%k)` + `end()` 时跨转 `begin()` |
| 5. `erase` 后访问迭代器失效 | 先 `id = *it`，再 `erase(id)`，之后操作 `id` |
| 6. 用 `end_time` 判定「最繁忙」 | 用 `cnt[]` 数组统计请求数 |

## 五、踩坑记录与复盘

### 坑 1：`map<Info,cmp2>` 类型设计错（数据结构选型）

| 维度 | 内容 |
|---|---|
| **现象** | 用 `map<Info, cmp2> idle_server` 试图存「服务器信息」 |
| **问题** | `std::map<Key, T, Compare>` 的三个参数分别是 key、value、比较器。这里 `map<Info, cmp2>` 实际声明的是「以 Info 为 key、以 cmp2 类型为 value、用默认 `less<Info>` 比较」——但 Info 没有 `operator<`，无法编译 |
| **根本原因** | 概念混淆：把「比较器」当成 map 的第二个模板参数，混淆了 `map` 与 `set` 的接口 |
| **修复** | 用 `set<int> idle_server`，因为空闲服务器只需存 id（end_time 概念对空闲服务器无意义） |
| **教训** | **数据结构选型先想清楚「需要存什么」**：本题空闲服务器只需 id，用 `set<int>` 最简；若需额外信息（如权重），用 `set<Info, Cmp>` 或 `map<int, Info>` |

### 坑 2：环形查找逻辑缺失（核心算法错）

| 维度 | 内容 |
|---|---|
| **现象** | Bug 版用 `idle_server.begin()` 直接取最小 id，完全忽略规则③「从 `i%k` 起环形查找」 |
| **影响** | 所有请求都分给最小 id 的空闲服务器，导致分配严重不均，答案完全错 |
| **反例** | `k=3, idle={1,2}, i=2, start=2`：正确应分配给 2（start 命中），Bug 版却分配给 1（begin） |
| **修复** | `lower_bound(start)` 找首个 ≥ start 的；找不到（即所有元素 < start）时跨转到 `begin()` |
| **教训** | **环形结构题要识别「起点 + 绕回」模式**：从指定起点查、找不到则绕回到首位。`set` 的 `lower_bound` + `end()` 判断是经典写法 |

### 坑 3：状态语义错乱（用 end_time 判定「最繁忙」）

| 维度 | 内容 |
|---|---|
| **现象** | Bug 版用 `it->end_time` 与 `ans.back().end_time` 比较，认为 end_time 大的就是「最繁忙」 |
| **问题** | 题目定义「最繁忙」= **处理的请求数最多**，与 end_time（任务结束时刻）完全无关 |
| **影响** | 答案返回的是「end_time 最大的服务器」，可能根本没处理过几个请求 |
| **修复** | 用 `cnt[id]++` 统计每个服务器处理的请求数，最后找最大值 |
| **教训** | **审题要抠字眼**：「最繁忙」在不同题里有不同定义——可能是「处理数最多」「CPU 时间最长」「end_time 最大」「负载最高」等。务必看清题目定义 |

### 坑 4：迭代器失效（C++ 通用陷阱）

| 维度 | 内容 |
|---|---|
| **现象** | Bug 版 `idle_server.erase(it); it->end_time += need_time;` —— erase 后仍访问 `it` |
| **问题** | `set/map` 的 `erase(it)` 会使 `it` 失效，继续访问是未定义行为（UB） |
| **影响** | 可能崩溃、可能读到垃圾值、可能看似正常但隐藏 bug |
| **修复** | 先 `int id = *it;` 拷出值，再 `erase(id)`，之后操作 `id` |
| **教训** | **C++ 容器 erase 后迭代器立即失效**：正确写法是 `auto next = erase(it)`（C++11 起返回下一个迭代器）或先拷贝值再 erase |

### 坑 5：end_time 混入 idle_server 状态

| 维度 | 内容 |
|---|---|
| **现象** | Bug 版从 work_server 弹出服务器后，把含 end_time 的 Info 直接插入 idle_server |
| **问题** | idle_server 的语义是「空闲服务器集合」，空闲服务器**没有 end_time 概念**（它当前没在处理任务） |
| **影响** | 同一个服务器在两堆间切换时 end_time 字段被反复读写，状态混乱；后续若误用 end_time 做判断（如坑 3），逻辑错乱 |
| **修复** | idle_server 只存 `int`（server_id）；end_time 信息只在 work_server 的 Info 中存在 |
| **教训** | **状态字段归属于语义对应的数据结构**：end_time 是「正在工作的服务器」的属性，应只出现在 work_server；idle_server 只关心 id |

### 通用教训小结

> 1. **数据结构选型先想「需要存什么」**：本题 idle 只需 id，用 set<int> 最简
> 2. **环形结构识别「起点 + 绕回」模式**：lower_bound + end() 跨转是经典写法
> 3. **状态语义抠字眼**：「最繁忙」「最多」「最大」要看清定义，别用想当然的指标
> 4. **迭代器失效是 C++ 通用陷阱**：erase 前先拷出值
> 5. **状态字段归属对应数据结构**：不要把无关字段混入（如 idle 不需要 end_time）

## 六、与 LC1882 深度对比

### 6.1 题目对照表

| 维度 | LC1882 处理任务的服务器 | LC1606 找最繁忙的服务器 |
|---|---|---|
| **服务器选择规则** | 权重最小，相同权重按下标最小 | 从 `(i % k)` 起环形查找下一个空闲 |
| **空闲服务器排序依据** | `(weight, idx)` 字典序 | `id` 升序（用于 lower_bound） |
| **任务到达** | 第 j 个任务在第 j 秒到达 | 第 i 个任务在 `arrival[i]` 时刻到达 |
| **任务舍弃** | 不舍弃，等待 | 全占满时舍弃 |
| **答案语义** | 每个**任务**分配的服务器下标 | 处理**请求数最多**的服务器列表 |
| **核心数据结构** | 双堆（idle_pq + work_pq） | `set<int>` + `priority_queue` |
| **空闲集数据结构选择** | `priority_queue`（只需堆顶） | `set`（需要 lower_bound 查找） |
| **答案统计** | 实时记录 `ans[i] = id` | 后处理找最大值 |

### 6.2 关键差异：为什么 LC1882 用 priority_queue 而 LC1606 用 set？

**LC1882**：每次选「权重最小」的空闲服务器 → 只需取堆顶 → `priority_queue` 足够

**LC1606**：每次选「从指定起点起环形查找首个空闲」 → 需要二分查找 → `priority_queue` 不支持，必须用 `set`

**结论**：**「需不需要任意位置查找」决定数据结构选择**：
- 只取堆顶 → `priority_queue`（常数小）
- 需要 lower_bound / 任意删除 → `set` / `map`

### 6.3 关键差异：答案语义

**LC1882**：实时记录「每个任务分配给谁」，分配时即 `ans[i] = id`

**LC1606**：累积统计「每个服务器处理了多少请求」，主循环结束后再找最大值

**结论**：**答案形式决定统计时机**：
- 每个 item 都要答案 → 实时记录
- 只关心最终聚合值（最大值 / 总数等） → 累积统计 + 后处理

### 6.4 共同套路：双堆协作

两题都遵循「工作堆 + 空闲集」的双堆协作模式：

```
扫描每个请求：
  1. 释放 work_server 中已完成的服务器到 idle_server
  2. 从 idle_server 选一个（按各自规则）
  3. 分配任务，推入 work_server
```

**这是任务调度类题目的通用模板**，记住这个骨架可以快速套用。

## 七、复杂度分析

### 7.1 时间复杂度

| 操作 | 次数 | 单次复杂度 | 小计 |
|---|---|---|---|
| 初始化 idle_server | `k` 次 insert | `O(log k)` | `O(k log k)` |
| 主循环 | `n` 次 | — | — |
| 释放服务器（work → idle） | 总共最多 `n` 次 | `O(log k)` | `O(n log k)` |
| 环形查找（lower_bound） | `n` 次 | `O(log k)` | `O(n log k)` |
| 分配任务（idle → work） | `n` 次（最多，舍弃的不算） | `O(log k)` | `O(n log k)` |
| 后处理找最大值 | `k` 次 | `O(1)` | `O(k)` |
| **总计** | — | — | **`O((n + k) log k)`** |

### 7.2 空间复杂度

| 部分 | 大小 |
|---|---|
| `idle_server` + `work_server` | 合计不超过 `k` |
| `cnt` 数组 | `O(k)` |
| `ans`（返回值） | `O(k)` 最坏 |
| **总计** | **`O(k)`** |

### 7.3 复杂度边界思考

- `k = 1`：所有请求串行，复杂度 `O(n)`
- `k >> n`：每个请求都直接分配到 `i%k`（永远空闲），复杂度 `O(n log k)`
- `k = n = 10^5`：`(n+k) log k ≈ 3×10^6`，远在时限内

### 8.2 拓展思考

- **环形结构题的常见处理套路**：
  - 模拟绕回：`if (it == end()) it = begin();`
  - 取模运算：`(i + 1) % k`、`(i - 1 + k) % k`
  - 双倍数组：把原数组复制一份拼起来，化为线性问题（适用于「环形数组最大子段和」类题）
- **数据结构选择决策树**：
  ```
  需要存什么？
  ├─ 只需堆顶 → priority_queue
  ├─ 需要 lower_bound / 任意删除 → set / map
  ├─ 需要按多个键排序 → set<struct, cmp> 或 map<key1, map<key2, val>>
  └─ 需要持久化历史版本 → 可持久化数据结构（主席树等）
  ```
- **答案形式决策**：
  - 每个事件都要答案 → 实时记录
  - 最终聚合 → 累积 + 后处理
- **状态字段归属**：每个数据结构只存其语义对应的状态字段，避免「大杂烩结构体」

### 8.3 通用模板：环形查找 + 双堆协作

```cpp
// 模板：环形分配 + 双堆协作
struct WorkItem {
    int id;
    long long end_time;
};
struct CmpWork {
    bool operator()(const WorkItem& a, const WorkItem& b) const {
        if (a.end_time != b.end_time) return a.end_time > b.end_time;
        return a.id > b.id;
    }
};

vector<int> ringScheduler(int k, vector<int>& arrival, vector<int>& load) {
    set<int> idle;
    priority_queue<WorkItem, vector<WorkItem>, CmpWork> work;
    vector<int> cnt(k, 0);

    for (int i = 0; i < k; ++i) idle.insert(i);

    for (int i = 0; i < (int)arrival.size(); ++i) {
        // 释放已完成
        while (!work.empty() && work.top().end_time <= arrival[i]) {
            idle.insert(work.top().id);
            work.pop();
        }
        if (idle.empty()) continue;           // 舍弃

        // 环形查找
        int start = i % k;
        auto it = idle.lower_bound(start);
        if (it == idle.end()) it = idle.begin();

        int id = *it;
        idle.erase(id);
        cnt[id]++;
        work.push({id, (long long)arrival[i] + load[i]});
    }

    // 后处理
    int maxs = *max_element(cnt.begin(), cnt.end());
    vector<int> ans;
    for (int i = 0; i < k; ++i)
        if (cnt[i] == maxs) ans.push_back(i);
    return ans;
}
```

## 九、复盘小结

| 维度 | 内容 |
|---|---|
| 核心算法 | 环形查找 + 双堆协作 |
| 难度 | 困难 |
| 关键洞察 | 「环形查找」需 lower_bound + 跨转；「最繁忙」是请求数最大不是 end_time 最大 |
| 主要踩坑 | 1) `map<Info,cmp2>` 类型设计错（应 set<int>）<br>2) 环形查找缺失（应 lower_bound + 跨转）<br>3) 状态语义错乱（用 end_time 当繁忙度）<br>4) 迭代器失效（erase 后访问）<br>5) end_time 混入 idle 状态 |
| 核心教训 | **数据结构选型先想「需要存什么」；环形结构识别「起点+绕回」模式；状态语义抠字眼；erase 前先拷值** |
| 与 LC1882 关系 | 同为双堆协作调度题，但 LC1882 用 priority_queue（选权重最小），LC1606 用 set（环形查找） |

### 下次遇到调度类题目的判断流程

1. **服务器选择规则是什么**？
   - 选最小权重 / 最小 idx → `priority_queue` + 自定义比较器
   - 从指定起点环形查找 → `set` + `lower_bound` + 跨转
   - 选最大 / 最小剩余容量 → `priority_queue` 或 `multiset`
2. **任务到达是按时间还是按索引**？
   - 按索引（第 j 个在第 j 秒）→ 不需 arrival 数组
   - 按时间（arrival 数组）→ 需要时间驱动释放
3. **任务舍弃还是等待**？
   - 舍弃 → `if (idle.empty()) continue;`
   - 等待 → `if (idle.empty()) time = work.top().end_time;`（参考 LC1882）
4. **答案形式是什么**？
   - 每个任务一个答案 → 实时记录 `ans[i]`
   - 最终聚合（最大值 / 列表）→ 累积 `cnt[]` + 后处理
5. **数据范围会溢出吗**？
   - end_time 累加 → `long long` 保险
   - 请求数 n ≤ 10^5 → `int` 够

记住这个判断流程，遇到任务调度类题目，先识别「选择规则」和「答案形式」，再选数据结构，避免 Bug 版那种「想当然」式编码。
