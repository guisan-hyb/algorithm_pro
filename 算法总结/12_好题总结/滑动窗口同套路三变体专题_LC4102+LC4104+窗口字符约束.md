# 滑动窗口同套路三变体专题｜LC4102 + LC4104 + 窗口字符约束

> **错题本条目**｜标签：滑动窗口 / 子串与子序列 / 状态机设计 / 计数器维护
> **难度**：中等 ｜ **专题性质**：三题对比，提炼「对每个 r 求最小 l」统一框架

---

## 一、三题速览与统一框架

### 1.1 三题并列速览

| 编号 | 题意 | 限制条件 | 求解目标 |
|---|---|---|---|
| **LC4102** | 字符串仅含 `a/b/c` | 不含 `"abc"` 作为**子串** | 有效子串数 |
| **LC4104** | 字符串仅含 `a/b/c` | 不含 `"abc"` 作为**子序列** | 有效子串数 |
| **改编题** | 字符串仅含 `a/b/c` | 窗口内**不同字符数 ≤ 2** | 有效子串数 |

### 1.2 统一框架

三题本质同型，都遵循一个共同模板：

> **对每个右端点 r，求出最小的左端点 l，使得子串 [l, r] 满足条件；累加 `r - l + 1` 到答案。**

```cpp
long long ans = 0;
for (int l = 0, r = 0; r < n; r++) {
    // 更新状态（与右端点 r 相关）
    // 调整 l（让 [l, r] 满足条件）
    ans += r - l + 1;
}
```

**为什么 `r - l + 1` 是对的**？

固定 r 时，所有以 r 结尾的合法子串为 `[r, r]`、`[r-1, r]`、...、`[l, r]`，共 `r - l + 1` 个。把每个 r 的贡献相加，得到所有合法子串总数。这是**右端点贡献法**，比「枚举所有子串」少一个维度。

三题的差异，**只在「如何更新状态」和「如何调整 l」两行**：

| 题目 | 状态变量 | l 调整依据 |
|---|---|---|
| LC4102 | `last`（最近 "abc" 起始位置） | `l > last` |
| LC4104 | `last_a`、`last_AB_a`、`last_ABC_a`（三阶段状态机） | `l > last_ABC_a` |
| 改编题 | `cnt` + `visited`（窗口内字符计数） | `visited.size() <= 2` |

## 二、LC4102：不含 "abc" 作为子串

### 2.1 题目描述

给定仅由 `a`、`b`、`c` 组成的字符串 `s`。如果一个字符串**不包含 `"abc"` 作为子串**，则称其为有效的。返回 `s` 中有效子串的数量。

> **子串**：字符串内连续的非空字符序列。

### 2.2 逆推思路

**问题**：怎样判断子串 `[l, r]` 是否含 `"abc"` 子串？

**逆推**：`[l, r]` 含 `"abc"` 子串 ⟺ 存在某个位置 `i ∈ [l, r-2]` 使得 `s[i..i+2] = "abc"`。

**关键观察**：设当前扫描到右端点 `r`，若发现 `s[r-2..r] = "abc"`，那么这个 `"abc"` 的起始位置 `r-2` 就是个**禁区起点**——任何包含位置 `r-2` 的子串（即 `l <= r-2`）都会含 `"abc"`。

**全局禁区**：随着扫描推进，"abc" 可能多次出现。设 `last` 为**最近一次出现的 "abc" 的起始位置**，则任何 `l <= last` 的子串都会**至少包含**这次 "abc"（因为它在 `[l, r]` 内）。

**结论**：`l` 必须满足 `l > last`。

### 2.3 状态设计

```cpp
int last = -1;   // 最近一次 "abc" 起始位置，-1 表示尚未出现
// 当 s[r-2..r] == "abc" 时：last = r - 2
// 调整 l：while (l <= last) l++;
```

**为什么用「最近一次」而不是「最早一次」**？

因为 `r` 单调右移，**新的 "abc" 起始位置一定 ≥ 旧的**。`last` 单调不减，所以 `l` 也单调不减，整个扫描是 `O(n)`。

如果用「最早一次」，会导致 `l` 卡在某个固定位置不能动，会错误地丢弃一些合法子串。

### 2.4 AC 代码

```cpp
class Solution {
public:
    long long countValidSubstrings(string s) {
        int n = s.size();
        long long ans = 0;
        int last = -1;
        for (int l = 0, r = 0; r < n; r++) {
            // 检测 r 结尾的 "abc" 子串
            if (r >= 2 && s[r] == 'c' && s[r-1] == 'b' && s[r-2] == 'a') {
                last = r - 2;          // 更新禁区起点
            }
            // 收缩 l 直到越过 last
            while (l <= last) l++;
            // 累加以 r 结尾的合法子串数
            ans += r - l + 1;
        }
        return ans;
    }
};
```

### 2.5 变体写法

**变体 1：直接用 `string::find`**（不推荐，每次 find 是 O(n)，整体 O(n²)）

```cpp
// 不推荐：复杂度退化
size_t pos = s.find("abc");
// ...
```

**变体 2：KMP 失败指针**（适合模式串更长的场景，本题 "abc" 仅 3 字符，过于复杂）

```cpp
// KMP 思路，对模式串 "abc" 预处理 next 数组，扫描时维护匹配长度
// 本题模式串太短，直接 if 判断更清晰
```

**变体 3：用滚动哈希**（理论可行，但常数大）

```cpp
// 滚动哈希检测 "abc"，对短模式串杀鸡用牛刀
```

> **结论**：对于本题「模式串仅 3 字符」的场景，**直接 if 判断**是最优解，KMP / 哈希都属于过度设计。

## 三、LC4104：不含 "abc" 作为子序列

### 3.1 题目描述

给定仅由 `a`、`b`、`c` 组成的字符串 `s`。如果一个字符串**不包含 `"abc"` 作为子序列**，则称其为有效的。返回 `s` 中有效子串的数量。

> **子序列**：从原字符串中删除一些或不删除字符，不改变剩余字符顺序所得到的新字符串。

### 3.2 子串 vs 子序列的本质区别

这是本专题**最核心**的对比点：

| 维度 | 子串 "abc" | 子序列 "abc" |
|---|---|---|
| 定义 | 连续 3 个字符恰好为 `a,b,c` | 字符串中存在 `a` 在 `b` 前、`b` 在 `c` 前 |
| 检测复杂度 | O(1)（看末尾 3 个字符） | 需要追踪状态机 |
| 禁区起点 | "abc" 起始位置 `r-2` | **完成 "abc" 子序列的那个 `a` 的位置** |
| 状态变量 | 单个 `last` | 三个 `last_a / last_AB_a / last_ABC_a` |

**核心差异**：子序列允许中间有其他字符，所以不能简单看「最后 3 个字符」，必须**逐步构建**「`a` → `ab` → `abc`」的状态。

### 3.3 逆推思路与状态机设计

**问题**：怎样判断子串 `[l, r]` 是否含 `"abc"` 子序列？

**逆推**：`[l, r]` 含 `"abc"` 子序列 ⟺ 存在 `i < j < k`（`l <= i < j < k <= r`）使得 `s[i]='a'`、`s[j]='b'`、`s[k]='c'`。

**贪心策略**：为了让 "abc" 子序列尽可能早出现（即对应的 `a` 位置尽可能靠左），应该选**最近能形成 "ab" 的 `a`**，再用最新的 `c` 完成 "abc"。

**三阶段状态机**：

| 状态变量 | 含义 | 更新时机 |
|---|---|---|
| `last_a` | 最近的 `'a'` 出现位置 | 遇到 `'a'` 时 `last_a = r` |
| `last_AB_a` | 最近的能形成 `"ab"` 子序列的 `'a'` 位置 | 遇到 `'b'` 且 `last_a != -1` 时 `last_AB_a = last_a` |
| `last_ABC_a` | 最近的能形成 `"abc"` 子序列的 `'a'` 位置 | 遇到 `'c'` 且 `last_AB_a != -1` 时 `last_ABC_a = last_AB_a` |

**为什么是这种链式更新**？

- 看 `'a'`：更新最近的 `a` 位置（备用，给后续的 `b` 用）
- 看 `'b'`：如果之前有 `a`（`last_a != -1`），那么这个 `a` 现在能跟当前 `b` 拼成 "ab"
- 看 `'c'`：如果之前有 "ab"（`last_AB_a != -1`），那么这个 "ab" 的 `a` 位置现在能跟当前 `c` 拼成 "abc"

最终 `last_ABC_a` 就是「禁区起点」——任何 `l <= last_ABC_a` 的子串都会含 "abc" 子序列。

### 3.4 AC 代码

```cpp
class Solution {
public:
    long long countValidSubstrings(string s) {
        int n = s.size();
        long long ans = 0;
        int last_a = -1, last_AB_a = -1, last_ABC_a = -1;
        for (int l = 0, r = 0; r < n; r++) {
            // 状态机更新：注意顺序——
            // 'a' 更新 last_a；
            // 'b' 用 last_a 更新 last_AB_a；
            // 'c' 用 last_AB_a 更新 last_ABC_a
            if (s[r] == 'a') {
                last_a = r;
            } else if (s[r] == 'b') {
                if (last_a != -1) last_AB_a = last_a;
            } else {  // s[r] == 'c'
                if (last_AB_a != -1) last_ABC_a = last_AB_a;
            }
            // 收缩 l 直到越过 last_ABC_a
            while (l <= last_ABC_a) l++;
            ans += r - l + 1;
        }
        return ans;
    }
};
```

### 3.5 变体写法

**变体 1：用 if-else if 链 vs 用 switch**（语义等价，前者更清晰）

**变体 2：用数组存储状态**（适合模式串更长时，如 "abcde" 子序列）

```cpp
// 对于模式串 P 长度为 k 的子序列检测
int last[k] = {-1, -1, ..., -1};   // last[i] = 已构建 P[0..i] 子序列的起点位置
for (int r = 0; r < n; r++) {
    for (int i = k - 1; i >= 0; i--) {  // 倒序更新避免覆盖
        if (s[r] == P[i]) {
            if (i == 0) last[0] = r;
            else if (last[i-1] != -1) last[i] = last[i-1];
        }
    }
    while (l <= last[k-1]) l++;
    ans += r - l + 1;
}
```

**变体 3：自动机 DFA**（理论上最优雅，但实现复杂）

把 `"abc"` 子序列检测建模为 4 状态 DFA：`∅ → a → ab → abc`，每次读入字符转移状态。本质等价于上面的三阶段状态机。

> **结论**：对于 "abc" 这种短模式，**三变量链式更新**最直观；模式串变长时建议用 `last[]` 数组泛化。

## 四、改编题：窗口内不同字符数 ≤ 2

### 4.1 题目描述

给定仅由 `a`、`b`、`c` 组成的字符串 `s`。如果子串中**不同字符的数量不超过 2**，则称其为有效的。返回 `s` 中有效子串的数量。

### 4.2 与前两题的本质区别

| 维度 | LC4102 / LC4104 | 改编题 |
|---|---|---|
| 限制对象 | 特定序列（"abc"） | 字符集合大小 |
| 检测方式 | 位置记忆（last 系列） | 计数器维护 |
| 难点 | 状态机设计 | 集合大小动态维护 |
| 数据结构 | 整数变量 | `unordered_map` 或数组 |

**核心差异**：前两题是「**特定模式**检测」，本题是「**集合基数**约束」。前者需要追踪模式构建进度，后者只需维护当前窗口的字符集大小。

### 4.3 思路

经典双指针滑动窗口：

1. 维护 `cnt[c]`：窗口内字符 `c` 的出现次数
2. 维护 `visited`：窗口内出现次数 > 0 的字符集合
3. 右端 `r` 推进时，`cnt[s[r]]++`，若从 0 变 1 则 `visited.insert(s[r])`
4. 若 `visited.size() == 3`（说明三种字符都在），收缩 `l` 直到 `visited.size() <= 2`
5. 累加 `r - l + 1`

### 4.4 AC 代码

```cpp
class Solution {
public:
    long long countValidSubstrings(string s) {
        int n = s.size();
        unordered_map<char, int> cnt;
        unordered_set<char> visited;
        long long ans = 0;
        for (int l = 0, r = 0; r < n; r++) {
            // 加入 s[r]，更新计数与集合
            if (cnt[s[r]]++ == 0) visited.insert(s[r]);
            // 收缩 l 直到不同字符数 <= 2
            while (l < n && visited.size() == 3) {
                if (--cnt[s[l]] == 0) {
                    visited.erase(s[l]);
                }
                l++;
            }
            ans += r - l + 1;
        }
        return ans;
    }
};
```

### 4.5 变体写法

**变体 1：用 `vector<int>(26)` 代替 `unordered_map`**（常数更小，本题字符集仅 3 种更适用 `vector<int>(3)`）

```cpp
class Solution {
public:
    long long countValidSubstrings(string s) {
        int n = s.size();
        int cnt[3] = {0, 0, 0};     // 仅 a/b/c 三种字符
        int distinct = 0;            // 直接维护计数，省去 unordered_set
        long long ans = 0;
        for (int l = 0, r = 0; r < n; r++) {
            if (cnt[s[r] - 'a']++ == 0) distinct++;
            while (distinct == 3) {
                if (--cnt[s[l] - 'a'] == 0) distinct--;
                l++;
            }
            ans += r - l + 1;
        }
        return ans;
    }
};
```

**优势**：避免 `unordered_map` / `unordered_set` 的哈希常数开销，性能提升 2-3 倍。

**变体 2：用位掩码**（仅当字符集 ≤ 32 时适用）

```cpp
// 用一个 int 的低 3 位表示 a/b/c 是否在窗口内
int mask = 0;
// 加 s[r]：mask |= (1 << (s[r] - 'a'))
// 减 s[l]（若 cnt 归零）：mask &= ~(1 << (s[l] - 'a'))
// 判断：__builtin_popcount(mask) <= 2
```

**变体 3：定长双指针 vs 变长双指针**（本题是变长，定长场景另算）

> **结论**：本题最优写法是**变体 1**——用数组替代哈希表，常数最小。LeetCode 数据范围不大时 `unordered_map` 也能 AC，但养成「**字符集小就用数组**」的习惯。

## 五、三题对比与套路提炼

### 5.1 大对比表

| 维度 | LC4102 | LC4104 | 改编题 |
|---|---|---|---|
| **限制对象** | 不含 "abc" 子串 | 不含 "abc" 子序列 | 不同字符数 ≤ 2 |
| **状态变量** | `last`（1 个） | `last_a, last_AB_a, last_ABC_a`（3 个） | `cnt[]` + `visited`（或 `distinct`）|
| **难点检测方式** | 看末尾 3 字符 | 三阶段状态机链式更新 | 计数器增减维护集合大小 |
| **l 调整依据** | `l > last` | `l > last_ABC_a` | `visited.size() <= 2` |
| **l 收缩方式** | `while (l <= last) l++` | `while (l <= last_ABC_a) l++` | `while (visited.size() == 3) { --cnt; ...; l++; }` |
| **时间复杂度** | O(n) | O(n) | O(n) |
| **空间复杂度** | O(1) | O(1) | O(1)（字符集固定）|
| **难点检测复杂度** | O(1) per char | O(1) per char | O(1) per char（用数组）|

### 5.2 同套路三变体的本质

三题共享同一个**算法骨架**：

```
扫描 r 从 0 到 n-1：
  1. 更新状态（与 s[r] 相关）
  2. 调整 l 让 [l, r] 满足条件
  3. ans += r - l + 1
```

差异只在第 1 步的**状态设计**和第 2 步的**判断条件**：

- **位置记忆型**（LC4102）：单变量 `last` 记最近禁区起点
- **状态机型**（LC4104）：多变量链式更新，构建「逐步完成」的过程
- **计数器型**（改编题）：维护窗口内元素计数与集合大小

### 5.3 子串 vs 子序列的本质差异

这是本专题最重要的对比：

**子串检测**：「连续」要求意味着只需看「最近一段」，状态可以用**单点位置**表达。

**子序列检测**：「不连续但有序」要求意味着需要**逐步构建**，状态需要**多阶段链式**表达。

**举例对照**：在字符串 `"aXXbYYc"` 中（X、Y 为任意非 abc 字符，本题中视为不存在，简化为 `"aXbYc"` 但 X、Y 必须是 a/b/c，所以更准确例子是 `"acbabc"`）：

- 子串 "abc"：只在位置 3-5 出现一次（`s[3..5]="abc"`）
- 子序列 "abc"：可以从 `s[0]='a'`、`s[2]='b'`、`s[5]='c'` 拼，也可以从 `s[3]='a'`、`s[4]='b'`、`s[5]='c'` 拼，多种拼法

子序列检测的复杂之处在于「**多种拼法**」——但通过贪心选「最近的 `a`」「最近的能拼 ab 的 `a`」，能简化为单链状态机。

### 5.4 滑动窗口变形谱

把三题放到更广的滑动窗口变形谱中：

| 变形类型 | 特征 | 典型题 |
|---|---|---|
| **位置记忆型** | 单点禁区，单变量维护 | LC4102、LC2747 |
| **状态机型** | 多阶段构建，链式更新 | LC4104、子序列匹配类 |
| **计数器型** | 集合大小 / 频次约束 | 改编题、LC3、LC1358 |
| **求和型** | 窗口内元素和约束 | LC209、LC713 |
| **最多 K 个型** | 重复次数上限 | LC2958、LC340 |

记住这 5 种变形，遇到滑动窗口题先归类，能快速锁定状态设计方向。

## 六、踩坑记录与复盘

### 坑 1：LC4102 的 `last = r - 2` 不要写成 `r - 1` 或 `r`

| 维度 | 内容 |
|---|---|
| **现象** | 检测到 `s[r-2..r] = "abc"` 时，`last` 应记录**起始位置** `r-2`，而非结束位置 `r` |
| **错写影响** | 写成 `last = r` 会过度收缩 `l`，丢弃合法子串；写成 `last = r - 1` 同理 |
| **原因** | "abc" 起始位置才是「禁区起点」，子串 `[l, r]` 含 "abc" 当且仅当 `l <= r-2` |
| **教训** | 检测到模式串时，**记录的是「禁区起点」**而非「模式串结束位置」|

### 坑 2：LC4104 三个 `last` 的更新顺序不能颠倒

| 维度 | 内容 |
|---|---|
| **现象** | 必须按 `'a' → last_a`、`'b' → 用 last_a 更新 last_AB_a`、`'c' → 用 last_AB_a 更新 last_ABC_a` 的链式顺序 |
| **错写影响** | 若顺序颠倒（如先更新 `last_AB_a` 再更新 `last_a`），会用**当前帧**的 `last_a` 而非**上一帧**的，导致状态错乱 |
| **原因** | 状态机是「逐步构建」，每个状态依赖前一个状态的稳定值 |
| **教训** | 多变量状态机更新时，**按依赖顺序**写，避免「同时更新」造成相互污染 |

### 坑 3：改编题 `visited.size()` 与 `cnt` 必须同步

| 维度 | 内容 |
|---|---|
| **现象** | 加入字符时若 `cnt[s[r]]` 从 0 变 1，必须**同时** `visited.insert(s[r])`；移出字符时若 `cnt[s[l]]` 减到 0，必须**同时** `visited.erase(s[l])` |
| **错写影响** | 漏掉任一处同步，`visited.size()` 会与实际不同字符数不一致，判断错误 |
| **原因** | `visited` 是 `cnt` 的「非零位」投影，二者必须同步维护 |
| **教训** | 双数据结构维护同一逻辑状态时，**所有修改点必须双写**；或用变体 1 的 `distinct` 计数器替代 `visited`，避免双写 |

### 坑 4：答案必须用 `long long`（通用坑）

| 维度 | 内容 |
|---|---|
| **现象** | 三题答案都是子串数，最大可达 `n × (n+1) / 2 ≈ n²/2` |
| **数值估算** | 若 `n = 10^5`，则 `n²/2 = 5×10^9`，**超出 `int` 上限 `2.1×10^9`** |
| **影响** | 用 `int` 累加 `ans` 会溢出，结果错误 |
| **修复** | `long long ans = 0;` |
| **教训** | **「计数题先估算上界」**：凡是「数子串/子数组/子序列」类问题，上界常是 `O(n²)`，必须用 `long long` |

### 通用教训小结

> 1. **统一框架先于细节**：三题算法骨架一致，先掌握「右端贡献法」再区分状态设计
> 2. **子串 vs 子序列是质变**：从「位置记忆」到「状态机」是质变，不是量变
> 3. **状态变量个数 = 模式构建阶段数**：模式串多长，状态机就要几个变量
> 4. **字符集小就用数组**：避免 `unordered_map` 的常数开销
> 5. **计数题估算上界**：`n=10^5` 时 `n²` 必溢出 `int`

## 七、复杂度分析

### 7.1 时间复杂度

三题均**O(n)**，证明关键：`l` 单调不减。

| 题目 | 内层 while 次数 | 总复杂度 |
|---|---|---|
| LC4102 | `l` 总共最多从 0 推进到 n，内层 while 总次数 ≤ n | O(n) |
| LC4104 | 同上 | O(n) |
| 改编题 | 同上 | O(n) |

**关键观察**：虽然代码里有 `while` 看似嵌套，但 `l` 是**单调不减**的，整个扫描过程中 `l` 最多从 0 走到 n，所以内层 while 的**总执行次数 ≤ n**，均摊到每个 r 是 O(1)。

### 7.2 空间复杂度

三题均**O(1)**（字符集固定为 3）：

| 题目 | 状态变量 | 大小 |
|---|---|---|
| LC4102 | `last` | O(1) |
| LC4104 | 3 个 `last_*` | O(1) |
| 改编题 | `cnt[3]` + `distinct` | O(1) |

若字符集扩展到 26（小写字母），仍是 O(26) = O(1)；扩展到全 Unicode 才需考虑 O(n)。

### 7.3 复杂度边界思考

- **n = 10^5**：O(n) 约 `10^5` 次操作，远在时限内
- **n = 10^7**：O(n) 仍可行，但需注意常数（用数组而非 `unordered_map`）
- **模式串变长（如 "abcdef"）**：LC4102 的 if 判断变长但仍 O(1) per char；LC4104 状态变量变多但仍 O(k) per char（k 为模式串长度）

### 8.2 拓展思考

- **正序 vs 逆序状态设计**：LC4104 是「正序构建 abc」，若改为「不含 cba 子序列」则需「逆序扫描 + 反向状态机」
- **双指针 vs 单调栈**：求「以每个 r 结尾的最小 l」用双指针；求「以每个 r 结尾的最大 l」可能需单调栈
- **多维约束**：若同时要求「不含 abc 子串」+「不同字符 ≤ 2」，需融合位置记忆和计数器，状态空间扩大
- **离线查询场景**：若题目改为多次查询区间内合法子串数，需用前缀和 + 离线处理

### 8.3 通用模板

```cpp
// 滑动窗口「右端贡献法」通用模板
long long slidingWindow(string s) {
    int n = s.size();
    long long ans = 0;
    // 状态变量声明（按需选择一种）
    int last = -1;              // 位置记忆型
    // int last1 = -1, last2 = -1, last3 = -1;  // 状态机型
    // int cnt[26] = {0}, distinct = 0;          // 计数器型

    for (int l = 0, r = 0; r < n; r++) {
        // Step 1: 更新状态（处理 s[r]）
        // ... 按题意设计 ...

        // Step 2: 收缩 l 让 [l, r] 满足条件
        while (/* [l, r] 不满足条件 */) {
            // 移出 s[l] 相关状态
            l++;
        }

        // Step 3: 累加贡献
        ans += r - l + 1;
    }
    return ans;
}
```

**模板使用要点**：
1. Step 1 的状态更新**必须先于** Step 2 的收缩判断
2. Step 2 的条件是「**不**满足条件时继续收缩」，注意取反
3. Step 3 的 `r - l + 1` 在收缩完成后计算，保证 `[l, r]` 已合法

## 九、复盘小结

| 维度 | 内容 |
|---|---|
| 核心算法 | 滑动窗口「右端贡献法」 |
| 难度 | 中等 |
| 三题共性 | 都用「对每个 r 求最小 l，ans += r - l + 1」框架 |
| 三题差异 | 状态设计：位置记忆 / 状态机 / 计数器 |
| 主要踩坑 | last 的位置精度 / 状态机更新顺序 / 双结构同步 / long long |
| 核心教训 | **子串 vs 子序列是质变；先掌握统一框架再区分状态设计** |

### 下次遇到滑动窗口题的判断流程

1. **是「数子串」还是「求最长」**？→ 数子串用右端贡献法
2. **限制对象是什么**？
   - 特定序列 → 子串（位置记忆）或子序列（状态机）
   - 集合大小 / 频次 → 计数器
   - 元素和 / 乘积 → 求和型
3. **状态变量需要几个**？→ 模式串长度 / 约束维度
4. **l 怎么收缩**？→ 单调不减，while 总次数 ≤ n
5. **答案会不会溢出**？→ `n²` 量级必用 `long long`

记住这个判断流程，遇到「数合法子串」类题目，第一反应就是右端贡献法 + 状态设计分类。
