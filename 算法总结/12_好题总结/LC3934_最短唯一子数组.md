# LC3934 最短唯一子数组

> **好题总结条目**｜标签：二分答案 / 单调性 / 滚动哈希 / 双哈希 / 子数组
> **难度**：中等偏难 ｜ **核心结论**：若某个长度存在唯一子数组，则所有更长长度也都存在唯一子数组

---

## 一、一句话解法与题目模型

二分答案长度 `len`，每次检查长度为 `len` 的全部子数组中，是否有某个序列只出现一次。

检查时使用前缀哈希：

```text
长度为 len 的子数组数量 = n - len + 1
```

如果某个哈希值出现次数恰好为 `1`，该长度就可行。利用“唯一性随长度增加而保持”的单调性，可以二分求出最小长度。

总复杂度为期望：

```text
O(n log n) 时间，O(n) 空间
```

---

## 二、为什么可以二分：唯一性单调

定义谓词：

```text
can(len) = 是否存在一个长度为 len、只出现一次的子数组
```

### 2.1 单调性证明

假设 `can(len) == true`，取一个长度为 `len` 的唯一子数组：

```text
S = nums[l..r]
```

对于任意更大的长度 `len2 > len`，都可以从 `S` 出发，在数组范围内不断向左右扩展，得到某个包含 `S` 的长度 `len2` 子数组 `T`。

如果 `T` 在别的位置再次出现，那么取它在相同偏移处包含的长度 `len` 片段，就会得到 `S` 的第二次出现，与 `S` 唯一矛盾。

因此：

```text
can(len) == true
⇒ can(len + 1), can(len + 2), ..., can(n) 全为 true
```

谓词形状为：

```text
false, false, ..., false, true, true, ..., true
```

所以可以二分第一个 `true`。

### 2.2 长度 n 必然可行

长度为 `n` 的子数组只有一个：

```text
nums[0..n-1]
```

它不可能与其他同长度子数组相同，所以 `can(n) == true` 恒成立，答案一定存在。

## 三、第一次提交为什么不通过

原代码二分范围是：

```cpp
for (int l = 0, r = n - 1; l <= r;) {
    int m = l + (r - l) / 2;
    if (f(sh, n, m)) {
        ...
    }
}
```

当 `m == 0` 时调用：

```cpp
f(sh, n, 0)
```

但 `f` 没有检查 `len <= 0`，于是进入：

```cpp
for (int l = 0, r = len - 1; r < n; r++, l++)
```

此时 `r = -1`，而 `-1 < n` 成立，循环会错误执行，并调用：

```cpp
sh.getHash(l, -1)
```

随后访问 `hash[-1]`，发生越界和未定义行为。最小测试 `nums = [1]` 时，第一次二分就取到 `m = 0`，最容易暴露。

根本原因有两层：

1. **搜索域错误**：子数组最小长度是 `1`，二分下界不应取 `0`；
2. **辅助函数缺少防御**：即使外部调用者非法传入 `len <= 0`，也应立即返回 `false`。

正确代码同时做了：

```cpp
if (len <= 0) return false;
```

以及：

```cpp
for (int left = 1, right = n; left <= right;) { ... }
```

两者共同保证不会构造长度为 `0` 的子数组。

## 四、前缀哈希如何表示子数组

把数组看作“字符依次为 `nums[i]` 的字符串”，使用多项式哈希。

定义：

```text
H[i] = nums[0] * B^i + nums[1] * B^(i-1) + ... + nums[i]
```

等价递推：

```text
H[i] = H[i-1] * B + nums[i]
```

`pow[k] = B^k`。

对于子数组 `nums[l..r]`，长度为：

```text
len = r - l + 1
```

哈希为：

```text
getHash(l, r) = H[r] - H[l-1] * B^len
```

其中 `l == 0` 时没有前缀需要减去。

代码使用 `unsigned long long`，算术溢出等价于对 `2^64` 取模，是无符号整数中定义良好的行为。

## 五、正确代码：单哈希 + 二分

```cpp
class Solution {
public:
    using ull = unsigned long long;

    class StringHash {
        static constexpr ull BASE = 499;

    public:
        explicit StringHash(const vector<int>& nums) {
            int n = static_cast<int>(nums.size());
            power.assign(n, 0);
            prefix.assign(n, 0);

            power[0] = 1;
            for (int i = 1; i < n; ++i) {
                power[i] = power[i - 1] * BASE;
            }

            prefix[0] = static_cast<ull>(nums[0]);
            for (int i = 1; i < n; ++i) {
                prefix[i] = prefix[i - 1] * BASE
                          + static_cast<ull>(nums[i]);
            }
        }

        ull getHash(int left, int right) const {
            ull result = prefix[right];
            if (left > 0) {
                int length = right - left + 1;
                result -= prefix[left - 1] * power[length];
            }
            return result;
        }

    private:
        vector<ull> power;
        vector<ull> prefix;
    };

    bool can(StringHash& hasher, int n, int length) const {
        if (length <= 0 || length > n) {
            return false;
        }

        unordered_map<ull, int> frequency;
        frequency.reserve(n - length + 1);

        for (int left = 0, right = length - 1;
             right < n;
             ++left, ++right) {
            ++frequency[hasher.getHash(left, right)];
        }

        for (const auto& [value, times] : frequency) {
            if (times == 1) {
                return true;
            }
        }
        return false;
    }

    int smallestUniqueSubarray(vector<int>& nums) {
        int n = static_cast<int>(nums.size());
        StringHash hasher(nums);

        int answer = n;
        int left = 1;
        int right = n;

        while (left <= right) {
            int middle = left + (right - left) / 2;
            if (can(hasher, n, middle)) {
                answer = middle;
                right = middle - 1;
            } else {
                left = middle + 1;
            }
        }
        return answer;
    }
};
```

也可以像原代码一样搜索 `[1, n - 1]` 并令初始 `answer = n`，因为长度 `n` 必然可行。

## 六、手算示例

### 6.1 `nums = [1, 1, 1]`

长度 `1`：

```text
[1] 出现 3 次，没有唯一子数组
```

长度 `2`：

```text
[1,1]、[1,1]，各出现 2 次
```

长度 `3`：

```text
[1,1,1] 只出现 1 次
```

答案为 `3`。

### 6.2 `nums = [1, 1, 2, 2]`

长度 `1`：

```text
1 出现 2 次，2 出现 2 次
```

长度 `2`：

```text
[1,1] 出现 1 次
[1,2] 出现 1 次
[2,2] 出现 1 次
```

已经存在唯一子数组，答案为 `2`。

### 6.3 `nums = [1, 2, 1, 2]`

长度 `1`：两种值都出现两次。

长度 `2`：

```text
[1,2] 出现 2 次
[2,1] 出现 1 次
[1,2] 出现 2 次
```

由于 `[2,1]` 唯一，答案为 `2`。

这也体现了唯一性判断必须按“定长窗口”计数，不能只看单个值是否重复。

## 七、双哈希解法

### 7.1 为什么需要双哈希

单哈希把任意长子数组压缩成一个 64 位整数，原理上必然存在不同序列得到同一结果的可能。

一次碰撞就足以让程序把两个不同子数组误认为相同，从而错误判断“唯一性”。双哈希使用两套独立基数和前缀表，把：

```text
hash(subarray)
```

变成：

```text
(hash1(subarray), hash2(subarray))
```

只有两个分量都相同才认为可能相同，碰撞概率显著降低。

严格地说，双哈希仍是概率算法，不是数学上绝对无误。

### 7.2 双哈希完整实现

```cpp
class Solution {
public:
    using ull = unsigned long long;

    class StringHash {
        static constexpr ull BASE1 = 499;
        static constexpr ull BASE2 = 547;

    public:
        explicit StringHash(const vector<int>& nums) {
            int n = static_cast<int>(nums.size());
            power1.assign(n, 0);
            power2.assign(n, 0);
            prefix1.assign(n, 0);
            prefix2.assign(n, 0);

            power1[0] = power2[0] = 1;
            for (int i = 1; i < n; ++i) {
                power1[i] = power1[i - 1] * BASE1;
                power2[i] = power2[i - 1] * BASE2;
            }

            prefix1[0] = prefix2[0] = static_cast<ull>(nums[0]);
            for (int i = 1; i < n; ++i) {
                ull value = static_cast<ull>(nums[i]);
                prefix1[i] = prefix1[i - 1] * BASE1 + value;
                prefix2[i] = prefix2[i - 1] * BASE2 + value;
            }
        }

        pair<ull, ull> getHash(int left, int right) const {
            ull h1 = prefix1[right];
            ull h2 = prefix2[right];
            if (left > 0) {
                int length = right - left + 1;
                h1 -= prefix1[left - 1] * power1[length];
                h2 -= prefix2[left - 1] * power2[length];
            }
            return {h1, h2};
        }

    private:
        vector<ull> power1, power2;
        vector<ull> prefix1, prefix2;
    };

    struct PairHash {
        size_t operator()(const pair<ull, ull>& value) const {
            ull first = value.first;
            ull second = value.second;
            return static_cast<size_t>(
                first ^ (second + 0x9e3779b97f4a7c15ULL
                         + (first << 6) + (first >> 2))
            );
        }
    };

    bool can(StringHash& hasher, int n, int length) const {
        if (length <= 0 || length > n) {
            return false;
        }

        unordered_map<pair<ull, ull>, int, PairHash> frequency;
        frequency.reserve(n - length + 1);

        for (int left = 0, right = length - 1;
             right < n;
             ++left, ++right) {
            ++frequency[hasher.getHash(left, right)];
        }

        for (const auto& [value, times] : frequency) {
            if (times == 1) {
                return true;
            }
        }
        return false;
    }

    int smallestUniqueSubarray(vector<int>& nums) {
        int n = static_cast<int>(nums.size());
        StringHash hasher(nums);

        int answer = n;
        int left = 1;
        int right = n;

        while (left <= right) {
            int middle = left + (right - left) / 2;
            if (can(hasher, n, middle)) {
                answer = middle;
                right = middle - 1;
            } else {
                left = middle + 1;
            }
        }
        return answer;
    }
};
```

### 7.3 `PairHash` 的职责

`PairHash` 只负责把一个二元哈希映射到哈希桶。`unordered_map` 在桶内还会用 `operator==` 比较完整的 `pair<ull, ull>`，因此：

```text
PairHash 发生桶碰撞
```

通常只会造成性能下降，不会直接把两个不同 pair 当作相等。

真正影响正确性的，仍然是对子数组本身计算出的双哈希 pair 是否碰撞。

## 八、避免哈希碰撞的确定性方案

如果要求数学上绝对正确，可以使用后缀数组加 LCP。

### 8.1 核心结论

对每个后缀起点 `i`，只保留它与所有其他后缀的最长公共前缀长度：

```text
common(i) = max LCP(suffix(i), suffix(j)), j != i
```

那么从 `i` 开始、第一次变得唯一的子数组长度为：

```text
common(i) + 1
```

原因：

- 长度不超过 `common(i)` 的前缀，至少会在另一个后缀中再出现一次；
- 长度等于 `common(i) + 1` 的前缀，已经不可能与其他后缀共享。

若 `common(i) + 1 > n - i`，说明从 `i` 开始的后缀长度不够，不存在唯一前缀。

最终答案为所有可行候选中：

```text
min(common(i) + 1)
```

### 8.2 如何快速求 `common(i)`

在后缀排序中，某个后缀与其他任意后缀的最长公共前缀，最大值一定来自它在字典序中的相邻后缀。

设：

```text
rank[i] = suffix(i) 在后缀数组中的排名
LCP[k]  = suffix(sa[k-1]) 与 suffix(sa[k]) 的 LCP
```

则：

```text
common(i)
= max(
      LCP[rank[i]],
      LCP[rank[i] + 1]
  )
```

越界的一侧视为 `0`。

### 8.3 算法流程

```text
1. 对 nums 做离散化，不改变任意两个元素是否相等；
2. 倍增法构造后缀数组；
3. 用 Kasai 算法求相邻后缀的 LCP；
4. 对每个后缀计算 common(i)；
5. 若 common(i) + 1 <= n - i，用它更新答案。
```

复杂度：

```text
后缀数组 O(n log n) + LCP O(n)
总时间 O(n log n)，空间 O(n)
```

没有二分答案，也没有碰撞概率。

## 九、正确性证明

### 9.1 `can(length)` 判定正确

长度为 `length` 的子数组共有 `n - length + 1` 个。哈希表记录了每个子数组序列对应的出现次数。

若某个哈希计数等于 `1`，则存在一个只出现一次的子数组；若没有计数等于 `1`，则所有子数组都至少出现两次。

这是“存在唯一子数组”的充要条件。

### 9.2 二分不会跳过答案

前文已证明谓词单调。二分不断保留仍然可能有更短答案的一侧：

- `can(middle)` 为真：记录答案，继续向左；
- `can(middle)` 为假：较短长度不可行，向右。

因此最终记录的是最小可行长度。

### 9.3 起点与结束边界正确

二分搜索范围至少包含 `length = 1` 和 `length = n`：

- 非空子数组最小长度为 `1`；
- 数组整体长度为 `n`，且必然唯一。

辅助函数拒绝 `length <= 0` 与 `length > n`，避免非法窗口。

## 十、复杂度分析

单哈希与双哈希：

| 步骤 | 复杂度 |
|---|---|
| 预处理前缀哈希 | `O(n)` |
| 单次 `can(length)` | 期望 `O(n)` |
| 二分次数 | `O(log n)` |
| 总时间 | 期望 `O(n log n)` |
| 空间 | `O(n)` |

`unordered_map` 使用平均值 `O(1)`，所以总复杂度是期望复杂度。若要求严格最坏情况保证，应使用后缀数组方案。

## 十一、易错点

### 坑 1：把二分下界写成 0

子数组最小长度是 `1`。写 `0` 可能让 `f` 构造 `[0, -1]` 的非法区间，访问 `hash[-1]`。

### 坑 2：辅助函数不检查非法长度

即使二分范围固定为 `[1, n]`，`can` 也应对 `length <= 0` 和 `length > n` 返回 `false`。边界防御应放在真正访问数组的位置。

### 坑 3：错误理解二分单调性

这里有单调性，但不是“子数组越长越容易重复”，而是：

```text
短长度存在唯一子数组
⇒ 所有更长长度也存在唯一子数组
```

原因是任何更长唯一子数组都包含那个短的唯一片段，而不是它自己更长。

### 坑 4：把所有哈希放进集合就判断唯一

仅把所有哈希放入 `unordered_set` 只能得到“不同哈希值数量”，不能直接判断某个哈希是否出现一次。

必须统计频率，或者同时维护集合与重复集合。

### 坑 5：单哈希结果没有碰撞风险

64 位溢出哈希依然可能碰撞。`nums` 足够特殊时，单哈希不是严格意义上的确定性正确算法。

双哈希降低碰撞概率，后缀数组则可完全消除该风险。

### 坑 6：双哈希的 `pair` 不能直接安全地用于普通 `unordered_map`

标准库没有默认的 `pair` 哈希。需要自定义 `PairHash`，否则会编译失败。

自定义哈希发生桶碰撞不等于 pair 相等；容器仍会比较两个 `ull` 分量。

### 坑 7：取子数组哈希时使用的幂次错误

长度必须写成：

```text
r - l + 1
```

不是 `r - l`。少一位会把左端最高位错误保留下来。

### 坑 8：`n - len + 1` 窗口数计算错误

长度为 `len` 的窗口数量恰好是：

```text
n - len + 1
```

例如 `n = 4, len = 3` 时有两个窗口。

### 坑 9：全相同数组容易漏测

```text
[1, 1, ..., 1]
```

任何长度小于 `n` 的子数组都会重复，答案必为 `n`。它很适合验证二分右边界和长度 `n` 的可行性。

### 坑 10：把“值唯一”误当成“子数组唯一”

值唯一不代表定长子数组唯一，反之亦然。

例如 `[1, 2, 1, 2]` 中所有单元素都不唯一，但长度为 `2` 的 `[2, 1]` 唯一。

## 十二、三种方案对比

| 方案 | 时间 | 空间 | 正确性 |
|---|---|---|---|
| 单 64 位哈希 + 二分 | 期望 `O(n log n)` | `O(n)` | 有碰撞概率 |
| 双 64 位哈希 + 二分 | 期望 `O(n log n)` | `O(n)` | 碰撞概率极低，但仍非绝对 |
| 后缀数组 + LCP | `O(n log n)` | `O(n)` | 确定性正确 |

面试中：

- 先给出二分 + 双哈希，最符合题目时间要求且代码直接；
- 如果面试官追问碰撞，补上后缀数组与 LCP 的思路；
- 如果只写单哈希，应主动说明其概率性质。

## 十三、闭卷自测

### 13.1 固定用例

| 输入 | 输出 | 原因 |
|---|---:|---|
| `[1]` | 1 | 唯一子数组只有整体 |
| `[1,1]` | 2 | 单元素重复，整体唯一 |
| `[1,1,1]` | 3 | 长度 1、2 都重复 |
| `[1,1,2,2]` | 2 | `[1,1]`、`[2,2]` 唯一 |
| `[1,2,1,2]` | 2 | `[2,1]` 唯一 |
| `[1,2,3,1]` | 1 | 值 2 或 3 只出现一次 |
| `[2,2,2,2]` | 4 | 只有长度 4 唯一 |
| `[1,1,2,1,1]` | 1 | 值 2 唯一 |

### 13.2 建议随机测试

随机生成小数组，使用三层暴力：

```text
枚举长度
→ 枚举第一个窗口
→ 枚举第二个窗口并逐元素比较
```

把暴力答案与哈希二分结果比较，适合捕获：

- 二分边界错误；
- 窗口哈希区间错误；
- 唯一性计数错误；
- 全相同或高重复数组问题。

## 十四、面试追问

### 14.1 为什么不是对所有子数组直接去重？

因为子数组有 `O(n²)` 个。二分只用处理 `O(log n)` 个长度，每个长度有 `O(n)` 个窗口，因此降到期望 `O(n log n)`。

### 14.2 能否不用二分

可以。后缀数组 + LCP 直接对每个起点求“第一次变得唯一”的长度，最后取最小值。

### 14.3 能否用后缀自动机

可以。后缀自动机可以描述子串及其出现次数，但本题用哈希二分或后缀数组更直接。

### 14.4 如果要求返回具体子数组

可行。记录当前长度中首次遇到计数为 `1` 的哈希及其窗口左端点，二分得到最优长度后再取出该窗口。

双哈希碰撞只会影响这种恢复，和长度判断一起承担风险。

| 单调性 | 短唯一片段扩展成长片段后仍然唯一 |
| 核心数据结构 | 前缀哈希 + 频次表 |
| 搜索方式 | 二分最小可行长度 |
| 主要边界 | 长度从 1 开始，长度 n 必然可行 |
| 首次失败根因 | `len = 0` 进入哈希循环，访问 `hash[-1]` |
| 工程改进 | 双哈希降低碰撞，后缀数组彻底消除碰撞 |
| 时间复杂度 | 期望 `O(n log n)` |
| 空间复杂度 | `O(n)` |

### 一句话口诀

> **唯一长度可二分，定长窗口统计频次；哈希记住从 1 开始，双哈希保稳，后缀数组保绝对正确。**
