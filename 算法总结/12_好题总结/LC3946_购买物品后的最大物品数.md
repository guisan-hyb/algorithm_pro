# LC3946 购买物品后的最大物品数

> **好题总结条目**｜标签：动态规划 / 预算背包 / 首次购买奖励 / 状态机
> **难度**：中等偏难 ｜ **核心结论**：每种物品的第一件与后续件收益不同，用两个状态拆开即可

---

## 一、一句话解法与题目模型

对于购买物品 `i`：

```text
买第 1 件：获得 1 件购买物品 + freeArr[i] 件免费物品
之后每多买 1 件：只额外获得 1 件购买物品
```

因此如果一共购买 `pick >= 1` 件物品 `i`，总收益为：

```text
pick + freeArr[i]
```

AC 代码用两个递归状态处理每种物品：

```text
dfs(i,b)  ：处理物品 i，预算 b，且尚未买过物品 i
dfs2(i,b) ：处理物品 i，预算 b，且已经买过至少一件物品 i
```

首次购买使用带 `freeArr[i]` 的转移；重复购买只增加 `1`。每个状态转移为 `O(1)`，所以主 DP 是 `O(n × budget)`。

## 二、先把“免费物品”拆成独立收益

### 2.1 `freeArr[i]` 的定义

```cpp
freeArr[i]
= 满足 j != i 且 items[j][0] % items[i][0] == 0 的物品数量
```

只要购买至少一件物品 `i`，这些物品中的每一个都会免费获得一份。

### 2.2 为什么免费数量可以提前算

免费规则只和 `factor_i` 与 `factor_j` 的整除关系有关，与预算、购买数量以及购买顺序都无关。

所以：

```text
第一次购买物品 i 的固定奖励 = freeArr[i]
```

可以先花 `O(n²)` 预处理，后面 DP 不再反复扫描所有物品。

### 2.3 重复购买不再增加免费物品

购买 `pick` 件物品 `i`：

```text
购买得到 pick 件
第一次购买触发一次免费奖励 freeArr[i]
重复购买不会再次触发
```

总收益：

```text
pick + freeArr[i]
```

### 2.4 同一件物品可以被不同购买种类重复免费获得

例如：

```text
购买物品 i 可以免费得到物品 j
购买物品 k 也可以免费得到物品 j
```

那么物品 `j` 会得到两份免费物品。题目明确允许这种情况，所以每种购买种类的免费收益可以直接相加，不需要在 `freeArr` 之间去重。

### 2.5 相同 factor 的不同物品仍然分别计数

判断条件是：

```text
items[j][0] % items[i][0] == 0
j != i
```

即使 `factor_i == factor_j`，两者也是不同下标的物品，因此会互相提供一份免费物品。`freeArr` 按物品下标计数是正确的。

## 三、尝试一：枚举购买数量 + 现场计算免费数，超时

第一次递归的状态是：

```text
f(i, budget)
= 考虑从物品 i 开始，剩余预算 budget 时的最大物品数
```

状态转移：

```text
不买物品 i：f(i + 1, budget)

购买 pick 件物品 i：
free(i) + pick + f(i + 1, budget - pick * price_i)
```

原代码的主循环：

```cpp
for(int pick = 1; pick <= group; pick++) {
    ans = max(ans,
        free + pick +
        f(items, budget - pick * items[i][1], i + 1, dp)
    );
}
```

### 3.1 超时原因一：每个状态枚举所有购买数量

状态总数是：

```text
O(n × budget)
```

单个状态最多枚举：

```text
budget / price_i 种 pick
```

总复杂度数量级为：

```text
O(n × budget²)
```

如果预算较大，这个枚举量无法承受。

### 3.2 超时原因二：免费数量在 DP 状态里重复计算

原代码在每次进入状态时都执行：

```cpp
for(int j = 0; j < items.size(); j++) {
    if(j == i) continue;
    if(items[j][0] % items[i][0] == 0) free++;
}
```

同一物品的免费数量与预算无关，却被重复计算了大量次数，又额外增加一层 `O(n)`。

### 3.3 记忆化没有解决枚举成本

`dp[i][budget]` 能避免同一个状态重复进入，但第一次真正计算它时，仍然要枚举所有可能的 `pick`。所以记忆化只消除了重复调用，没有改变大循环。

---

## 四、尝试二：预处理 `freeArr`，仍然超时

第二次把免费数量预处理掉：

```cpp
vector<int> free(n, 0);
for(int i = 0; i < n; i++) {
    for(int j = 0; j < n; j++) {
        if(i != j && items[j][0] % items[i][0] == 0) {
            free[i]++;
        }
    }
}
```

这一优化正确，也把“免费数量”的重复计算消除了，但核心循环仍然存在：

```cpp
for(int pick = 1; pick <= group; pick++) {
    ans = max(ans,
        free[i] + pick +
        f(items, budget-pick*items[i][1], i+1, dp, free)
    );
}
```

所以主 DP 仍然是：

```text
O(n × budget²)
```

预处理只省掉了额外一层 `O(n)`，没有解决“一个状态枚举大量购买数量”的主要瓶颈。

## 五、AC 思路：首次购买与重复购买拆成两个状态

### 5.1 `dfs`：尚未买过物品 i

三种行为中实际只有两种：

```text
1. 跳过物品 i：
   dfs(i + 1, budget)

2. 买第一件物品 i：
   1 + freeArr[i] + dfs2(i, budget - price_i)
```

买第一件后不能直接跳到 `i + 1`，因为还可以继续购买同一物品。因此进入 `dfs2(i, budget - price_i)`。

### 5.2 `dfs2`：已经买过物品 i

已有第一件的购买收益和免费奖励都计入过了，现在有两种选择：

```text
1. 停止购买物品 i：
   dfs(i + 1, budget)

2. 再买一件物品 i：
   1 + dfs2(i, budget - price_i)
```

这里再加的价格不能包含 `freeArr[i]`，因为重复购买不会触发新的免费物品。

### 5.3 为什么只需要两个状态

同一种物品只有两类身份：

```text
从没买过 → 下一次购买可以拿首次奖励
已经买过 → 下一次购买只能拿普通的一件
```

买了多少件不需要单独记录，因为每多买一件的收益固定为 `1`，预算会自动限制购买次数。

## 六、AC 代码

```cpp
class Solution {
public:
    int maximumSaleItems(vector<vector<int>>& items, int budget) {
        int n = items.size();
        vector<int> freeArr(n, 0);
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++) {
                if (i != j && items[j][0] % items[i][0] == 0) freeArr[i]++;
            }
        }

        // dp[i][b]: 处理到物品 i，预算为 b，且尚未买过物品 i 时的最大总数
        vector<vector<int>> dp(n + 1, vector<int>(budget + 1, -1));
        // dp2[i][b]: 处理到物品 i，预算为 b，且已经买过物品 i 时的最大总数
        vector<vector<int>> dp2(n + 1, vector<int>(budget + 1, -1));

        function<int(int, int)> dfs;
        function<int(int, int)> dfs2;

        // dfs: 尚未买过物品 i
        dfs = [&](int i, int b) -> int {
            if (i == n) return 0;
            if (dp[i][b] != -1) return dp[i][b];

            int p = items[i][1];
            int ans = dfs(i + 1, b); // 情况1：跳过，不买物品 i

            if (b >= p) {
                // 情况2：买第一件物品 i，获得 1 + freeArr[i]，并进入“已买过”状态
                ans = max(ans, 1 + freeArr[i] + dfs2(i, b - p));
            }
            return dp[i][b] = ans;
        };

        // dfs2: 已经买过至少一件物品 i
        dfs2 = [&](int i, int b) -> int {
            if (i == n) return 0;
            if (dp2[i][b] != -1) return dp2[i][b];

            int p = items[i][1];
            // 情况1：停止购买物品 i，直接去看下一个物品
            int ans = dfs(i + 1, b);

            if (b >= p) {
                // 情况2：再买一件物品 i，只获得 +1（无免费奖励）
                ans = max(ans, 1 + dfs2(i, b - p));
            }
            return dp2[i][b] = ans;
        };

        return dfs(0, budget);
    }
};
```

这段代码保留了原来的变量名、递归结构和注释方式，核心是把“枚举所有购买数量”替换成了两个 `O(1)` 转移。

## 七、手算示例

### 7.1 输入

```text
items = [[2,1], [2,1], [4,1]]
budget = 2
```

计算 `freeArr`：

| 购买种类 | factor | 能整除的其他物品下标 | `freeArr` |
|---|---:|---|---:|
| 0 | 2 | 1、2 | 2 |
| 1 | 2 | 0、2 | 2 |
| 2 | 4 | 无 | 0 |

所以：

```text
购买第一件 0 或 1：获得 1 + 2 = 3 件
购买第一件 2：获得 1 + 0 = 1 件
```

### 7.2 最优选择

预算为 `2`，可以分别购买一件物品 `0` 和一件物品 `1`：

```text
购买物品 0：1 件购买 + 免费物品 1、2
购买物品 1：1 件购买 + 免费物品 0、2
```

总共：

```text
2 件购买 + 4 件免费 = 6
```

物品 `2` 被两个不同购买种类各免费赠送一次，这正是题目允许的重复免费。

递归中的一条最优路径：

```text
dfs(0,2)
→ 买第一件物品 0：+3，剩余 1
→ dfs2(0,1)
→ 停止购买物品 0：dfs(1,1)
→ 买第一件物品 1：+3，剩余 0
→ dfs2(1,0)
→ 停止并处理物品 2：预算为 0，不再购买
```

答案为 `6`。

### 7.3 只有一种物品

```text
items = [[1,2]]
budget = 5
```

没有其他物品可以免费获得，`freeArr[0] = 0`。

每买一件增加 `1`，预算最多买两件：

```text
5 / 2 = 2
answer = 2
```

剩余预算 `1` 不需要强制花完。

## 八、正确性证明

### 8.1 `freeArr` 正确

购买任一正数量的物品 `i` 后，每个满足 `j != i` 且 `factor_i` 整除 `factor_j` 的物品 `j` 都会免费获得一次。

`freeArr[i]` 恰好枚举了这些下标，因此第一次购买物品 `i` 的免费收益正确。

不同购买种类产生的免费物品允许重复，因此不同 `freeArr` 直接相加也正确。

### 8.2 `dfs` 穷尽“尚未购买”的全部选择

尚未购买物品 `i` 时：

- 不购买它，后续从 `i + 1` 开始；
- 购买第一件后，至少已经买过一件，后续必须进入已购买状态。

所有方案要么属于前者，要么属于后者，没有第三种情况。首次收益中包含 `freeArr[i]`，且只会加一次。

### 8.3 `dfs2` 正确计算重复购买

已经购买过物品 `i` 后：

- 停止购买它，转入下一个物品；
- 再买一件只额外增加 `1`，继续留在已购买状态。

重复购买的转移中没有再加 `freeArr[i]`，符合“重复购买不能获取额外免费物品”的规则。

### 8.4 对物品下标归纳

从最后一个物品开始看，`i == n` 时没有物品，收益为 `0`。

假设物品 `i + 1` 之后的两种状态都正确。对物品 `i` 的分类讨论覆盖跳过、首次购买和重复购买，因此 `dfs(i,b)` 与 `dfs2(i,b)` 也正确。

归纳到 `dfs(0,budget)`，得到全局最优答案。

### 8.5 预算不要求花完

每条转移都允许直接跳过当前物品，或以 `b == 0` 继续处理后续物品，因此“剩余预算不使用”被自然包含在状态中。

## 九、复杂度分析

### 9.1 免费数量预处理

```text
O(n²)
```

### 9.2 主 DP

状态数：

```text
2 × (n + 1) × (budget + 1)
```

每个状态最多执行两条 `O(1)` 转移，因此：

```text
时间复杂度 = O(n × budget + n²)
空间复杂度 = O(n × budget)
```

递归栈深度最坏为：

```text
O(n + budget / minPrice)
```

其中 `budget / minPrice` 来自对同一最低价物品反复购买。

### 9.3 与超时版本对比

| 版本 | 免费数量预处理 | 单状态转移 | 总时间 |
|---|---|---|---|
| 尝试一 | 无 | 扫描物品 + 枚举购买数量 | 至少 `O(nB² + n²B)` |
| 尝试二 | `O(n²)` | 枚举购买数量 | `O(nB² + n²)` |
| AC | `O(n²)` | `O(1)` | `O(nB + n²)` |

`B = budget`。

## 十、去掉递归栈的迭代写法

AC 思路可以改写成反向迭代。代码继续使用 `freeArr`、`bought`、`notBought` 等原命名风格：

```cpp
class Solution {
public:
    int maximumSaleItems(vector<vector<int>>& items, int budget) {
        int n = items.size();
        vector<int> freeArr(n, 0);
        for (int i = 0; i < n; i++) {
            for (int j = 0; j < n; j++) {
                if (i != j && items[j][0] % items[i][0] == 0) freeArr[i]++;
            }
        }

        // nextState[b] = 处理物品 i+1 到 n-1 时的最大收益
        vector<int> nextState(budget + 1, 0);

        for (int i = n - 1; i >= 0; i--) {
            int p = items[i][1];

            // bought[b] = 已经买过物品 i，剩余预算 b 时的最大收益
            vector<int> bought = nextState;
            // notBought[b] = 尚未买过物品 i，剩余预算 b 时的最大收益
            vector<int> notBought = nextState;

            for (int b = p; b <= budget; b++) {
                // 再买一件物品 i，只增加 1
                bought[b] = max(bought[b], bought[b - p] + 1);

                // 买第一件物品 i，增加 1 + freeArr[i]
                notBought[b] = max(
                    notBought[b],
                    1 + freeArr[i] + bought[b - p]
                );
            }

            nextState.swap(notBought);
        }

        return nextState[budget];
    }
};
```

这个版本保持：

```text
时间 O(nB + n²)
空间 O(B)
```

并且不再依赖递归调用栈。

说明：

- `bought` 从 `nextState` 开始，表示“已经买过当前种类，但选择停止”，随后可继续购买当前种类；
- `notBought` 从 `nextState` 开始，表示完全跳过当前种类；
- 按 `b` 从小到大更新，使 `b - p` 处已经处理完更少预算的重复购买。

## 十一、易错点

### 坑 1：首次购买和重复购买加同样的收益

错误写法：

```cpp
ans = max(ans, 1 + freeArr[i] + dfs2(i, b - p));
```

第二次购买只能增加 `1`，不能再次加 `freeArr[i]`。

### 坑 2：把首次购买后的状态写回 `dfs`

买过第一件后再进入 `dfs(i, b - p)`，会再次获得免费奖励。

首次购买后必须进入 `dfs2`。

### 坑 3：首次购买后直接跳到 `i + 1`

买第一件以后仍然可以继续购买同一种物品，所以应先在 `dfs2` 中决定是否重复购买，停止时才转到下一个种类。

### 坑 4：把 `freeArr` 之间去重

题目明确允许同一个免费物品由不同购买种类重复赠送，所以不同 `freeArr` 的贡献可以直接相加。

### 坑 5：相同 factor 只算一次

物品按下标区分，`factor` 相同不代表是同一件物品。`j != i` 且整除成立时仍应计一次。

### 坑 6：认为预算必须刚好花完

题目只要求花费不超过预算。`dfs(i + 1, b)` 允许跳过剩余物品，`b == 0` 也允许直接返回后续最优值。

### 坑 7：忘记 `dfs2` 也要处理后续物品

`dfs2(i,b)` 的停止分支是：

```cpp
dfs(i + 1, b)
```

不是直接返回 `0`。当前种类停止后，后面的种类仍可购买。

### 坑 8：递归重复购买造成无限递归

每次重复购买都从 `b` 转移到 `b - p`，而价格 `p > 0`，剩余预算严格减少，所以递归一定会终止。

### 坑 9：只看状态数，忽略原版本的购买数量枚举

`dp[i][b]` 确实只有 `O(nB)` 个，但原实现计算每个状态时还循环所有 `pick`，真实时间不是 `O(nB)`。

### 坑 10：忽略递归栈

AC 递归的语义正确，但链状递归深度可能达到 `n + budget / minPrice`。如果预算较大且最低价很小，建议改成第十节的迭代版本。

## 十三、面试追问

### 13.1 为什么不是普通 01 背包

每种物品不是只有“选或不选”：

```text
选择后还可以重复购买；
第一次选择和后续选择收益不同。
```

因此需要“未买过 / 已买过”两个状态。

### 13.2 能不能按每件物品展开成多重背包

可以，但把每种物品展开大量副本会带来高复杂度。AC 方法直接在两个状态间转移，天然处理无限件。

### 13.3 `freeArr` 能否继续优化

如果 `factor` 值域允许，可以统计每个 factor 的出现次数，再用倍数前缀和求出每种 factor 能整除多少个其他物品，将预处理从 `O(n²)` 降低到与值域相关。

当 `n` 较小时，直接双重循环最简单，也符合当前 AC 代码风格。

### 13.4 如果预算非常大

当前 DP 与预算线性相关，不适合 `budget` 达到很大数量级的情况。那类变体通常需要利用“每种物品额外收益固定为 1”的结构，结合性价比、排序或整数规划性质重新推导，不能直接套 `O(nB)`。

---

## 十四、最终复盘

| 维度 | 内容 |
|---|---|
| 固定奖励 | 第一次购买物品 `i` 获得 `1 + freeArr[i]` |
| 边际收益 | 之后每多买一件只增加 `1` |
| 核心状态 | 未买过当前种类 / 已买过当前种类 |
| 关键转移 | 首次购买后进入已购买态，不重复加免费奖励 |
| 超时根因 | 每个 DP 状态枚举所有购买数量 |
| AC 复杂度 | `O(nB + n²)` 时间，`O(nB)` 空间 |
| 迭代优化 | `O(nB + n²)` 时间，`O(B)` 空间，无递归栈 |
| 核心口诀 | **第一件领奖励，之后只加一；买过不回头，停止再下一类。** |
