# LC2747 统计没有收到请求的服务器数目

> **错题本条目**｜标签：滑动窗口 / 离线查询 / 计数数组维护区间内不同元素
> **难度**：中等 ｜ **首次提交结果**：RE → 修正后 AC

---

## 一、题目描述与考察知识点

### 1.1 题目描述

给你一个整数 `n`，表示服务器的总数目；再给你一个下标从 0 开始的二维整数数组 `logs`，其中 `logs[i] = [server_id, time]` 表示 id 为 `server_id` 的服务器在 `time` 时收到了一个请求。

同时给你一个整数 `x` 和一个下标从 0 开始的整数数组 `queries`。

请你返回一个长度等于 `queries.length` 的数组 `arr`，其中 `arr[i]` 表示在时间区间 `[queries[i] - x, queries[i]]` 内**没有收到请求**的服务器数目。

注意：时间区间是个**闭区间**。

### 1.2 示例

**示例 1**

```
输入：n = 3, logs = [[1,3],[2,6],[1,5]], x = 5, queries = [10,11]
输出：[1,2]
解释：
- queries[0] = 10，区间 [5,10]：
  - 服务器 1 在 t=3 和 t=5 收到请求（t=3 不在窗口内，t=5 在）
  - 服务器 2 在 t=6 收到请求
  - 服务器 0 没有收到任何请求 → 答案 = 1
- queries[1] = 11，区间 [6,11]：
  - 只有服务器 2 在 t=6 收到请求
  - 服务器 0、1 都没有收到请求 → 答案 = 2
```

### 1.3 数据范围

| 参数 | 范围 |
|---|---|
| `n` | `1 <= n <= 10^5` |
| `logs.length` | `1 <= L <= 10^5` |
| `server_id` | 标准约束 `0 <= server_id < n`（部分平台变体可能为 `1 <= server_id <= n`，详见踩坑记录）|
| `time` / `queries[i]` | `1 <= time, queries[i] <= 10^6` |
| `x` | `1 <= x <= 10^6` |
| `queries.length` | `1 <= Q <= 10^5` |

### 1.4 考察知识点

- **滑动窗口（双指针）**：利用单调性线性扫描
- **离线查询**：将 query 排序后批量处理
- **计数数组维护「区间内不同元素个数」**：通过 `cnt[s]` 是否归零判断去重
- **排序 + 单调性利用**：把看似不相关的多次查询转化为单次扫描

## 二、思路分析

### 2.1 朴素做法与瓶颈

最直接的想法：对每个 query，扫描一遍 `logs`，挑出时间在 `[q-x, q]` 内的所有 log，记录其中出现过的不同 `server_id`，答案是 `n - 不同 server_id 数`。

复杂度：`O(Q × L)`，Q 和 L 都到 `10^5`，最坏 `10^10`，**必超时**。

### 2.2 关键转化

> **「没有收到请求的服务器数」 = n − 「窗口内收到过请求的不同服务器数」**

设 `active` 表示窗口内「至少收到一次请求」的不同服务器数，答案就是 `n - active`。

这把问题从「数没有出现的」转化为「数出现过的不同元素」——后者有成熟的滑动窗口套路。

### 2.3 关键观察：查询排序后窗口单调

把所有 query 按值从小到大排序后处理。设当前 query 为 `q`，对应窗口 `[q-x, q]`：

- `q` 增大 → 窗口右端点 `q` **单调右移**
- `q` 增大 → 窗口左端点 `q-x` **也单调右移**

这意味着如果用两个指针 `left`、`right` 在按 `time` 排序后的 `logs` 上滑动：

- `right` 只往右走（纳入更多 log）
- `left` 也只往右走（剔除过期 log）

每个 log 最多被纳入一次、剔除一次，整个扫描是 `O(L + Q)` 的（不算排序）。

### 2.4 状态设计

维护两个量：

| 变量 | 含义 |
|---|---|
| `cnt[s]` | 服务器 `s` 当前在窗口内的请求条数 |
| `active` | 窗口内 `cnt > 0` 的服务器个数（即不同活跃服务器数）|

转移规则：

- **纳入一条 log**（服务器 `s`）：若 `cnt[s] == 0`，则 `active++`；然后 `cnt[s]++`
- **剔除一条 log**（服务器 `s`）：先 `cnt[s]--`；若 `cnt[s] == 0`，则 `active--`

通过「cnt 是否归零」来判断 `active` 的增减，自然处理了同一服务器多条 log 的去重——这是本题的核心技巧。

## 三、算法详解与手算示例

### 3.1 预处理

1. 将 `logs` 按 `time` 升序排序
2. 将 `queries` 带上原下标后按值升序排序（便于最后还原答案顺序）

### 3.2 双指针扫描流程

初始化 `left = right = 0`，`cnt` 数组全 0，`active = 0`。

对每个排序后的 query `(q, idx)`：

1. **扩张右端**：`while right < L && logs[right].time <= q`，纳入这条 log
2. **收缩左端**：`while left < right && logs[left].time < q - x`，剔除这条 log
3. 记录 `ans[idx] = n - active`

### 3.3 手算示例

输入：`n=3, logs=[[1,3],[2,6],[1,5]], x=5, queries=[10,11]`

排序后 `logs = [(1,3), (1,5), (2,6)]`（按 time）
排序后 `queries = [(10, 0), (11, 1)]`（带原下标）

| query | 窗口 | 纳入的 log | 剔除的 log | cnt 状态 | active | ans |
|---|---|---|---|---|---|---|
| 10 | [5,10] | (1,5), (2,6) | (1,3) | cnt[1]=1, cnt[2]=1 | 2 | 3-2 = **1** |
| 11 | [6,11] | （无） | (1,5) | cnt[2]=1 | 1 | 3-1 = **2** |

输出 `[1, 2]`。

### 3.4 状态转移细节剖析

以 query=10 为例，详细看 `active` 的变化：

```
初始: cnt = [0,0,0], active = 0, left = right = 0

[扩张右端] right=0, logs[0].time=3 <= 10 → 纳入 (1,3)
  s=1, cnt[1]==0 → active=1, cnt[1]=1, right=1

[扩张右端] right=1, logs[1].time=5 <= 10 → 纳入 (1,5)
  s=1, cnt[1]==1 → active 不变, cnt[1]=2, right=2

[扩张右端] right=2, logs[2].time=6 <= 10 → 纳入 (2,6)
  s=2, cnt[2]==0 → active=2, cnt[2]=1, right=3

[收缩左端] left=0, logs[0].time=3 < 5 → 剔除 (1,3)
  s=1, cnt[1]-- → cnt[1]=1, 未归零 → active 不变, left=1

[收缩左端] left=1, logs[1].time=5 < 5? 否 → 停止

最终: active=2, ans[0] = 3 - 2 = 1
```

注意 step 2：纳入 `(1,5)` 时 `cnt[1]` 已经是 1，所以 `active` 不变——这就是「去重」的核心机制，同一服务器多条 log 只算一次活跃。

## 四、代码实现（踩坑版 vs 修正版）

### 4.1 踩坑版（初次提交）

```cpp
class Solution {
public:
    vector<int> countServers(int n, vector<vector<int>>& logs, int x, vector<int>& queries) {
        int L = logs.size();
        int Q = queries.size();
        sort(logs.begin(),logs.end(),[this](const vector<int>& a, const vector<int>& b){
            return a[1]<b[1];                // ← [this] 多余捕获
        });

        vector<pair<int,int>> sorted_q(Q);
        for(int i = 0;i<Q;i++){
            sorted_q[i] = {queries[i],i};
        }
        sort(sorted_q.begin(),sorted_q.end());

        vector<int> ans(Q);
        vector<int> cnt(n,0);                // ← 开 n 个，遇到 server_id=n 时越界
        int active = 0;
        int left = 0, right = 0;
        for(auto&[q,idx]:sorted_q){
            int lo = q-x, hi = q;
            while(right<L&&logs[right][1]<=hi){
                int s = logs[right][0];
                if(cnt[s]++==0) ++active;   // 后置 ++
                ++right;
            }

            while(left<right&&logs[left][1]<lo){
                int s = logs[left][0];
                if(--cnt[s]==0) active--;   // 前置 --，风格不对称
                ++left;
            }

            ans[idx] = n - active;
        }

        return ans;
    }
};
```

**问题清单**：
- `[this]` 捕获多余（lambda 没用任何成员变量）
- `cnt` 开 n 个，遇到 `server_id = n` 时越界 RE
- `++`/`--` 表达式风格不对称（虽不影响正确性）

### 4.2 修正版（AC 版）

```cpp
class Solution {
public:
    vector<int> countServers(int n, vector<vector<int>>& logs, int x, vector<int>& queries) {
        int L = (int)logs.size();
        int Q = (int)queries.size();
        sort(logs.begin(), logs.end(),
             [](const vector<int>& a, const vector<int>& b) { return a[1] < b[1]; });

        vector<pair<int,int>> sorted_q(Q);
        for (int i = 0; i < Q; ++i) sorted_q[i] = {queries[i], i};
        sort(sorted_q.begin(), sorted_q.end());

        vector<int> ans(Q);
        vector<int> cnt(n + 1, 0);          // ← 关键修复：开 n+1 避免越界
        int active = 0, left = 0, right = 0;

        for (const auto& [q, idx] : sorted_q) {
            int lo = q - x, hi = q;
            while (right < L && logs[right][1] <= hi) {
                int s = logs[right][0];
                if (cnt[s]++ == 0) ++active;   // 先判再增
                ++right;
            }
            while (left < right && logs[left][1] < lo) {
                int s = logs[left][0];
                if (cnt[s]-- == 1) --active;   // 减之前是 1，减完归零
                ++left;
            }
            ans[idx] = n - active;
        }
        return ans;
    }
};
```

**修复要点**：
- lambda 改为 `[]` 空捕获
- `cnt` 改开 `n+1` 大小
- `++`/`--` 表达式风格统一为「先判后改」式，且 `--` 时判 `== 1`（减之前为 1，减完归零）

## 五、踩坑记录与复盘

### 坑 1：lambda 多余捕获 `[this]`

| 维度 | 内容 |
|---|---|
| **现象** | lambda 体里只用到了参数 `a`、`b`，没访问任何成员变量，却写了 `[this]` 捕获 |
| **影响** | 不影响功能（编译通过，结果正确），但会被严格编译选项 `-Wall` 警告「未使用的 capture」；阅读时让人误以为用到了成员，干扰理解 |
| **原因** | 从其他 lambda 写法套用时随手带的，没思考是否真用到 `this` |
| **修复** | 改成 `[]` 空捕获 |
| **教训** | 养成习惯——lambda 不用外部变量就写 `[]`，避免「拷贝代码留下的死捕获」 |

### 坑 2：`cnt` 数组开 n 还是 n+1（核心坑点）

| 维度 | 内容 |
|---|---|
| **现象** | 开 `cnt(n, 0)` 提交 RE，改成 `cnt(n+1, 0)` 后 AC |
| **最初判断** | 参考标准 LeetCode 2747 约束 `0 <= server_id < n`，认为 server_id 范围是 `[0, n-1]`，开 n 个足够 |
| **实际原因** | 当前题目的约束可能与标准版本不同，`server_id` 可能取到 `n`（即 1-indexed 或闭区间 `[0, n]`）。访问 `cnt[n]` 时越界导致 RE |
| **修复** | `cnt` 改开 `n+1` 大小 |
| **教训** | 1. **以实际运行结果为准**——RE 就是越界，越界就先扩大数组试试<br>2. 不同平台 / 不同题号的同一类题，约束细节可能不同<br>3. 不放心时直接开 `n+2` 留哨兵位，多几字节内存换省心<br>4. 排查思路：打印出错的 `server_id` 值，确认是否有 `= n` 的情况；或翻题目原文 Constraints 部分 |

### 坑 3：`++`/`--` 表达式风格不对称

| 维度 | 内容 |
|---|---|
| **现象** | 纳入时用 `if(cnt[s]++==0)`（后置 ++），剔除时用 `if(--cnt[s]==0)`（前置 --）。两段逻辑都对，但风格不对称 |
| **影响** | 不影响正确性，但增加阅读负担，复查时容易绕晕 |
| **修复** | 统一为「先判后改」式：纳入判 `==0`，剔除判 `==1`（减之前为 1，减完归零） |
| **教训** | 算法正确性不依赖风格，但对称写法便于复查，尤其在压力面试或 AC 后回头看时 |

### 通用教训小结

> 1. **数据范围类细节以实际跑为准**，不要轻信「我记得标准题是 XXX」
> 2. **RE 第一反应是数组越界**，先扩大数组再排查
> 3. **代码风格对称**比抠那一两行紧凑更重要
> 4. **lambda 捕获列表要精确**，没用到的变量不要捕获

## 六、复杂度分析

### 6.1 时间复杂度

| 步骤 | 复杂度 |
|---|---|
| 排序 `logs` | `O(L log L)` |
| 排序 `queries` | `O(Q log Q)` |
| 双指针扫描 | `O(L + Q)`，每个 log 最多进/出窗口各一次 |
| **总计** | **`O(L log L + Q log Q)`** |

数据规模 `10^5` 量级，`L log L ≈ 1.7×10^6` 次操作，远在时限内。

### 6.2 空间复杂度

| 部分 | 大小 |
|---|---|
| `cnt` 数组 | `O(n)` |
| `sorted_q` 数组 | `O(Q)` |
| `ans` 数组（输出） | `O(Q)`（不计入也可视为 `O(1)` 额外） |
| **总计** | **`O(n + Q)`** |

`n, Q` 都到 `10^5`，总内存约几 MB，完全可接受。

### 6.3 复杂度边界思考

- 若 `L` 极小而 `Q` 极大（如 `L=1, Q=10^5`）：双指针扫描退化为 `O(Q)`，瓶颈在排序 `queries`
- 若 `L` 极大而 `Q` 极小：瓶颈在排序 `logs`
- 若两者都极大：考虑用桶排序（如果 `time` 范围有限）替换比较排序，可降到 `O(L + Q + max_time)`

## 七、举一反三

### 7.1 套路提炼

本题核心套路：**「区间内不同元素计数」+「离线查询」+「滑动窗口」**

适用条件：
1. 多个查询，每个查询问某个区间内不同元素的个数（或导出量）
2. 查询可以离线（不要求实时回答）
3. 区间边界随查询值单调变化（排序后即可单调）

### 7.2 相似题目

| 题号 | 题名 | 套路关联 |
|---|---|---|
| LC2747 | 统计没有收到请求的服务器数目 | 滑动窗口 + 离线查询（本题） |
| LC1847 | 最近的房间 | 离线查询 + 排序 + 集合二分 |
| LC2080 | 区间内查询数字的频率 | 离线 + 滑动窗口 / 二分前缀和 |
| LC1851 | 包含每个查询的最小区间 | 离线 + 优先队列 |
| LC3169 | 无需上课的天数 | 区间合并 / 差分 |
| LC3413 | 收集连续 K 个糖果的最大币值 | 前缀和 + 滑动窗口 |
| LC1170 | 比较 0 和 1 出现次数的字符串 | 预处理 + 排序 + 双指针 |

### 7.3 拓展思考

- **如果 query 要在线回答**？滑动窗口失效，需要可持久化数据结构（主席树）或莫队算法
- **如果窗口大小 `x` 不固定**？双指针失效，需对每个 query 独立二分 + 数据结构查询
- **如果 query 数远大于 log 数**？注意常数优化，可能用差分 + 离散化更优
- **如果要求支持动态插入 log**？需要树状数组 / 线段树维护，本题套路不再适用

### 7.4 通用模板

```cpp
// 离线 + 滑动窗口通用模板
vector<int> offlineSlidingWindow(
    vector<vector<int>>& events,   // [key, ...] 按 key 排序
    vector<int>& queries,          // 查询数组
    int window_size                // 窗口大小
) {
    sort(events.begin(), events.end(),
         [](auto& a, auto& b) { return a[0] < b[0]; });

    vector<pair<int,int>> qs;
    for (int i = 0; i < (int)queries.size(); ++i)
        qs.push_back({queries[i], i});
    sort(qs.begin(), qs.end());

    vector<int> ans(queries.size());
    int left = 0, right = 0;
    // 维护状态：cnt 数组 / active 计数 / 其他...

    for (auto [q, idx] : qs) {
        int lo = q - window_size, hi = q;
        while (right < (int)events.size() && events[right][0] <= hi) {
            // 纳入 events[right]，更新状态
            ++right;
        }
        while (left < right && events[left][0] < lo) {
            // 剔除 events[left]，更新状态
            ++left;
        }
        ans[idx] = /* 根据状态计算答案 */;
    }
    return ans;
}
```

### 下次遇到类似题目的判断流程

1. **能不能离线？** → query 不需要实时回答 → 可以排序
2. **排序后窗口是否单调？** → 是 → 上滑动窗口
3. **维护什么状态？** → 区间内不同元素 → `cnt` + 归零判断
4. **数组开多大？** → **看题目约束，不放心就开 +1/+2**

记住这个判断流程，遇到「区间内不同元素计数」类题目，第一反应就是这套模板。
