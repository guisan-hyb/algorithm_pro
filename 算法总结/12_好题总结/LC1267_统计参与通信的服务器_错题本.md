# LC1267 统计参与通信的服务器

> **错题本条目**｜标签：连通分量 / 并查集 / DFS / BFS / 计数预处理
> **难度**：中等 ｜ **专题性质**：四法对比，重点辨析「同行同列连通」语义

---

## 一、题目描述与连通性语义辨析

### 1.1 题目描述

这里有一幅服务器分布图，服务器的位置标识在 `m * n` 的整数矩阵网格 `grid` 中：
- `1` 表示单元格上有服务器
- `0` 表示没有

**通信规则**：如果两台服务器位于**同一行**或者**同一列**，就认为它们之间可以进行通信。

请你统计并返回**能够与至少一台其他服务器进行通信**的服务器的数量。

### 1.2 数据范围

| 参数 | 范围 |
|---|---|
| `m == grid.length` | `1 <= m <= 250` |
| `n == grid[i].length` | `1 <= n <= 250` |
| `grid[i][j]` | `0` 或 `1` |

### 1.3 连通性语义辨析（核心）

这是本题最大的「陷阱」——连通性的定义**不同于普通网格题**。

| 连通性类型 | 定义 | 类比 |
|---|---|---|
| **普通网格连通**（如 LC200 岛屿） | 上下左右相邻的格子才连通 | 象棋里**兵**的走法 |
| **本题连通** | 同行或同列任意位置都连通 | 象棋里**车**的走法 |

**关键差异**：
- 普通网格题：每个格子最多 4 个邻居（上下左右），扫描邻居是 `O(1)`
- 本题：每个服务器的邻居是**整行 + 整列**的所有服务器，扫描邻居是 `O(m + n)`

**这种语义差异直接决定算法选择**：
- DFS/BFS 仍可用，但找邻居时必须**整行整列扫描**，不能用 4 方向循环
- 计数预处理法之所以成立，正是因为「同行同列连通」等价于「所在行或所在列的服务器数 > 1」
- 并查集必须按行连接 + 按列连接两趟扫描，不能按 4 方向连接

### 1.4 考察知识点

- **连通分量计算**：四法本质上都是求连通分量大小
- **并查集**：路径压缩、Union by size、id 编码
- **DFS / BFS**：在非传统网格上的扩展
- **计数预处理**：把连通分量判定转化为行/列计数判定
- **连通性语义识别**：识别「同行同列连通」并选择对应算法

## 二、四法总览与统一框架

### 2.1 四法一句话总结

| 解法 | 核心思路 | 数据结构 |
|---|---|---|
| **并查集** | 把同行/同列的服务器合并成连通分量，统计大小 > 1 的分量 | `father[]` + `sz[]` |
| **DFS** | 沿同行同列递归扩展连通分量，统计分量大小 | 递归 + grid 原地标记 |
| **计数预处理** | 预处理每行/每列服务器数，二次扫描判定 | `row_cnt[]` + `col_cnt[]` |
| **BFS** | 队列驱动扩展连通分量，统计大小 | `queue` + `visited[][]` |

### 2.2 统一框架

四法共享同一个**算法骨架**：

```
1. 把所有「同行同列」的服务器组织成连通分量
2. 计算每个连通分量的大小
3. 大小 > 1 的分量中的所有服务器都计入答案
```

差异只在第 1 步的「组织方式」和第 2 步的「大小计算」：

- 并查集：合并 → 查询 `sz[find(id)]`
- DFS：递归扩展 → 返回值累加
- 计数预处理：预处理行/列计数 → 直接判定
- BFS：队列扩展 → `num++` 累加

## 三、法一：并查集

### 3.1 思路

把每个服务器视作一个节点，按以下规则连边：
- **同行**：把同一行的所有服务器两两连起来（实际上只需链式连接相邻的，并查集会自动合并）
- **同列**：把同一列的所有服务器连起来

合并完成后，每个连通分量的大小就是 `sz[find(id)]`。

### 3.2 id 编码

把二维坐标 `(i, j)` 映射为一维 id：`id = i * n + j`，便于用一维数组存并查集。

### 3.3 优化技巧

- **路径压缩**：`find` 函数递归时把节点直接挂到根上，查询退化到 `O(α(n))`
- **Union by size**：合并时把小树挂到大树下，避免树退化
- **链式合并**：每行/每列只需把相邻服务器连起来（首个为基准，后续的依次与首个合并），无需两两全连

### 3.4 AC 代码

```cpp
class Solution {
public:
    vector<int> father;
    vector<int> sz;

    void build(int x) {
        father.resize(x);
        sz.resize(x, 1);
        for (int i = 0; i < x; i++) father[i] = i;
    }

    int find(int i) {
        if (i == father[i]) return i;
        return father[i] = find(father[i]);   // 路径压缩
    }

    void Union(int a, int b) {
        int fa = find(a), fb = find(b);
        if (fa != fb) {
            father[fa] = fb;
            sz[fb] += sz[fa];                  // Union by size（这里简化为合并到 fb）
        }
    }

    int countServers(vector<vector<int>>& grid) {
        int m = grid.size(), n = grid[0].size();
        build(m * n);

        // 同行连接：每行的服务器依次与首个合并
        for (int i = 0; i < m; i++) {
            int first = -1;
            for (int j = 0; j < n; j++) {
                if (grid[i][j]) {
                    int id = i * n + j;
                    if (first == -1) first = id;
                    else Union(first, id);
                }
            }
        }

        // 同列连接：每列的服务器依次与首个合并
        for (int j = 0; j < n; j++) {
            int first = -1;
            for (int i = 0; i < m; i++) {
                if (grid[i][j]) {
                    int id = i * n + j;
                    if (first == -1) first = id;
                    else Union(first, id);
                }
            }
        }

        // 统计：大小 > 1 的分量中的服务器计入答案
        int ans = 0;
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (grid[i][j]) {
                    int id = i * n + j;
                    if (sz[find(id)] > 1) ans++;
                }
            }
        }
        return ans;
    }
};
```

### 3.5 优缺点

| 优点 | 缺点 |
|---|---|
| 思路直观，套路成熟 | 实现较长，需要 `father` + `sz` 两个数组 |
| 复杂度近线性 `O(mn·α)` | 两趟扫描（行+列） |
| 易于泛化到其他连通性问题 | 需要 id 编码（多一层概念转换） |

## 四、法二：DFS

### 4.1 思路

遍历每个服务器，若未访问过，从它开始 DFS 扩展整个连通分量：

1. 标记当前格子为已访问（用 `grid[i][j] = cnt` 作为标记，cnt 从 2 开始避免与 0/1 冲突）
2. 沿**整行**扫描，把所有未访问的服务器递归 DFS
3. 沿**整列**扫描，把所有未访问的服务器递归 DFS
4. 累加分量大小，若 > 1 则全部计入答案

### 4.2 关键技巧：原地标记

用 `grid[i][j] = cnt` 替代 `visited[i][j]`：
- 节省一个 `O(mn)` 的 visited 数组
- cnt 从 2 开始，避免与原值 0（无服务器）和 1（有服务器未访问）混淆
- cnt 可以兼作「连通分量编号」，便于调试

### 4.3 AC 代码

```cpp
class Solution {
public:
    int f(vector<vector<int>>& grid, int i, int j, int cnt) {
        if (i < 0 || i >= grid.size() || j < 0 || j >= grid[0].size()
            || grid[i][j] != 1) return 0;

        int ret = 1;
        grid[i][j] = cnt;                  // 原地标记，cnt >= 2

        // 同行扫描（不包括自己，但 grid[i][k]!=1 的判断会跳过自己）
        for (int k = 0; k < grid[0].size(); k++) {
            if (grid[i][k] == 1) ret += f(grid, i, k, cnt);
        }

        // 同列扫描
        for (int k = 0; k < grid.size(); k++) {
            if (grid[k][j] == 1) ret += f(grid, k, j, cnt);
        }
        return ret;
    }

    int countServers(vector<vector<int>>& grid) {
        int m = grid.size(), n = grid[0].size();
        int ans = 0, cnt = 2;
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (grid[i][j] == 1) {       // 未访问的服务器
                    int sz = f(grid, i, j, cnt++);
                    if (sz > 1) ans += sz;
                }
            }
        }
        return ans;
    }
};
```

### 4.4 优缺点

| 优点 | 缺点 |
|---|---|
| 实现简洁，递归自然 | 递归深度可能爆栈（极端 m=n=250 时深度最多 62500） |
| 原地标记省空间 | 修改了原数组，可能不符合某些场景要求 |
| 易于理解 | 每次扩展都要 O(m+n) 扫描，整体复杂度 O(mn(m+n)) |

## 五、法三：计数预处理 + 枚举判定

### 5.1 思路（最优解）

**关键观察**：服务器 `(i, j)` 能与其他服务器通信 ⟺ 所在行有 > 1 台服务器 OR 所在列有 > 1 台服务器。

**证明**：
- 若 `row_cnt[i] > 1`：行 i 上至少还有另一台服务器，与 `(i,j)` 同行，可通信
- 若 `col_cnt[j] > 1`：列 j 上至少还有另一台服务器，与 `(i,j)` 同列，可通信
- 反之，若两者都 = 1，说明行 i 和列 j 都只有 `(i,j)` 这一台，它无法与任何人通信

**算法**：
1. 预处理：`row_cnt[i]` = 第 i 行服务器总数；`col_cnt[j]` = 第 j 列服务器总数
2. 枚举：对每个 `grid[i][j] == 1`，若 `row_cnt[i] > 1 || col_cnt[j] > 1`，则计入答案

### 5.2 为什么这个转化成立？

回到连通分量视角：
- 连通分量大小 > 1 ⟺ 至少存在另一台服务器与当前服务器连通
- 在「同行同列」连通定义下，「另一台服务器」必然满足：要么同行，要么同列
- 所以 `row_cnt[i] > 1 || col_cnt[j] > 1` 是「分量大小 > 1」的充要条件

这个等价转化把「连通分量判定」简化为「行/列计数判定」，省去了显式建图、DFS、并查集等复杂操作。

### 5.3 AC 代码

```cpp
class Solution {
public:
    int countServers(vector<vector<int>>& grid) {
        int m = grid.size(), n = grid[0].size();

        vector<int> row_cnt(m), col_cnt(n);
        // 预处理行/列计数
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (grid[i][j]) {
                    row_cnt[i]++;
                    col_cnt[j]++;
                }
            }
        }

        // 枚举判定
        int ans = 0;
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (grid[i][j] && (row_cnt[i] > 1 || col_cnt[j] > 1)) ans++;
                //              ↑ 是服务器          ↑ 行或列多于 1 台
            }
        }
        return ans;
    }
};
```

### 5.4 优缺点

| 优点 | 缺点 |
|---|---|
| **复杂度最优** O(mn) | 仅适用于「同行同列连通」语义 |
| 实现最简短，无递归无并查集 | 不能输出具体连通分量（若题目改成「输出每个分量」则失效） |
| 无栈溢出风险 | 思路需要洞察「连通 ⟺ 行列计数」的等价关系 |
| 可读性最佳 | — |

## 六、法四：BFS

### 6.1 思路

与 DFS 思路类似，只是用队列替代递归。从每个未访问的服务器出发，BFS 扩展整个连通分量，统计大小。

### 6.2 AC 代码

```cpp
class Solution {
public:
    int countServers(vector<vector<int>>& grid) {
        int m = grid.size(), n = grid[0].size();
        vector<vector<char>> visited(m, vector<char>(n, 0));
        int ans = 0;

        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (grid[i][j] == 0 || visited[i][j]) continue;

                queue<pair<int,int>> q;
                q.push({i, j});
                visited[i][j] = 1;
                int num = 0;

                while (!q.empty()) {
                    auto cur = q.front(); q.pop();
                    num++;
                    // 同行扫描入队
                    for (int t = 0; t < n; t++) {
                        if (grid[cur.first][t] && !visited[cur.first][t]) {
                            visited[cur.first][t] = 1;
                            q.push({cur.first, t});
                        }
                    }
                    // 同列扫描入队
                    for (int t = 0; t < m; t++) {
                        if (grid[t][cur.second] && !visited[t][cur.second]) {
                            visited[t][cur.second] = 1;
                            q.push({t, cur.second});
                        }
                    }
                }
                if (num > 1) ans += num;
            }
        }
        return ans;
    }
};
```

### 6.3 优缺点

| 优点 | 缺点 |
|---|---|
| 无递归无栈溢出风险 | 实现较长，需 queue 和 visited |
| 扩展顺序明确（按层） | 复杂度同 DFS，O(mn(m+n)) |
| 易于改造为分层 BFS | 比 DFS 多一个 visited 数组 |

## 七、同一例子走四法

### 7.1 选取示例

```
grid = [[1, 0, 0],
        [0, 1, 1],
        [0, 1, 0]]
```

服务器位置：`(0,0)`、`(1,1)`、`(1,2)`、`(2,1)`

**连通性分析**：
- `(1,1)`、`(1,2)` 同行 → 连通
- `(1,1)`、`(2,1)` 同列 → 连通
- 由传递性：`(1,1)`、`(1,2)`、`(2,1)` 都连通，形成大小为 3 的分量
- `(0,0)`：行 0 只有它，列 0 只有它 → **孤立**

**预期答案**：3（前三个连通，最后一个孤立不计）

### 7.2 法一：并查集执行轨迹

**初始化**：father = [0,1,2,...,8]，sz = [1,1,...,1]，id 映射 `(i,j) → i*3+j`

服务器 id：
- (0,0) → 0
- (1,1) → 4
- (1,2) → 5
- (2,1) → 7

**行扫描**：
- 第 0 行：只有 (0,0)，first = 0，无 Union
- 第 1 行：(1,1) first=4，(1,2) Union(4, 5) → father[4]=5, sz[5]=2
- 第 2 行：(2,1) first=7，无 Union

**列扫描**：
- 第 0 列：只有 (0,0)，无 Union
- 第 1 列：(1,1) first=4，(2,1) Union(4, 7) → find(4)=5, find(7)=7 → father[5]=7, sz[7]=3
- 第 2 列：只有 (1,2)，无 Union

**统计**：
- (0,0): sz[find(0)] = sz[0] = 1 → 不计
- (1,1): sz[find(4)] = sz[find(5)] = sz[7] = 3 → 计
- (1,2): sz[find(5)] = sz[7] = 3 → 计
- (2,1): sz[find(7)] = sz[7] = 3 → 计

**答案 = 3** ✅

### 7.3 法二：DFS 执行轨迹

cnt 初始 = 2

**外层扫描**：
- (0,0): grid=1，DFS(grid, 0, 0, 2)
  - 标记 grid[0][0]=2，ret=1
  - 同行扫描：grid[0][1]=0、grid[0][2]=0，跳过
  - 同列扫描：grid[1][0]=0、grid[2][0]=0，跳过
  - 返回 1
  - sz=1，不满足 >1，不计入答案
- (1,1): grid=1，DFS(grid, 1, 1, 3)
  - 标记 grid[1][1]=3，ret=1
  - 同行扫描：grid[1][0]=0、grid[1][2]=1 → DFS(1, 2, 3)
    - 标记 grid[1][2]=3，ret=1
    - 同行扫描：grid[1][0]=0、grid[1][1]=3（已访问），跳过
    - 同列扫描：grid[0][2]=0、grid[2][2]=0，跳过
    - 返回 1
  - ret = 1 + 1 = 2
  - 同列扫描：grid[0][1]=0、grid[2][1]=1 → DFS(2, 1, 3)
    - 标记 grid[2][1]=3，ret=1
    - 同行扫描：grid[2][0]=0、grid[2][2]=0，跳过
    - 同列扫描：grid[0][1]=0、grid[1][1]=3（已访问），跳过
    - 返回 1
  - ret = 2 + 1 = 3
  - 返回 3
  - sz=3 > 1，ans += 3
- (1,2): grid=3（已访问），跳过
- (2,1): grid=3（已访问），跳过

**答案 = 3** ✅

### 7.4 法三：计数预处理执行轨迹

**预处理**：
- row_cnt = [1, 2, 1]  （第 0 行 1 台、第 1 行 2 台、第 2 行 1 台）
- col_cnt = [1, 2, 1]  （第 0 列 1 台、第 1 列 2 台、第 2 列 1 台）

**枚举判定**：
- (0,0): row_cnt[0]=1, col_cnt[0]=1 → 1>1 ❌ OR 1>1 ❌ → 不计
- (1,1): row_cnt[1]=2>1 ✅ → 计
- (1,2): row_cnt[1]=2>1 ✅ → 计
- (2,1): col_cnt[1]=2>1 ✅ → 计

**答案 = 3** ✅

> 注意法三的简洁——只需两行核心判定，无需任何连通分量扩展操作。

### 7.5 法四：BFS 执行轨迹

**外层扫描**：
- (0,0): 入队，visited[0][0]=1
  - pop (0,0), num=1
  - 同行扫描：grid[0][1]=0、grid[0][2]=0，无入队
  - 同列扫描：grid[1][0]=0、grid[2][0]=0，无入队
  - num=1，不满足 >1，不计
- (1,1): 入队，visited[1][1]=1
  - pop (1,1), num=1
  - 同行：grid[1][2]=1, 未访问 → 入队，visited[1][2]=1
  - 同列：grid[2][1]=1, 未访问 → 入队，visited[2][1]=1
  - pop (1,2), num=2
  - 同行：grid[1][0]=0、grid[1][1] 已访问，无入队
  - 同列：grid[0][2]=0、grid[2][2]=0，无入队
  - pop (2,1), num=3
  - 同行：grid[2][0]=0、grid[2][2]=0，无入队
  - 同列：grid[0][1]=0、grid[1][1] 已访问，无入队
  - 队列空，num=3 > 1，ans += 3
- (1,2)、(2,1): visited 已置 1，跳过

**答案 = 3** ✅

### 7.6 四法执行对比

| 法 | 核心动作 | 总扫描次数 |
|---|---|---|
| 并查集 | 2 趟预处理（行+列）+ 1 趟统计 | 3 趟 |
| DFS | 递归扩展，原地标记 | 每个分量扩展时多次扫描行/列 |
| 计数预处理 | 1 趟预处理 + 1 趟枚举 | **2 趟** |
| BFS | 队列驱动扩展 | 类似 DFS，多个分量多次扫描 |

## 八、踩坑记录与复盘

### 坑 1：连通性语义误读（最核心）

| 维度 | 内容 |
|---|---|
| **现象** | 看到「网格」「服务器」「通信」就条件反射认为是「上下左右相邻连通」，按 LC200 岛屿数量的思路写代码 |
| **影响** | 用 4 方向循环找邻居，导致漏掉同行同列但**不相邻**的服务器，连通分量判定错误 |
| **反例** | `grid = [[1,0,1]]`：两台服务器在 (0,0) 和 (0,2)，中间隔着一个 0。按「上下左右相邻」它们不连通（答案 0），但按题意「同行」它们连通（答案 2） |
| **修复** | 找邻居时**整行整列扫描**，而非 4 方向循环 |
| **教训** | **审题时第一件事是确认「连通性定义」**——是相邻连通？同行同列连通？还是其他自定义规则？这决定整个算法骨架 |

### 坑 2：同行同列扫描范围

| 维度 | 内容 |
|---|---|
| **现象** | DFS / BFS 中找邻居时，扫描范围写成「上下左右各 1 格」 |
| **影响** | 漏掉同行同列远端的服务器，连通分量被切碎 |
| **修复** | 同行扫描 `for (k = 0; k < n; k++)` 遍历整行；同列扫描 `for (k = 0; k < m; k++)` 遍历整列 |
| **教训** | 邻居扫描范围必须与连通性定义一致，本题是 `O(m + n)` 而非 `O(1)` |

### 坑 3：DFS 用 grid[i][j]=cnt 作为标记可能误伤

| 维度 | 内容 |
|---|---|
| **现象** | 若 cnt 从 1 开始，会与原值 1（有服务器未访问）混淆 |
| **影响** | 标记后无法区分「已访问」和「未访问」，递归陷入死循环 |
| **修复** | cnt 从 **2** 开始（`int cnt = 2;`），用 0/1/≥2 三态区分「无服务器/未访问/已访问」 |
| **教训** | 原地标记技巧中，标记值必须避开原值的所有可能取值 |

### 坑 4：计数法的「或」逻辑

| 维度 | 内容 |
|---|---|
| **现象** | 计数法判定条件写成 `row_cnt[i] > 1 && col_cnt[j] > 1`（用「与」） |
| **影响** | 漏判：只要行或列任一多于 1 台就能通信，是「或」关系而非「与」 |
| **反例** | `(0,0)` 在 row_cnt[0]=1、col_cnt[0]=2 的网格中：行只有它，但列还有别的服务器，应该能通信；写错成「与」会漏判 |
| **修复** | 改为 `row_cnt[i] > 1 \|\| col_cnt[j] > 1` |
| **教训** | 「或」/「与」的逻辑选择要回到题意——「**同行或同列**」对应「**行多或列多**」，是「或」关系 |

### 通用教训小结

> 1. **审题先审连通性**：网格题不一定是 4 方向连通，可能是「车走法」「马走法」「皇后走法」等
> 2. **邻居范围跟着连通性走**：连通定义变了，邻居扫描范围就要变
> 3. **原地标记避开原值**：用 cnt ≥ 2 标记访问状态
> 4. **「或」/「与」对回题意**：逻辑连词要与题目的「或」「且」对应
> 5. **能用计数预处理就别用 DFS/并查集**：当连通性能等价转化为简单条件时，选最优解

## 九、复杂度分析与四法对比

### 9.1 时间复杂度

| 解法 | 预处理 | 主循环 | 总计 |
|---|---|---|---|
| **并查集** | O(mn)（两趟扫描）+ O(mn·α)（Union） | O(mn·α)（查询） | **O(mn·α)** ≈ O(mn) |
| **DFS** | — | 每个服务器扩展时 O(m+n)，总和 O(mn(m+n)) | **O(mn(m+n))** |
| **计数预处理** | O(mn)（一趟扫描） | O(mn)（一趟枚举） | **O(mn)** ⭐ |
| **BFS** | — | 类似 DFS | **O(mn(m+n))** |

> α 是阿克曼函数的反函数，对实际数据规模可视为常数。

### 9.2 空间复杂度

| 解法 | 主要空间 | 大小 |
|---|---|---|
| **并查集** | `father` + `sz` | O(mn) |
| **DFS** | 递归栈 | O(mn) 最坏 |
| **计数预处理** | `row_cnt` + `col_cnt` | **O(m + n)** ⭐ |
| **BFS** | `visited` + `queue` | O(mn) |

### 9.3 实现复杂度

| 解法 | 代码行数 | 实现难度 |
|---|---|---|
| **并查集** | ~50 行 | 中（需熟练掌握并查集模板） |
| **DFS** | ~25 行 | 易 |
| **计数预处理** | ~15 行 | **最易** ⭐ |
| **BFS** | ~45 行 | 中 |

### 9.4 推荐选择顺序

```
计数预处理（最优）> 并查集（通用）> DFS（简洁）> BFS（无栈溢出）
```

**选择逻辑**：
- 本题语义清晰、能转化为计数判定 → **首选计数预处理**
- 若题目扩展为「输出每个连通分量的成员」或「动态加边」 → **用并查集**
- 若题目改为求最长连通路径或带权连通 → **用 DFS/BFS**
- 若数据规模极大担心栈溢出 → **用 BFS 替代 DFS**

| **LC1905** | 统计子岛屿 | 网格连通 + 集合包含关系 |

### 10.2 拓展思考

- **连通性定义变化对解法选择的影响**：
  - 4 方向相邻 → DFS/BFS/并查集，邻居 O(1)
  - 8 方向相邻 → 邻居 O(1) 但循环改 8 次
  - 同行同列（车走法）→ 计数预处理最优，邻居 O(m+n)
  - 任意同行同列同对角线（皇后走法）→ 需额外维护对角线计数
- **网格题与图题的转化**：网格本质是图，连通性定义即图的边定义
- **动态加边场景**：若题目支持「在线新增服务器」，计数预处理失效（无法增量更新），并查集仍是首选
- **多查询场景**：若多次查询「某服务器能否与某服务器通信」，并查集 + 路径压缩最优

### 10.3 通用模板：计数预处理（适用于「同行同列连通」类网格题）

```cpp
// 计数预处理模板
int solve(vector<vector<int>>& grid) {
    int m = grid.size(), n = grid[0].size();
    vector<int> row_cnt(m, 0), col_cnt(n, 0);

    // 预处理
    for (int i = 0; i < m; i++)
        for (int j = 0; j < n; j++)
            if (grid[i][j]) {
                row_cnt[i]++;
                col_cnt[j]++;
            }

    // 枚举判定
    int ans = 0;
    for (int i = 0; i < m; i++)
        for (int j = 0; j < n; j++)
            if (grid[i][j] && (row_cnt[i] > 1 || col_cnt[j] > 1))
                ans++;
    return ans;
}
```

### 10.4 通用模板：并查集（适用于更广义的连通性问题）

```cpp
class DSU {
    vector<int> parent, rank_;
public:
    DSU(int n) : parent(n), rank_(n, 0) {
        iota(parent.begin(), parent.end(), 0);
    }
    int find(int x) {
        return parent[x] == x ? x : parent[x] = find(parent[x]);
    }
    bool unite(int x, int y) {
        int rx = find(x), ry = find(y);
        if (rx == ry) return false;
        if (rank_[rx] < rank_[ry]) swap(rx, ry);
        parent[ry] = rx;
        if (rank_[rx] == rank_[ry]) rank_[rx]++;
        return true;
    }
};
```

## 十一、复盘小结

| 维度 | 内容 |
|---|---|
| 核心算法 | 连通分量计数（四法对比） |
| 难度 | 中等 |
| 关键洞察 | 「同行同列连通」可等价转化为「行/列计数 > 1」 |
| 最优解 | 计数预处理，O(mn) 时间 + O(m+n) 空间 |
| 主要踩坑 | 1) 连通性语义误读（最常见）<br>2) 邻居扫描范围错（4 方向 vs 整行整列）<br>3) DFS 原地标记值冲突<br>4) 计数法「或」逻辑误写「与」 |
| 核心教训 | **审题先审连通性定义；能用计数预处理就别用复杂结构** |

### 下次遇到网格连通题的判断流程

1. **连通性定义是什么**？
   - 4 方向相邻 → DFS/BFS/并查集
   - 同行同列连通（车走法）→ **优先尝试计数预处理**
   - 8 方向相邻 → DFS/BFS，邻居循环 8 次
   - 自定义规则 → 按规则设计邻居扫描
2. **能否等价转化为简单条件**？
   - 能 → 用计数预处理（最优）
   - 不能 → 用并查集 / DFS / BFS
3. **是否需要输出分量成员**？
   - 需要 → DFS / BFS（标记值即分量编号）
   - 不需要 → 任选
4. **是否支持动态加边**？
   - 支持 → 并查集（在线算法）
   - 不支持 → 任选
5. **数据规模是否担心栈溢出**？
   - 担心 → 用 BFS 替代 DFS

记住这个判断流程，遇到网格连通题先审连通性定义，再选算法，避免「条件反射式」套模板。
