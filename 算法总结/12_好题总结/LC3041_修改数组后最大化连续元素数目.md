# LC3041 修改数组后最大化连续元素数目

> **好题总结条目**｜标签：值域 DP / 排序 / 状态压缩 / 连续序列
> **难度**：中等偏难 ｜ **核心结论**：不需要以下标为状态，只需记录连续序列最终以哪个数值结尾

---

## 一、一句话解法与模型重写

每个原数 `x` 最终只有三种处理方式：

```text
不选；选它并保持为 x；选它并增加 1，变成 x + 1
```

排序后维护：

```text
best[v] = 已处理元素能够形成的、以最终数值 v 结尾的最长连续序列长度
```

当前数 `x` 可以：

```text
作为 x，接在 best[x - 1] 后面；
作为 x + 1，接在 best[x] 后面。
```

每次转移为 `O(1)`，总复杂度由排序决定，为期望 `O(n log n)`。

原数组下标顺序并不重要，因为选出的元素最终会按值重新排序。先把 `nums` 排序，问题就变成：

> 对每个原数 `x`，选择 `x`、`x + 1` 或跳过，使选出的最终值构成一段连续且互不相同的整数区间，并最大化长度。

### 为什么能压缩成一个值域状态

若最终连续序列为：

```text
L, L + 1, L + 2, ..., R
```

每次扩展只依赖前一个值 `v - 1`：

```text
以 v 结尾的最长连续序列
= 以 v - 1 结尾的最长连续序列 + 1
```

两个方案只要最终结尾值相同，后续能够接上的值也完全相同。因此同一结尾值下，较短方案永远没有优势，只保留最长长度即可。

## 二、题目与示例

给定只包含正整数的数组 `nums`。先选择任意数量元素，将它们各增加至多 `1`；再从最终数组中选择若干元素，使升序排列后连续，返回最多能选出的数量。

连续要求相邻值恰好相差 `1`，并且不能重复：

```text
[3, 4, 5]       连续
[3, 4, 6]       不连续
[1, 1, 2, 3]    不连续
```

### 示例一

```text
输入：nums = [2, 1, 5, 1, 1]
输出：3
```

可以构造：

```text
1 → 1
1 → 2
2 → 3
```

最终选出 `[1, 2, 3]`，其余元素不选。

### 示例二

```text
输入：nums = [1, 4, 5, 2]
输出：4
```

四个数都能选：

```text
1 → 2
2 → 3
4 → 4
5 → 5
```

最终得到 `[2, 3, 4, 5]`。这说明原数在原数组中的相邻关系并不重要，关键是它们能否映射到同一个连续值域。

## 三、法一：下标 DP + 两个状态，超时

### 状态定义

```cpp
f(i, op)
```

表示原始元素 `nums[i]` 被使用，最终取 `nums[i] + op` 时，以该最终值结尾的连续序列最大长度。

```text
op = 0：保持 nums[i]
op = 1：将 nums[i] 增加 1
```

### 状态转移

当前最终值的前一个值必须是 `nums[i] + op - 1`。因此枚举 `j < i` 和 `k ∈ {0, 1}`：

```text
若 nums[j] + k == nums[i] + op - 1：
f(i, op) = max(f(i, op), 1 + f(j, k))
```

整理后的代码：

```cpp
class Solution {
public:
    int dfs(const vector<int>& nums, int i, int op,
            vector<array<int, 2>>& memo) {
        if (memo[i][op] != -1) {
            return memo[i][op];
        }

        int answer = 1;
        int current = nums[i] + op;

        for (int j = 0; j < i; ++j) {
            for (int k = 0; k <= 1; ++k) {
                if (nums[j] + k == current - 1) {
                    answer = max(answer, 1 + dfs(nums, j, k, memo));
                }
            }
        }
        return memo[i][op] = answer;
    }

    int maxSelectedElements(vector<int>& nums) {
        sort(nums.begin(), nums.end());
        int n = static_cast<int>(nums.size());
        vector<array<int, 2>> memo(n, array<int, 2>{-1, -1});

        int answer = 0;
        for (int i = 0; i < n; ++i) {
            answer = max(answer, dfs(nums, i, 0, memo));
            answer = max(answer, dfs(nums, i, 1, memo));
        }
        return answer;
    }
};
```

这个 DP 是正确的：任何以此元素结尾的连续序列，要么从当前元素单独开始，要么从前一个值 `current - 1` 转移而来；循环穷尽了所有可能前驱。

### 为什么超时

记忆化后的状态数只有：

```text
2n
```

但每个状态仍要扫描所有此前元素：

```text
O(n) 个状态 × O(n) 次前驱枚举 = O(n²)
```

记忆化只能避免重复计算状态，不能减少单个状态的转移成本。`n = 10^5` 时无法通过。

### 优化切入点

前驱只可能是最终值 `current - 1`。我们并不关心它来自哪个下标，也不关心它原来是否增加了 `1`。

因此把：

```text
(下标 i, 是否增加 op)
```

替换成：

```text
最终结尾值 v
```

即可把“扫描所有前驱”改为“直接查询一个值”。

## 四、法二：值域 DP + 记忆化，仍然超时

### 完整二维状态

```text
dp[i][j]
= 只考虑排序后的前 i 个元素，以最终数值 j 结尾的连续序列最大长度
```

设当前元素为 `x = nums[i - 1]`。选择当前元素时，新的结尾值只能是 `x` 或 `x + 1`：

```text
dp[i][j] = dp[i - 1][j]                         // 不选当前元素

如果 x == j 或 x + 1 == j：
dp[i][j] = max(dp[i][j], dp[i - 1][j - 1] + 1)
```

### 原笔记递推式的修正

原笔记写的是：

```text
dp[i][j] = dp[i - 1][j - 1] + 1
```

这是“当前元素确实被用来变成 j”这一分支的简写，不是完整递推式。完整版本必须：

1. 保留“不选择当前元素”的状态；
2. 先检查当前元素能否变成 `j`；
3. 再与前一个值 `j - 1` 的方案连接。

原代码中的 `dfs` 实际包含了“不选择”分支，因此思路正确；问题在于状态空间。

### 原代码整理版

```cpp
class Solution {
public:
    const vector<int>* nums;
    unordered_map<long long, int> memo;

    int dfs(int i, int j) {
        if (i == 0) {
            return 0;
        }

        long long key = 1LL * i * 1'000'005 + j;
        if (memo.count(key)) {
            return memo[key];
        }

        int answer = dfs(i - 1, j);  // 不选当前元素

        int x = (*nums)[i - 1];
        if (x == j || x + 1 == j) {  // 选当前元素并变成 j
            answer = max(answer, dfs(i - 1, j - 1) + 1);
        }
        return memo[key] = answer;
    }

    int maxSelectedElements(vector<int>& arr) {
        sort(arr.begin(), arr.end());
        nums = &arr;

        int answer = 0;
        for (int j = 1; j <= 1'000'005; ++j) {
            answer = max(answer, dfs(static_cast<int>(arr.size()), j));
        }
        return answer;
    }
};
```

### 为什么仍会超时

设计层面的状态表是：

```text
O(n × V)
```

其中 `V` 为值域大小。即使只访问实际可达状态，最坏也可能达到 `O(n²)`，再加上外层枚举大量 `j`、哈希表开销和递归栈开销，仍然无法承受。

### 二维 DP 的正确改进方向

处理原数 `x` 时，只需要更新两个最终结尾：

```text
x
x + 1
```

没有必要对值域中的每个 `j` 单独 DFS。这个观察直接导出最终的一维值域 DP。

## 五、法三：值域压缩 DP

### 状态定义

```text
best[v] = 当前已处理元素能够形成的、以 v 结尾的最长连续序列长度
```

不存在的结局值默认长度为 `0`。

对于当前原数 `x`：

| 选择 | 当前最终值 | 前驱结尾 | 候选长度 |
|---|---:|---:|---:|
| 不增加 | `x` | `x - 1` | `best[x - 1] + 1` |
| 增加 1 | `x + 1` | `x` | `best[x] + 1` |
| 不选择 | — | — | 保持旧状态 |

因此：

```text
best[x]     = max(best[x],     best[x - 1] + 1)
best[x + 1] = max(best[x + 1], best[x]     + 1)
```

但两条语句的顺序非常关键。

### 正确更新顺序

```cpp
best[x + 1] = max(best[x + 1], best[x] + 1);
best[x]     = max(best[x],     best[x - 1] + 1);
```

先处理“把当前元素增加为 `x + 1`”，再处理“保持为 `x`”。

如果反过来，当前元素会先作为结尾 `x` 使用，再作为 `x + 1` 的前驱使用一次，相当于同一个元素被用了两次。

最小反例：

```text
nums = [1]
```

错误顺序：

```text
best[1] = best[0] + 1 = 1
best[2] = best[1] + 1 = 2
```

一个元素被错误算成长度为 `2`。

正确顺序：

```text
best[2] = 旧 best[1] + 1 = 1
best[1] = best[0] + 1 = 1
```

### AC 代码

```cpp
class Solution {
public:
    int maxSelectedElements(vector<int>& nums) {
        sort(nums.begin(), nums.end());

        unordered_map<int, int> best;
        best.reserve(2 * nums.size() + 2);

        int answer = 0;
        for (int x : nums) {
            // 先让当前 x 变成 x + 1，接到旧的 best[x] 后面
            best[x + 1] = max(best[x + 1], best[x] + 1);

            // 再让当前 x 保持为 x，接到 best[x - 1] 后面
            best[x] = max(best[x], best[x - 1] + 1);

            answer = max(answer, max(best[x], best[x + 1]));
        }
        return answer;
    }
};
```

`best[x - 1]` 不存在时通过 `operator[]` 得到 `0`，正好表示没有前驱；当前元素因此可以单独构成长度为 `1` 的序列。

### 为什么必须排序

DP 的方向是：

```text
x - 1 → x → x + 1
```

必须按值从小到大处理，才能保证前驱值已经算好。

最小反例：

```text
nums = [2, 1]
```

按原序处理时，先得到 `best[2] = 1`；再处理 `1` 后无法把已经处理过的 `2` 接在 `1` 后面，错误得到 `1`。

排序后先处理 `1`，才能得到 `best[2] = 2`。

这不是普通的“排序后去重”，而是在按值域依赖关系进行拓扑顺序上的 DP。

### 手算示例一

```text
nums = [2, 1, 5, 1, 1]
排序后：[1, 1, 1, 2, 5]
```

| 当前 x | 更新 `best[x + 1]` | 更新 `best[x]` | 当前答案 |
|---:|---:|---:|---:|
| 1 | `best[2] = 1` | `best[1] = 1` | 1 |
| 1 | `best[2] = 2` | `best[1] = 1` | 2 |
| 1 | `best[2] = 2` | `best[1] = 1` | 2 |
| 2 | `best[3] = 3` | `best[2] = 2` | 3 |
| 5 | `best[6] = 1` | `best[5] = 1` | 3 |

最终答案为 `3`。

### 手算示例二

```text
nums = [1, 4, 5, 2]
排序后：[1, 2, 4, 5]
```

| 当前 x | `best[x + 1]` | `best[x]` | 当前答案 |
|---:|---:|---:|---:|
| 1 | `best[2] = 1` | `best[1] = 1` | 1 |
| 2 | `best[3] = 2` | `best[2] = 2` | 2 |
| 4 | `best[5] = 1` | `best[4] = 3` | 3 |
| 5 | `best[6] = 2` | `best[5] = 4` | 4 |

最后的 `best[5]` 对应：

```text
1 → 2
2 → 3
4 → 4
5 → 5
```

## 六、正确性证明

### 状态不变量

处理完排序数组前 `i` 个元素后：

> `best[v]` 表示只使用这 `i` 个元素时，能够形成的、以 `v` 结尾的最长连续序列长度。

### 转移穷尽所有情况

对于当前原数 `x`：

1. 不选择它，旧状态保持不变；
2. 选择它并保持为 `x`，前一项只能是 `x - 1`；
3. 选择它并增加为 `x + 1`，前一项只能是 `x`。

由于每个元素最多增加 `1`，不会出现第四种使用方式。两条 `max` 转移覆盖全部选择，旧状态通过 `max` 保留“不选择”的情况。

### 保留最长方案为什么足够

所有以同一个值 `v` 结尾的方案，后续都只能接 `v + 1`。更长的序列在任何后续扩展中都不会比短序列差，因此同结尾值只保留最大长度。

### 为什么不会重复使用当前元素

先计算 `best[x + 1]`，使它只能使用本轮的旧 `best[x]`；再更新 `best[x]`。这样当前元素分别对应“变成 x”和“变成 x + 1”的两个互斥候选，不会在同一条方案中被使用两次。

### 答案完整性

任意最优连续序列都有一个最终结尾值 `R`，处理完所有元素后其长度一定记录在 `best[R]` 中。取所有 `best` 的最大值就是全局最优答案。

## 七、复杂度与实现选择

| 部分 | 复杂度 |
|---|---|
| 排序 | `O(n log n)` |
| 哈希表转移 | 期望 `O(1)` / 元素 |
| 总时间 | 期望 `O(n log n)` |
| 空间 | `O(n)` |

每个元素最多引入 `x`、`x + 1` 两个键，因此哈希表大小最多约为 `2n`。

若确认 `nums[i] <= 10^6`，也可用数组：

```cpp
class Solution {
public:
    int maxSelectedElements(vector<int>& nums) {
        sort(nums.begin(), nums.end());
        int maximum = *max_element(nums.begin(), nums.end());
        vector<int> best(maximum + 2, 0);

        int answer = 0;
        for (int x : nums) {
            best[x + 1] = max(best[x + 1], best[x] + 1);
            best[x] = max(best[x], best[x - 1] + 1);
            answer = max(answer, max(best[x], best[x + 1]));
        }
        return answer;
    }
};
```

数组版常数稳定，但额外空间为 `O(max(nums))`；哈希表版只与 `n` 有关。

## 八、易错点与三种方法对比

### 坑 1：更新顺序写反

先更新 `best[x]` 会让当前元素被重复使用。最小反例 `[1]`：错误答案为 `2`，正确答案为 `1`。

### 坑 2：二维递推式漏掉“不选当前元素”

如果直接写 `dp[i][j] = dp[i-1][j-1] + 1`，会漏掉跳过当前元素的情况，也会错误使用无法变成 `j` 的元素。

### 坑 3：认为法二只有 `2n` 个状态

法二的状态由 `(i, j)` 两个维度共同决定，不只是每个下标的两种增加选择。对值域中的多个 `j` 分别递归，会访问大量二维状态。

### 坑 4：忘记排序

DP 依赖从小值到大值的计算方向，原序 `[2, 1]` 就能暴露问题。

### 坑 5：排序后直接去重

重复元素可以分别变成不同的连续值：

```text
[1, 1] → [1, 2]
```

因此不能去重；要逐个处理重复元素。

### 坑 6：与 LIS 混淆

| 模型 | 要求 |
|---|---|
| LIS | 严格递增即可，不要求相邻值相差 1 |
| 本题 | 最终值必须连续，下一项只能是上一项加 1 |
| 普通子数组 | 原下标连续 |
| 本题 | 原下标无关，最终排序后连续 |

| 方法 | 状态 | 单状态转移 | 主要瓶颈 | 结果 |
|---|---|---|---|---|
| 下标 DP | `(i, op)` | 扫描所有 `j < i` | `O(n²)` | 超时 |
| 值域记忆化 | `(i, j)` | `O(1)` | 状态空间过大 | 超时 |
| 值域压缩 DP | `best[v]` | 两次哈希查询 | `O(n log n)` | AC |

## 九、面试追问与自测

### 为什么相同结尾值只保留最长长度

后续只知道当前结尾 `v`，并只能继续接 `v + 1`。同一结尾下，长度更大的方案支配所有更短方案。

### 如何从法一直接推出法三

1. 当前最终值只需要前一项 `current - 1`；
2. 前一项来自哪个下标无关；
3. 状态改为 `best[value]`；
4. 当前元素只产生 `x`、`x + 1` 两个新结尾；
5. 每次只做两次哈希查询。

### 如果要恢复具体方案

`best[v]` 只保存长度。若需要输出选中的数和修改方式，还要记录每个状态的前驱值或来源下标；本题只求最大数量，因此一个整数足够。

### 闭卷自测

| 输入 | 输出 | 一种构造 |

| `[1]` | 1 | `[1]` |
| `[1, 1]` | 2 | `[1, 2]` |
| `[1, 1, 1]` | 2 | `[1, 2]` |
| `[1, 1, 2]` | 3 | `[1, 2, 3]` |

## 十、最终复盘

| 维度 | 内容 |
|---|---|
| 核心模型 | 每个 `x` 选择 `x` 或 `x + 1`，形成数轴上的连续区间 |
| 最优状态 | `best[v]`：以 `v` 结尾的最大连续长度 |
| 核心转移 | `x + 1` 接 `best[x]`，`x` 接 `best[x - 1]` |
| 关键顺序 | 先更新 `best[x + 1]`，再更新 `best[x]` |
| 决定性优化 | 用“前一个最终值”查询，替代扫描此前所有下标 |
| 时间复杂度 | 期望 `O(n log n)` |
| 空间复杂度 | `O(n)` |
| 主要陷阱 | 更新顺序、漏排序、二维递推无条件转移 |

### 一句话口诀

> **排序后盯终点：保持 `x` 接 `x-1`，加一 `x+1` 接 `x`；先算加一，再算保持，防止一个元素用两次。**
