# LC3331 修改后子树的大小

> **好题总结条目**｜标签：树 / DFS 回溯 / 路径状态 / 最近同字符祖先 / 递归 lambda
> **难度**：中等 ｜ **核心结论**：先在原树上为每个节点确定新父亲，再在新树上后序汇总子树大小

---

## 一、一句话解法与题目模型

分两遍处理：

1. 在**原树**上 DFS，维护根到当前节点路径上每种字符最近出现的节点，求出每个节点的新父亲；
2. 用全部新父亲关系建出**最终树**，再做一次后序 DFS，按 `size[u] = 1 + sum(size[v])` 计算答案。

时间复杂度 `O(n)`，空间复杂度 `O(n)`。

题目中的“同时执行”非常重要：

> 节点 `x` 找最近同字符祖先时，依据的是修改前的原树祖先链，而不是前面节点已经改边后的新树。

因此两个阶段不能混在一起：先把所有 `newParent` 求完，再建最终树。

## 二、法一为什么错误

法一试图按节点编号建立每种字符的列表：

```cpp
unordered_map<char, vector<int>> cnt;
for (int i = 0; i < n; ++i) {
    cnt[s[i]].push_back(i);
}
```

然后取当前节点之前最近的同字符编号作为新父亲。这个思路混淆了“编号顺序”和“树的祖先关系”。

### 反例：之前的同字符节点不是祖先

```text
parent = [-1, 0, 0, 1]
s      = "aaba"
```

树形为：

```text
0(a)
├─ 1(b) ─ 3(a)
└─ 2(a)
```

处理节点 `3`：

- 原树祖先链是 `1(b) → 0(a)`；
- 最近同字符祖先是节点 `0`；
- 正确新父亲是 `0`。

但全局字符列表里，节点 `3` 前面最近的 `'a'` 是节点 `2`。节点 `2` 只是兄弟分支，根本不是祖先，法一却会把 `3` 接到 `2`。

### 法一的其他问题

1. **祖先关系不是编号关系**：`i < j` 不能说明 `i` 是 `j` 的祖先。
2. **没有找到也不一定安全**：当前字符列表至少包含当前节点，`cnt.contains(cur)` 不代表此前存在真正祖先。
3. **根节点处理有越界风险**：根节点的 `parent[0] == -1`，却仍可能访问 `copy_tree[parent[i]]`。
4. **删除位置写错**：代码在 `copy_tree[parent[i]]` 中删除，却用 `AdjList[i]` 搜索元素；应检查当前父亲的孩子列表。
5. **`erase(find(...))` 未检查 `end()`**：找不到元素时属于未定义行为。
6. **把孩子数当子树大小**：`copy_tree[i].size()` 只是节点 `i` 的直接孩子数量，不是整棵子树节点数。

正确做法必须沿祖先链查询，并在最终树上递归汇总，不能依赖全局字符列表或直接孩子数。

## 三、法二：原树 DFS + 路径回溯

### 3.1 状态定义

```text
last[c] = 当前 DFS 路径上，字符 c 最近出现的节点编号
```

初始时路径为空，所以：

```cpp
vector<int> last(26, -1);
```

进入节点 `u` 时，`last[s[u]]` 正好是：

> 原树上距离 `u` 最近的、字符相同的祖先。

因为 DFS 栈中保存的正是从根到 `u` 的路径。

### 3.2 求新父亲

设：

```cpp
int c = s[u] - 'a';
int pre = last[c];
```

这里必须先读取 `pre`，再更新 `last[c] = u`。

规则：

```text
pre != -1：newParent[u] = pre
pre == -1：newParent[u] = parent[u]
根节点：  newParent[0] = -1
```

### 3.3 为什么递归后要恢复路径状态

```cpp
int old = last[c];
last[c] = u;

for (int v : adj[u]) {
    dfs(v);
}

last[c] = old;
```

`last[c] = u` 只对 `u` 的子树有效。退出 `u` 后进入兄弟分支时，`u` 已不在当前路径上，所以必须恢复为进入 `u` 之前的最近节点。

如果不恢复，兄弟分支会错误地把本分支的节点当成祖先。

### 3.4 C++17 可提交代码

```cpp
class Solution {
public:
    vector<int> findSubtreeSizes(vector<int>& parent, string s) {
        int n = static_cast<int>(parent.size());
        vector<vector<int>> originalTree(n);
        for (int i = 1; i < n; ++i) {
            originalTree[parent[i]].push_back(i);
        }

        vector<int> newParent(n, -1);
        vector<int> last(26, -1);

        function<void(int)> findNewParent = [&](int u) {
            int c = s[u] - 'a';
            int previous = last[c];

            if (u == 0) {
                newParent[u] = -1;
            } else if (previous != -1) {
                newParent[u] = previous;
            } else {
                newParent[u] = parent[u];
            }

            int old = last[c];
            last[c] = u;

            for (int v : originalTree[u]) {
                findNewParent(v);
            }

            last[c] = old;
        };

        findNewParent(0);

        vector<vector<int>> finalTree(n);
        for (int i = 1; i < n; ++i) {
            finalTree[newParent[i]].push_back(i);
        }

        vector<int> answer(n, 0);
        function<int(int)> calculateSize = [&](int u) -> int {
            answer[u] = 1;
            for (int v : finalTree[u]) {
                answer[u] += calculateSize(v);
            }
            return answer[u];
        };

        calculateSize(0);
        return answer;
    }
};
```

### 3.5 “同时执行”到底体现在哪

第一阶段递归始终使用：

```text
originalTree
parent[]
```

它从未沿着新边继续搜索，因此节点 `x` 找的是修改前原树上的最近同字符祖先。

反例：

```text
原树：0(a) → 1(b) → 2(a) → 3(c) → 4(a)
新边：2 → 0，4 → 2
```

节点 `3(c)` 在原树上没有同字符祖先，所以新父亲仍是原父亲 `2`。虽然节点 `2` 后来改接到了 `0`，这个变化不会反向影响“同时执行”时对节点 `3` 的判断。

## 四、手算示例

### 4.1 输入

```text
parent = [-1, 0, 1, 2, 3]
s      = "abaca"
```

原树是一条链：

```text
0(a) → 1(b) → 2(a) → 3(c) → 4(a)
```

### 4.2 第一阶段

| 节点 | 字符 | 原树最近同字符祖先 | 新父亲 |
|---:|:---:|---:|---:|
| 0 | a | 不存在 | -1 |
| 1 | b | 不存在 | 0 |
| 2 | a | 0 | 0 |
| 3 | c | 不存在 | 2 |
| 4 | a | 2 | 2 |

最终父亲：

```text
newParent = [-1, 0, 0, 2, 2]
```

最终树：

```text
0
├─ 1
└─ 2
   ├─ 3
   └─ 4
```

### 4.3 第二阶段子树大小

后序汇总：

```text
size[1] = 1
size[3] = 1
size[4] = 1
size[2] = 1 + 1 + 1 = 3
size[0] = 1 + 1 + 3 = 5
```

答案：

```text
[5, 1, 3, 1, 1]
```

### 4.4 题面“同时执行”与顺序修改的区别

再看一个能暴露顺序修改错误的反例：

```text
原树：0(b) → 1(a) → 2(b) → 3(a) → 4(b)
```

按原树同时判断：

- 节点 `3(a)` 的最近同字符祖先是 `1(a)`；
- 节点 `4(b)` 的最近同字符祖先是 `2(b)`。

如果先处理 `3`，把 `3` 改接到 `1`，再让 `4` 沿“已经修改后的树”向上找：

```text
4(b) → 3(a) → 1(a) → 0(b)
```

节点 `4` 会错误地把祖先 `0` 当作最近同字符祖先，因为原树中的 `2(b)` 已经被新边跳过了。

因此必须先在原树上为所有节点求新父亲，再统一建最终树。这是“同时执行”在代码结构上的直接体现。

## 五、正确性证明

### 5.1 第一阶段：新父亲正确

对 DFS 深度归纳。

进入节点 `u` 时，假设 `last[c]` 保存的是当前根到 `u` 的原树路径上、字符 `c` 最近出现的节点。

- 若 `last[s[u]] != -1`，它就是距离 `u` 最近的同字符祖先；
- 若等于 `-1`，说明原树中不存在同字符祖先，保持原父亲；
- 根节点没有祖先，所以新父亲为 `-1`。

随后把 `last[s[u]]` 更新为 `u`，再进入子树；子树中的路径确实增加 `u`。退出子树后恢复旧值，兄弟分支不会看到 `u`。

因此归纳成立，所有节点的 `newParent` 都与题目要求一致。

### 5.2 第二阶段：子树大小正确

新父亲始终指向原树中的严格祖先，所以不会形成环；每个非根节点仍恰有一个父亲，因此最终结构仍是一棵以 `0` 为根的树。

对任意节点 `u`，它的子树恰好由：

```text
u 自己 + 新树中每个孩子 v 的整棵子树
```

构成，且这些部分互不重叠。因此后序递推：

```text
size[u] = 1 + sum(size[v])
```

正确。所有孩子先于父亲计算，最终得到全部答案。

## 六、复杂度与边界

| 阶段 | 时间 | 空间 |
|---|---|---|
| 建立原树、求新父亲 | `O(n)` | `O(n)` |
| 建立最终树、计算子树大小 | `O(n)` | `O(n)` |
| 总计 | `O(n)` | `O(n)` |

每条边在两棵树中最多被处理常数次。字符表只有 26 项，可视为 `O(1)`。

边界情况：

```text
n = 1
parent = [-1]
s = "a"
answer = [1]
```

以及：

```text
所有节点同字符
```

此时每个非根节点都会接到最近的同字符祖先；链式树会保持原样，星形树也会保持原样。

## 七、易错点

### 坑 1：用节点编号判断祖先

编号小不代表是祖先。必须沿 `parent` 链或原树 DFS 判断祖先关系。

### 坑 2：把 finalTree 的边数当子树大小

`finalTree[u].size()` 是直接孩子数，子树还要包含所有后代。

### 坑 3：DFS 后不恢复 `last`

`last` 是“当前路径”状态，不是全局“最近处理节点”。只更新不回溯，兄弟分支会串线。

### 坑 4：先进入子节点再更新当前节点

当前节点也是子树中节点的祖先，所以必须先完成 `newParent[u]`，再设置 `last[s[u]] = u`，最后递归孩子。

### 坑 5：边修改边用新树判断后续节点

题目要求同时执行，所有“最近同字符祖先”都应在原树上判断。Phase 1 始终使用 `originalTree`。

### 坑 6：删除边时搜索错列表

在 `tree[parent[u]]` 中删除 `u`，不能到 `tree[u]` 中寻找 `u`；删除前应确认元素存在。

### 坑 7：根节点使用 `parent[0]`

根节点父亲是 `-1`，任何邻接表访问都必须先单独处理根。

## 八、递归 lambda 语法专题

### 8.1 `std::function` 版本为什么能递归

题目代码使用：

```cpp
function<void(int)> dfs = [&](int u) {
    for (int v : adj[u]) {
        dfs(v);
    }
};
```

可行性来自两点：

1. 变量 `dfs` 的类型在初始化器执行前已经确定为 `function<void(int)>`；
2. `[&]` 通过引用捕获 `dfs`，lambda 内部可以在稍后调用它。

真正调用发生在 `dfs` 初始化完成之后，因此不会在对象尚未就绪时递归。

`std::function` 使用类型擦除，调用通常比直接调用函数对象多一层间接性，但对 `O(n)` 的树遍历通常可以接受。需要显式包含：

```cpp
#include <functional>
```

### 8.2 为什么不能直接写 `auto dfs = [&](int u) { dfs(v); };`

```cpp
auto dfs = [&](int u) {
    dfs(u - 1);
};
```

变量 `dfs` 的类型正在由初始化器推导，初始化器内部又依赖 `dfs` 的完整类型，标准 C++ 会出现“在 `auto` 推导完成前使用变量”的错误。

核心区别：

```text
function<...> dfs：类型事先已知
auto dfs：类型要靠 lambda 初始化器推导
```

### 8.3 C++23：显式对象参数 `this auto&& self`

题目第二段代码使用：

```cpp
auto calculateSize = [&](this auto&& self, int u) -> int {
    int result = 1;
    for (int v : finalTree[u]) {
        result += self(v);
    }
    return result;
};
```

`this auto&& self` 是 C++23 的**显式对象参数**，也常称为 deducing this。

细节：

- `self` 代表 lambda 闭包对象自身；
- 它不是调用方传入的普通参数，调用仍写成 `calculateSize(0)`；
- lambda 内可以通过 `self(v)` 递归；
- `auto&&` 保留闭包的值类别，避免无谓复制；
- 不需要 `std::function` 的类型擦除。

等价地可以把题目里的递归汇总写成：

```cpp
auto calculateSize = [&](this auto&& self, int u) -> int {
    int result = 1;
    for (int v : finalTree[u]) {
        result += self(v);
    }
    return result;
};

int rootSize = calculateSize(0);
```

注意：这是 C++23 特性，不能用于严格按 C++17 或 C++20 编译的程序。是否可提交取决于平台的编译选项；需要最大兼容性时使用 `std::function`。

### 8.4 C++14 可移植的“自动递归”写法

如果不希望使用 `std::function`，又需要兼容 C++14，可以把闭包自己作为额外参数传入：

```cpp
auto calculateSize = [&](int u, auto&& self) -> int {
    int result = 1;
    for (int v : finalTree[u]) {
        result += self(v, self);
    }
    return result;
};

int rootSize = calculateSize(0, calculateSize);
```

这里 `self` 是普通参数，所以不依赖 C++23 的显式对象参数。

### 8.5 三种递归写法对比

| 写法 | 最低标准 | 类型擦除 | 递归调用 |
|---|---|:---:|---|
| `function<void(int)> dfs` | C++11 | 有 | `dfs(v)` |
| `lambda(u, auto&& self)` | C++14 | 无 | `self(v, self)` |
| `lambda(this auto&& self, u)` | C++23 | 无 | `self(v)` |

初学与调试时，`std::function` 最直观；追求零类型擦除且接受额外参数时，用通用 lambda；确认平台支持 C++23 时，显式对象参数最简洁。

### 8.6 捕获列表与 `mutable`

题目中的两个 lambda 都写了 `[&]`，根据实际使用情况以引用捕获局部变量：

```text
newParent、last、answer、originalTree、finalTree
```

这些引用在同步 DFS 期间都有效，函数返回后 lambda 即被销毁，不存在悬空问题。

lambda 的 `operator()` 默认是 `const`，但写 `last[c] = u` 仍然合法：闭包中的捕获成员是引用，`const` 限制的是引用成员本身，不禁止修改它指向的 `vector`。

如果按值捕获一个对象并修改该对象本身，通常需要 `mutable`：

```cpp
auto f = [count = 0]() mutable {
    ++count;
};
```

本题不应把可能很大的 `vector` 按值捕获。

### 8.7 返回类型和递归深度

递归 lambda 如果参与类型推导，写明确的尾置返回类型更稳妥：

```cpp
function<int(int)> dfs = [&](int u) -> int { ... };
```

`void` 的遍历可以写 `function<void(int)>`，返回 `int` 的汇总写成 `function<int(int)>`，两者不要混淆。

另外，`O(n)` 状态复杂度不等于递归安全。对于一条长度为 `10^5` 的链，递归深度也可能是 `10^5`，有栈溢出风险。链式树或稳定性优先时，可把两次 DFS 改为显式栈；lambda 递归的主要价值是结构清晰和适合面试表达。

## 十、最终复盘

| 维度 | 内容 |
|---|---|
| 核心结构 | 原树一遍求新父亲，新树一遍求子树大小 |
| 路径状态 | `last[26]` 保存当前根到节点路径上的最近同字符节点 |
| 关键细节 | 先读旧 `last`，更新当前节点，递归，最后回溯 |
| 关键语义 | 所有祖先判断都基于修改前的原树 |
| 时间复杂度 | `O(n)` |
| 空间复杂度 | `O(n)` |
| 递归 lambda | C++17 用 `std::function`，C++23 可用显式对象参数 |
| 核心口诀 | **原树找祖先，回溯清路径；新树算大小，后序加孩子。** |
